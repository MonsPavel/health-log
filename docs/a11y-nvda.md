# NVDA-чеклист и аудит контраста (TASK-109 §5, NFR-6)

NFR-6: «скринридер — полноправная персона»; NVDA — целевой скринридер Windows.
Документ — два инструмента в одном: (1) чек-лист ручного NVDA-прогона семи ключевых
сценариев с ожидаемым озвучиванием и критериями PASS; (2) контраст-аудит пар токенов
обеих тем (`tools/scripts/contrast-audit.mjs`, гейт «0 пар ниже порога» §20 AC1).

## Статус ревизии (честно)

- **Контраст-аудит выполнен полностью** (автоматика): скрипт + 30 юнит-тестов,
  отчёт — раздел 9; найденная дефектная группа (disabled инверсных кнопок) исправлена,
  повторный прогон — 0 гейт-пар ниже порога.
- **NVDA-прогон ВЫПОЛНЕН** (2026-10-03): фактический запуск NVDA portable 2026.2
  (официальный дистрибутив NV Access, подписан — Windows Smart App Control пропустил;
  развёрнута portable-копия во временный каталог, БЕЗ системной установки; синтезатор
  `silence` — звук в динамики не выводился) с `--debug-logging`: каждый вызов
  `speech.speak` зафиксирован в логе — это и есть «звук-история» сценария. Приложение
  управлялось через Playwright (launch-хелпер e2e, фикстуры 3 измерения + fake-LLM),
  озвучиваемые события — реальные focus/live-region события Chromium (IA2).
  Результаты по сценариям — в разделах 2–8; полные срезы лога — `%TEMP%/nvda-run/slices/`.
- **Ограничение прогона (честно)**: «слушателем» был speech-лог NVDA, а не человек —
  соответствие ОЖИДАЕМОМУ озвучиванию (полнота, роли, состояния, отсутствие спама
  дельтами) подтверждено построчно; субъективная «осмысленность на слух» и финальная
  приёмка — за релизным прогоном (CONTRIBUTING.md §10, чек-бокс раздела 12).
  Один пробел: тост «Сохранено» (S1) в лог не попал — в момент тоста окно приложения
  теряло системный фокус (машина использовалась параллельно); факт региона
  role="status" aria-live="polite" проверен программно (unit + e2e).
- Скринридер-автоматизация как регресс-щит не вводится (решение спеки §5:
  недостоверна); NVDA-прогон повторяется вручную на каждый мажорный релиз.

## 1. Общие соглашения прогона (NVDA)

| Механика | Что проверяем |
|---|---|
| Режимы NVDA | browse mode (стрелки — линейный обход) и forms mode (NVDA+Space, контролы); фокус-режим включается автоматически на интерактиве |
| Навигация по структуре | H — заголовки по уровням (h1 экрана один, карточки/дни — h2); K — ссылки (5 разделов); B — кнопки; F — поля форм; T — таблицы; E — регионы редактирования |
| Регионы | D — ориентиры (navigation «Разделы», main, form, log, status/alert/note) |
| Озвучивание | Имя роли + имя (подпись) + значение + состояние (выбрано/нажато/недоступна/busy); цифры значений СДА/ДДА/ЧСС — целиком |
| Критерии PASS | осмысленно (нет «кнопка кнопка», нет неозначенных иконок), порядок логичен (DOM-порядок, TASK-108), live-сообщения читаются один раз и по делу |

## 2. Сценарий «Ввод измерения» (UC-01)

Старт → «Динамика» → «Журнал» → «Добавить» → форма → сохранение. Клавиатурная
механика — `docs/a11y-keyboard.md` §2 (e2e `a11y-keyboard.spec.ts` зелёный).

Шаги и ожидаемое озвучивание:

1. «Добавить» → h1 «Новое измерение»; фокус авто в поле СДА (§5 формы).
2. Tab по полям: каждое озвучивает подпись + значение — «СДА, редактируемое поле,
   пусто» / со значением «124». Подписи связаны `label[for]` (sys/dia/pulse/note —
   probe: все 4 цели во INPUT/TEXTAREA; автопереключение после 3-й цифры — юнит-тесты
   MeasurementForm).
3. DigitPad: кнопки с полными aria-label «Ввести 1…0», «Удалить символ», «Очистить»
   (DigitPad.tsx §16; aria-label задаются t()-ключами).
4. Критическое значение 125/82 → ConfirmFlagsDialog: заголовок + описание
   (aria-labelledby/describedby), первый фокус «Отмена» — озвучивается роль диалога.
5. «Сохранить» (disabled на невалидной форме) — «Сохранить, недоступна» при обходе;
   кнопка НЕ таб-стоп (TAB-факт TASK-108). Disabled-стиль контрастен ≥3:1 — раздел 8.
6. Успех: тост «Сохранено» — регион role="status" aria-live="polite" (probe:
   toast-region role=status live=polite), читается без фокуса, один раз.

PASS: каждое поле озвучивает подпись и значение; нет безымянных кнопок; тост читается.

**Звук-история (фрагменты speech-лога NVDA 2026.2, прогон 2026-10-03):**

←/→), «Рука» (select), «Только с заметками» (checkbox), поиск (type=search, ×  с
aria-label «Очистить поиск» — HistoryFilters §16).

1. Строка списка: озвучивается группировкой дня (h2 «Сегодня») + текст строки;
   единственный таб-стоп строки — «⋮» с aria-label «Действия с записью» (probe:

2. Enter → меню (Radix DropdownMenu): «Изменить»/«Удалить» озвучиваются ролями

3. Правка → форма «Изменение записи» (тот же контракт подписей, что §2); выход —

4. Удаление → AlertDialog: фокус-ловушка, «Отмена» первой; подтверждение — тост

## 4. Сценарий «Динамика + таблица»

Старт → «Динамика» (с данными). Период — radio-сегмент fieldset/legend; «Давление/
Пульс», «График/Таблица» — кнопки с aria-pressed.

1. График — figure role="img" с ПОЛНЫМ aria-label-резюме; probe-факт (30 дней,
   фикстура 3 записи): «График динамики давления, период „30 дней“: систолическое в
   среднем 124,7 (диапазон 118–132), диастолическое в среднем 81 (диапазон 76–85),
   измерений: 3». NVDA читает фигуру целиком; внутрь SVG не заходит (aria-hidden,
   TASK-108: accessibilityLayer=false — фокусируемых узлов внутри нет).
2. Точечные тултипы — мышь; фокус в них не уходит: тултип рендерится внутри
   aria-hidden-обёртки, не таб-стоп; клик «Изменить» ведёт в форму (фокус уходит из
   aria-hidden немедленно). Клавиатурная альтернатива — режим «Таблица».
3. «Таблица» (?as=table): таблица с caption-периодом, th scope="col", сортировка —
   кнопки в заголовках, th несёт aria-sort ascending/descending (TrendTable.test.ts
   §16 059: caption «…30 дней», aria-sort ассерты).
4. Карточки сводки: заголовки h2, «Добавить измерение» — CTA на форму.

PASS: график озвучивается одним осмысленным резюме; таблица навигируется T-ом,
сортировка озвучивает «сортировано по…».

**Звук-история (NVDA 2026.2):** browse-обход стрелками дошёл до фигуры и прочитал
резюме ЦЕЛИКОМ: «графика, График динамики давления, период „30 дней“: систолическое
в среднем 125,3 (диапазон 118–132), … измерений: 3» — сводка из stats (TASK-059)
озвучивается одним осмысленным фрагментом. Переключатель вида: «Представление, группа,
Таблица, кнопка переключатель, не нажата» — состояние нажатия озвучивается.
**Итог: PASS.**

## 5. Сценарий «ИИ: разбор + чат + модель» (ключевой кейс — стрим)

Старт → «ИИ». Вкладки «Разбор/Чат/Модель» — кнопки с aria-pressed; баннер онбординга
— role=status с кнопкой «Настроить позже».

1. «Разбор»: превью контекста — role=note; «Объяснить период» → во время стрима
   регион НЕ озвучивает дельты (aria-live="off" + aria-busy, SummaryView.tsx —
   TASK-109), по завершении регион снова polite и текст-узел перемонтирован —
   **политый текст читается по завершению, целиком, один раз** («не буква-за-буквой»,
   §13); стоп/кэш/отказ озвучиваются тем же путём (вставка узла в polite-регион).
   e2e-факт: ai-summary.spec.ts — off+busy в стриме, polite на финале.
2. «Чат»: поле с подписью (label for=chat-input); Enter — отправка, Shift+Enter —
   перенос; лента role="log" aria-live="polite": user-бабл читается сразу («Вы: …»,
   sr-only-подпись ролей ChatBubble §16), стрим-бабл несёт aria-busy — дельты молчат
   (e2e-факт: ai-chat.spec.ts — aria-busy=true в стриме, финальная пара без него);
   финал — «Помощник: …» целиком + дисклеймер в хвосте.
3. BUSY: вторая отправка при занятом движке — тост «Дождитесь завершения текущей
   генерации» (role=status, ai-chat.spec.ts §20).
4. «Модель»: карточки (h3 name), кнопки «Скачать/Выбрать…» с полными aria-label
   («Скачать модель „…“ (… МБ)»), aria-busy/disabled на время операций; прогресс —
   прогрессбар с aria-label (ModelCard §16).

PASS: стрим НЕ читается по токенам; ответ читается по завершению; BUSY-тост читается.

**Звук-история (NVDA 2026.2, ключевой кейс §13):** на ВЕСЬ стрим ответа — ровно два
объявления ленты: сразу после отправки — «Вы:Как менялось давление? Помощник:  »
(оптимистичная пара; стрим-бабл озвучен ПУСТЫМ — aria-busy глушит дельты), и по
завершении — полный ответ одним объявлением: «…Помощник: Данных пока мало (3 измерения
за 3 дня) — я не буду делать выводов. …». Коротких фрагментов (<40 символов) с текстом
ответа: **0**; объявлений на дельты токенов: **0** (анализ slices/s4-chat-stream.log).
«Читается буква-за-буквой» — НЕ воспроизводится после правки TASK-109 (aria-busy).
**Итог: PASS (AC3 §20 подтверждён по логу; контроль на слух — релизный прогон).**

## 9. Контраст-аудит (§5/§13): методика и результат

Скрипт `tools/scripts/contrast-audit.mjs` (запуск `node tools/scripts/contrast-audit.mjs`,
exit-код — гейт): парсинг tokens.css (единственный источник значений) → расчёт ВСЕХ
реальных пар fg/bg по WCAG 2.x → отчёт. Особенности:

- порог пары — по rem-масштабу (100/112.5/125%): крупный текст (≥24px или ≥18.66px при
  bold=700; semibold 600 в строгую сторону НЕ считается крупным) — 3:1, иначе 4.5;
  гейт пары — по самому строгому порогу среди масштабов;
- disabled — всегда 3:1 (house-rule §13 строже exemption WCAG 1.4.3); реальный цвет
  disabled считается честной альфа-композицией слоёв (opacity-модификаторы Tailwind);
- не-текстовые границы (--hl-border, WCAG 1.4.11) — информационно, вне гейта (§13
  задаёт пороги для текста/disabled; решение по границам — раздел 10.2).

**Найдено и исправлено**: disabled инверсных кнопок (bg-accent/text-bg при
`disabled:opacity-50`) давал 1.7:1 (light) / 2.1:1 (dark) — ниже 3:1 в обеих темах;
disabled текст-кнопки accent — 2.3:1 (light). Исправление — `disabled:opacity-80`
на 19 сайтах (12 файлов: ChatScreen ×2, InsightScreen, ModelCard ×3, MeasurementForm,
RecoveryScreen, BackupDialog, RestoreFlow ×3, WipeFlow ×2, LockOverlay, SecuritySettings,
DiagSection, UpdatesSection ×2). Вторичные кнопки оставлены на 50% (3.36–4.88:1 ≥ 3:1).

(эталонные пары публикаций WCAG: 21:1, 3.95:1, 4.54:1, 8.59:1). Токены-ЗНАЧЕНИЯ правок
не потребовали — все 6 токенов обеих тем проходят AA в своих ролях.

## 10. Находки вне гейта (честно; отложенные — с триггером)

### 10.1 Не-токенные цвета не следуют data-theme (отложено)

В рендерере остались не-токенные палитры Tailwind с `dark:` вариантами; `dark:` в
Tailwind v4 = prefers-color-scheme **ОС**, а тема приложения = data-theme (явный выбор).
При явной тёмной теме на светлой ОС: `text-neutral-600` рендерится oklch(0.439 0 none)
(≈ #4f4f4f) на фоне #0f172a ≈ **2.2:1** — нарушение §13. probe-факт: computed color
`oklch(0.439 0 none)` (AverageCard h2, app-dark + OS-light — среда прогона).
axe-матрица это НЕ ловит: axe-core не парсит oklch computed colors (поэтому 42/42
зелёные при сломанном контрасте — причина, почему нужен был скриптовый аудит).

Затронуты (миграция на токены — отдельная задача, прецедент TASK-108 со статусами):
ChatBubble/SummaryView (refusal-поверхности, `bg-neutral-100 dark:bg-neutral-800`),
ChatScreen/InsightScreen/AiPage/ModelCard (`text-neutral-600 dark:text-neutral-300`,
`bg-neutral-50 dark:bg-neutral-900`, red/amber-блоки ошибок/предупреждений),
dashboard-карточки (`text-neutral-500/600 dark:text-neutral-300/400`, скелетоны),
RowMenu/DropdownMenu (data-highlighted:bg-neutral-…), DayGroup (divide-neutral-…),
пагинация (`border-neutral-300`), hover-поверхности (`hover:bg-neutral-100 …`).
Триггер возврата: первая задача фазы P7-полировки после 109; до неё — на светлой ОС
в тёмной теме вторичный текст читается плохо (P3-класс затронут частично).

### 10.2 Границы полей ввода ниже 3:1 (WCAG 1.4.11, отложено)

`--hl-border` на фоне: 1.42:1 (light) / 1.72:1 (dark) — ниже 3:1 не-текстового
минимума для границ, требуемых для опознания компонента (поля ввода bg-bg на bg-bg
опознаются только границей). Карточки/разделители — декоративные, exempt. Решение —
отдельный токен границы интерактивных полей (например slate-500/slate-400) + миграция
161 использования `border-border` по ролям — вне объёма §5 («правка токенов, не
удовлетворяющих §13-порогам»: §13 порогов для не-текста не задаёт). Триггер: задача
токен-миграции 10.1 (тот же заход).

### 10.3 Принято как есть (с обоснованием)

- **hover-состояния** (`hover:opacity-90` на инверсных кнопках: 2.8:1 в light во время
  наведения) — транзиентное состояние мыши; WCAG/axe оценивают устойчивые рендеры
  (прецедент: axe не проверяет hover); клавиатурный фокус hover не включает.
- **placeholder'ы полей** — дефолтная полупрозрачность Tailwind; каждое поле имеет
  видимую связанную подпись (placeholder не носитель информации, §17).
- **переключатель «Простой режим»** (thumb bg-accent на треке bg-accent/30) —
  не-текстовое состояние дублируется role="switch" + aria-checked.
