# Реестр отложенных a11y-нарушений (TASK-108 §5/§13)

Статус: **нарушений нет** — отложенных moderate/minor нарушений axe на текущий прогон не
зарегистрировано. Файл существует как процессный механизм (§13): любой moderate/minor,
появившийся в прогоне `apps/desktop/tests/e2e/a11y-full.spec.ts`, обязан попасть сюда с
обоснованием «почему отложено» и триггером возврата — иначе прогон падает (в спеке список
`DEFERRED_RULE_IDS` — зеркало этого файла).

## Правила (§13)

- **critical/serious** — блокер, чинится в задаче, в реестр не попадает никогда.
- **moderate/minor** — допустимы только из этого реестра; каждая строка: rule-id axe,
  маршрут/условие, обоснование отложения, триггер возврата.
- Чистый прогон — норма: файл остаётся с пометкой «нарушений нет» (раздел ниже).

## Исправлено в TASK-108 (след, не отложенное)

Найдено в первом прогоне матрицы, исправлено в этой же задаче (по классам из §5):

- `serious/aria-hidden-focus` (графики TrendChart/PulseChart): клавиатурный слой recharts 3
  (`accessibilityLayer` по умолчанию) даёт фокусируемый wrapper внутри `aria-hidden`;
  плюс Chromium делает скролл-контейнеры фокусируемыми. Исправление: `accessibilityLayer={false}`,
  `aria-hidden` перенесён на внутреннюю обёртку SVG, скролл-контейнер — вне `aria-hidden`.
- `serious/color-contrast` (тёмная тема): `text-white` на кнопках `bg-accent` (в тёмной теме
  акцент светлый: 1.6:1) → `text-bg` (~12:1; прецедент LockOverlay); статусные тексты
  `text-green-700`/`text-red-600` не следовали теме → токены `--hl-status-ok`/`--hl-status-fail`
  с AA-контрастом в обеих темах (контраст-тест tokens.test.ts расширен).
- `moderate/page-has-heading-one` (/dashboard, /journal, форма ввода): заголовки экранов — h1,
  карточки/дни — h2 (иерархия без пропусков), у формы появился h1 «Новое измерение».

## Как обновлять реестр

1. Прогон `pnpm --filter @hl/desktop test:e2e -- a11y-full` упал со списком
   «moderate/minor вне реестра».
2. Для каждого rule-id: решить «чинить сейчас» (предпочтительно) или «отложить».
3. Отложенные — строкой в таблицу + rule-id в `DEFERRED_RULE_IDS` спеки (оба места).
