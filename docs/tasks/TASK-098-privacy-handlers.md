## 2. Цель

Каналы экрана «Приватность»: `privacy/journal {limit} → {entries: NetworkEventDto[], ops: OperationInfo[]}` (последние записи + перечень всех возможных операций с их назначением/согласием) и `privacy/consents {patch?} → Consents` (чтение/переключение).

## 3. Бизнес-контекст

US-33: экран «Приватность» — витрина BG-2. Данные готовы (network_event, prefs.netConsents, EgressPolicy) — канал агрегирует в одну форму для UI; список операций должен генерироваться из политики (не дублироваться руками).

## 4. Технический контекст

- **Архитектура:** FR-7.1; генерация описаний из EgressPolicy — D11-следствие.
- **Обоснование:** OperationInfo = из ALLOWED-карты политики: `{op, consentKey, descriptionKey}` — новая сетевая операция появляется в UI автоматически при добавлении в политику (нельзя забыть).

## 5. Объём

- **Включено:** contracts `privacy/*`: `NetworkEventDto {kind, endpoint, status, bytes?, atUtc}`, `OperationInfo {op, consentKey, descriptionKey, enabled: bool}`, `Consents {updatesCheck, modelsDownload}`; каналы: `privacy/journal {limit=50} → {entries, ops}` (entries desc по at_utc), `privacy/consents {patch?: Partial<Consents>} → Consents` (валидация известных ключей — только из политики); события: invalidate по `net:activity` (лента живая); тесты: journal-агрегация, ops генерируются из политики (тест-инвариант: ops.length == ALLOWED keys), consent-patch строгий (неизвестный ключ → VALIDATION).
- **Не включено:** удаление записей журнала вручную (ротация — TASK-103), экспорт журнала.
- **Будущая работа:** фильтры журнала по op (пост-MVP).
