## 2. Цель

Усиление vault: при включении пароля ключ БД оборачивается дополнительно — `KEK = Argon2id(passphrase, salt)`, `wrappedKey = AES-256-GCM(dbKey, KEK)`; смена/снятие пароля = переобёртка (БД не перешифруется); неверный пароль обнаруживается по auth-tag GCM без открытия БД.

## 3. Бизнес-контекст

FR-7.5: защита от «подошёл и посмотрел». NFR-2: забытый пароль = невосстановимость — предупреждение обязательна. DPAPI (TASK-023) привязан к Windows-профлю; пароль — независимый фактор для случаев «общий компьютер».

## 4. Технический контекст

- **Архитектура:** арх. 08 §2 (двойная обёртка), крипто-инвентарь §7 (только стандартные примитивы).
- **Модуль:** `security/adapters`.
- **Обоснование:** Argon2id (память 64 МБ, iterations подобраны под ~0,5 с на целевом железе — калибровочная функция в задаче, параметры сохраняются в файле vault) — стойкость к офлайн-перебору. AES-256-GCM auth-tag = верификация пароля без открытия БД. node:crypto — без новых зависимостей; argon2 — единственный нативный Addition (фикс. решения).

## 5. Объём

- **Включено:** расширение `vault.key` формата v2: `{v: 2, mode: 'safeStorage'|'passphrase', saltB64?, argonParams?, wrappedKeyB64, verifier?}`; миграция формата v1→v2 при старте (old safeStorage-wrap переупаковывается, data сохраняется — тест); API vault: `setPassphrase(pass)` / `changePassphrase(old, new)` / `removePassphrase(old)` / `unlock(pass)`; калибровка Argon2id: `calibrate()` — подбор memory/iterations под бюджет 500 мс (замер на первой установке, параметры кэшируются); verifier = первые 16 байт SHA-256(wrappedKey) — быстрая проверка «пароль даже не тот» без Argon2 (нет: verifier должен требовать KEK — иначе офлайн-перебор минуя Argon2! РЕШЕНИЕ: verifier = AES-GCM tag самой обёртки — проверка только после полного derive; быстрого обхода нет); тесты: верный/неверный пароль, смена, снятие, потеря salt, калибровка-детерминизм.
- **Не включено:** UI (094/095), rate-limit (094), восстановление пароля (невозможно по определению — предупреждение 095).
- **Будущая работа:** аппаратные ключи/WebAuthn — вне MVP.

## 6. Файлы

- **Изменить:** `key-vault.ts` порт (методы §5), redact-список (salt, wrappedKey, passphrase).

## 7. Модель предметной области

Порт-расширение (аддитивно к TASK-023): методы выше + `getMode(): 'none'|'passphrase'`. Инвариант: смена пароля не меняет dbKey (БД не перешифровывается — тест: данные читаются после смены).

## 8. База данных

Файл vault.key v2; сама БД не меняется. Порядок при включении пароля: БД открыта текущим ключом → переобёртка файла → дальнейшие старты требуют unlock.

## 9. Бэкенд

Старт с mode=passphrase: контейнер НЕ открывает БД до unlock (состояние locked — TASK-094 управляет); unlock → ensureKey → открытие БД (ленивое открытие — изменение контейнера 027: БД открывается по требованию, если mode=passphrase; при mode=none — сразу. Включить патч контейнера в объём).

## 12. Управление состоянием

## 13. Бизнес-логика

Кейсы: setPassphrase при открытой БД — мгновенно (переобёртка); changePassphrase с неверным old → отказ; removePassphrase → возврат в mode safeStorage; потеря/порча salt/wrapped → VAULT/KEY_CORRUPT (данные невосстановимы — та же семантика потери ключа); downgrade формата v2→v1 запрещён.

## 14. Безопасность

Пароль: min 8 (UI-политика 095, крипто-агностик); Argon2id параметры в файле (не коде) — эволюционируют; пароль/KEK/salt — redact; обнуление строк пароля по возможности (JS-ограничение, документируется).

## 15. Производительность

Argon2id ~500 мс калибровано: unlock-UX приемлем; калибровка однократно при setPassphrase.

## 18. Телеметрия

## 19. Стратегия тестирования

Интеграционные (tmp vault): set→unlock-ок; неверный → WRONG_PASSPHRASE; change (old неверный/верный); remove → данные читаются; формат v1→v2 миграция (фикстура v1-файла); калибровка: параметры в бюджете (замер <1 с); redact-тест пароля.
