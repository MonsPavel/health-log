## 2. Цель

Копия данных (create-backup → `VACUUM INTO`) шифруется ключом источника, а ключ
генерируется на профиль (`randomBytes(32)`, safe-storage-key-vault.ts) и в
манифест копии не попадает → восстановление на ЧУЖОМ профиле/машине падает
`BACKUP/FAILED` (откат-страховка отрабатывает, данные не теряются). Нести ключ
БД в контейнере копии, обёрнутый passphrase (Argon2id+AES-256-GCM, формат
v-N+1 — конвенции TASK-093), и импортировать в локальный vault при restore.

## 3. Объём

- **Включено:** create-backup: passphrase-запрос + обёртка ключа источника в
  манифест копии (v-N+1); restore: расшифровка обёртки → импорт ключа в
  локальный vault; e2e-сценарий «чужой профиль» (расширение UC-08
  data-care.spec.ts: restore в другой tmp-userData — сквозной тест, который
  отсюда и появился); совместимость: старые копии (v-N без обёртки) — прежний
  путь с честной ошибкой «копия с этой машины» вместо BACKUP/FAILED.
- **Не включено:** перенос vault-сессий/автоблока; облачные копии.

## 4. Критерии приёмки

- [ ] Restore копии на пустом ДРУГОМ профиле: все записи/заметки/настройки, счётчик совпадает (AC-2.4 ✅, e2e).
- [ ] Старые копии (без обёртки) на чужом профиле — понятная ошибка, данные целы.
- [ ] Повтор AC-2.4 + DoD-1 на релизной сборке после фикса (обязательство mvp-dod.md §D).
- [ ] Полный gate зелёный.

## 5. Проверка

e2e (двухпрофильный сценарий) + юниты формата v-N+1. Откат: revert.
