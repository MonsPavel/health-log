## 2. Цель

Шаблон PDF-отчёта врача (@react-pdf/renderer): титул (период, дата формирования, версия приложения), таблица измерений, средние утро/вечер/период, график, регулярность; шрифты с кириллицей; опциональный ИИ-раздел — только по явному включению, маркированный «сгенерировано ИИ, не является медицинским заключением»; рендер в worker pool.

## 3. Бизнес-контекст

US-26/UC-05/П5: отчёт — то, ради чего ведётся дневник: врач должен получить данные, а не «умные выводы» (решение SRS: ИИ-раздел по умолчанию выключен и маркирован). Структура отчёта повторяет ожидания П5 из персоны: дата-время, утро/вечер, средние, регулярность.

## 4. Технический контекст

- **Архитектура:** состав отчёта — арх. 02 §3.4 (политика Reporting), FR-6.3; рендер в пуле — TASK-066.
- **Модуль:** `reporting/adapters/pdf`.
- **Обоснование:** @react-pdf/renderer — декларативные React-компоненты (стек-совместимость), детерминированный вывод. Кириллица: подключение встроенного TTF (Roboto-Regular/Bold с OFL-лицензией — фикс. решения) — обязательный ранний чек: если кириллица не рендерится в первой половине задачи → эскалация выбора (pdfkit-путь — alt-план ADR-комментарий). График в PDF: сериализация SVG точек в PDF-примитивы ограничена → РЕШЕНИЕ: рисовать упрощённый линейный график примитивами react-pdf (Line/SVG-элементы react-pdf поддерживает) из тех же точек TASK-056 — без PNG-растра (чёткая печать), только sys-линия + опорные 140/90 (упрощение задокументировано; полный график — на экране).

## 5. Объём

- **Включено:** task пула `pdf.render`: payload `{spec: ReportSpec}` → bytes (Uint8Array); `ReportSpec {period: {fromUtcMs, toUtcMs}, includeAiSection: false, aiText?: {contentMd, generatedAt, modelId}}`; компоненты: `ReportDocument` (A4, поля 15мм): заголовок «Дневник артериального давления», подзаголовок периода (Intl), «Сформировано: {date}, Health Log v{appVersion}»; таблица измерений (Дата, Время, СДА, ДДА, ЧСС, Рука, Примечание — перенос строк, зебра-строки для читаемости, разрывы страниц с повтором заголовка); блок «Средние» (утро/вечер/за период + count + дни с измерениями); блок «Регулярность» (N дней из M, streak); график-линия sys (упрощённый, §4); ИИ-раздел (если spec.includeAiSection и aiText): рамка + заголовок-маркировка + текст (моноширинный? обычный с переносами) + повтор дисклеймера; golden-снапшот: фикстурный период → PDF bytes → хеш-стабильность (одинаковые входы = одинаковый хеш — детерминизм react-pdf проверить!) + текст-выжимка через pdf-parse-подобную проверку? РЕШЕНИЕ: текст-проверка — рендер в текст не тривиален; проверяем хеш-стабильность + ручную визуальную ревизию + количество страниц разумное; юнит-тесты компонентов (проп-логика: разбиение таблицы, форматирование).
- **Не включено:** логотип/бренд (пост-MVP), выбор сортировки (всегда asc — решение), печать напрямую.
- **Будущая работа:** подпись пациента/врача, выбор шаблона (пост-MVP).

## 15. Производительность

## 16. Доступность

PDF — печатный артефакт: читаемость (размер шрифта ≥9pt таблица), контраст печати (чёрный/белый, зебра светлая); теги доступности PDF — вне MVP.

## 17. Интернационализация

Тексты отчёта — RU-каталог reporting (ключи, не литералы — единообразие); даты Intl ru; при EN-локализации пост-MVP — шаблон параметризован.

## 18. Телеметрия

Лог: `pdf.render pages=… durationMs=… records=…` (в воркере — логирование через parent-port в общий логгер? Решение: задача возвращает метрики в результате — логирует main).

## 19. Стратегия тестирования

Юниты: форматтеры (даты/прочерки), разбивка таблицы на страницы (логика строк на страницу), ИИ-раздел не рендерится при флаге false даже с текстом. Golden-хеш: фикстура 40 записей → PDF → sha256; повторный рендер — тот же хеш (детерминизм; если react-pdf вкладывает дату генерации — отключить метаданные, тест это выявит). Ручная визуальная ревизия на печать.

## 20. Критерии приёмки

- [ ] Кириллица в PDF рендерится корректно (ручная ревизия, скриншот в PR) — ранний чек §4.
- [ ] Golden-хеш: два рендера фикстуры → идентичные bytes (детерминизм).
- [ ] includeAiSection=false + переданный aiText → раздела нет в bytes (проверка размера/страниц — тест).
- [ ] Таблица: разрывы страниц повторяют заголовок (ручная + юнит-логика).
- [ ] Ограничение 2000 строк: 3000 записей → приписка «последние 2000 из 3000» (юнит + ручная).
- [ ] Рендер 5k ≤30 с локально (замер в логе).
