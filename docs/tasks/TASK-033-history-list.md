## 2. Цель

Экран «Журнал»: список записей, сгруппированных по дням (заголовки дат по настенному времени Instant), обратная хронология, компактная строка записи (время, 125/82, пульс, рука), обучающее пустое состояние; live-обновление по событиям.

## 3. Бизнес-контекст

«Посмотреть, что я вводил» — основная навигация П1 (FR-2.1); пустое состояние — первый экран новичка (FR-9.2): подсказка «Измерьте давление и нажмите Добавить» превращает пустоту в следующий шаг.

## 4. Технический контекст

- **Архитектура:** read-модель — арх. 03 §2; состояние — 06 §3 (TanStack Query + события).
- **Пакет:** renderer feature `measurement`.
- **Обоснование:** группировка по дням в renderer (не в SQL): данные маленькие (200/страница), а настенное время — домен Instant/Intl; SQL-группировка усложнила бы контракт.

## 5. Объём

- **Включено:** `HistoryScreen`: useQuery `['measurements', profileId, {limit:200}]` → хендлер list; группировка: сортировка уже desc — группировка по wallDate(takenAt); заголовок дня: «Сегодня» / «Вчера» / дата (Intl); строка записи: время (HH:MM), `125/82`, `70 уд/мин`, иконка руки (título-атрибут), флаг-место (бейджи — TASK-042); кнопка «Добавить» → форма (TASK-031); подписка `useHlEvent('measurement:changed')` → invalidateQueries; пустое состояние: иллюстрация-иконка + 2 строки текста + CTA; подпись «Показано N из M» + кнопка «Показать ещё» (offset-пагинация через useQueryComponent — fetchNextPageTanStack); скелетон при первой загрузке; тесты.
- **Не включено:** фильтры (TASK-044), правка/удаление из списка (TASK-038), бейджи (TASK-042).
- **Будущая работа:** виртуализация списка (при >1000 строк на экране — не ожидается при пагинации).

## 10. Фронтенд

Состояния: loading (скелетон 3 строк), empty (EmptyHistory), error (тост + retry-кнопка — queryClient refetch), данные. «Показать ещё»: keepPreviousData, append. Live: invalidate по событию — список обновляется после ввода в другой вкладке формы.

## 11. API

Потребляет `measurements/list` (TASK-030).

## 12. Управление состоянием

Ключ: `['measurements', profileId, page-offset-файлы]`; инвалидация: событие `measurement:changed` (global) и onSuccess мутаций; staleTime Infinity — данные всегда «свежие после инвалидации» (арх. 06 §3).

## 13. Бизнес-логика

Группировка: wallDate из (utcMs, tzOffsetMin) — записи одного дня с разными tz (перелёт) попадут по своему настенному дню (EC-06 — правильное поведение). «Сегодня/Вчера» — сравнение с настенной датой устройства сейчас (Intl-датой), пограничный случай полуночи — по настенной дате записи.

## 14. Безопасность

## 15. Производительность

## 16. Доступность

Список: `<ul>` по дням → `<li>`; строка — читаемая последовательность «Время, 125 на 82, пульс 70, левая рука»; флаг-место — aria-hidden пока пусто; кнопка «Показать ещё» — стандартная; заголовки дней — `<h3>`.

## 17. Интернационализация

## 19. Стратегия тестирования

Тесты: группировка фикстуры (2 дня, 3 записи — заголовки «Сегодня/Вчера»), пустое состояние (текст+CTA, клик CTA → форма), скелетон при pending, «Показать ещё» вызывает fetch с offset=200, invalidate по mock-событию refetch'ает, a11y-семантика (роли).

## 20. Критерии приёмки

- [ ] Записи группируются по настенным дням; «Сегодня/Вчера» корректны.
- [ ] Пустой список → обучающее состояние с CTA, открывающим форму (AC-3.6-дух).
- [ ] После добавления записи из формы список обновляется без перезагрузки (событие).
- [ ] «Показать ещё» подгружает следующую страницу; подпись «N из M» точна.
- [ ] Скелетон при первой загрузке; ошибка — retry-кнопка работает.
- [ ] axe: критических нарушений нет.
