## 2. Цель

IPC-канал `stats/period {period} → {stats, scale}` поверх read models 052/053; контракты DTO статистики; поведение при малых данных: значения с пометкой «мало данных», категория не показывается как «вердикт» (EC-09).

## 3. Бизнес-контекст

Статистика — данные для трёх потребителей (дашборд, отчёт, ИИ-контекст); канал фиксирует форму один раз. Честность при малых данных (EC-09): три измерения не должны превращаться в «категорию АГ» — показываем цифры с пометкой.

## 4. Технический контекст

- **Архитектура:** read path — арх. 05 §5; период — те же семантики, что TASK-044 (пресеты + custom).
- **Модуль:** `analytics/application` + `main/ipc` + contracts.
- **Обоснование:** scale в ответе (а не отдельный канал для потребителей статистики) — классификация без второй загрузки; период — вход, всё остальное — производное.

## 5. Объём

- **Включено:** contracts: `StatsRequest {profileId, period: '7d'|'30d'|'90d'|'all'|{fromUtcMs, toUtcMs}}`, `PeriodStatisticsDto` (плоская форма структуры 052, включая classification и notes), `StatsResponse {stats, scale: {code, version, sourceLabel}}`; канал `stats/period` регистрация (GetPeriodStatistics use case — тонкая сборка: период→границы → read model → scale из ScaleService); хендлер-замер длительности (лог); тесты интеграционные (tmp-контейнер с фикстурами TASK-052).
- **Не включено:** UI (057/061), кэширование на main (render-side кэша достаточно, TD-8).
- **Будущая работа:** параметры «включить распределение категорий по точкам» (если потребуется отчёту).

## 6. Файлы

- **Создать:** `packages/contracts/src/stats/*`; `modules/analytics/application/get-period-statistics.ts`; `ipc/handlers/stats.ts`; интеграционный тест.
- **Изменить:** `contracts/channels.ts`, `container.ts`.

## 7. Модель предметной области

DTO = структура 052 + classification (053); правило flat-маппинга: undefined-части отсутствуют в JSON (не null-простыня); округления — уже в read model.

## 8. База данных

## 9. Бэкенд

Порядок: zod → границы периода (пресет: now−N*24ч; custom — как TASK-046 семантика включительно) → read model → classification (требует scale — из ScaleService) → Response. Отказы: STORAGE/*.

## 10. Фронтенд

N/A (057/061). Потребители обязаны: при insufficientData.tooFewMeasurements показывать пометку «мало данных» рядом со значениями и НЕ показывать категорию как вывод (классификация в данных уже undefined — UI не может ошибиться).

## 11. API

`stats/period` (§5). Пустой период → полная структура с нулями/undefined (не ошибка).

## 12. Управление состоянием

Ключ рендерера: `['stats', profileId, period]`; инвалидация по `measurement:changed` (событие). staleTime Infinity.

## 13. Бизнес-логика

Пограничные: custom-период из одного дня; период «всё» на пустой БД; period=30d ровно на границе записи (включительно — тест). Кэш-дружелюбность: одинаковые запросы — одинаковые ответы (детерминизм read model).

## 14. Безопасность

profileId в запросе (схема).

## 15. Производительность
