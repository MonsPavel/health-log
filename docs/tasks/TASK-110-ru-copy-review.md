## 2. Цель

Сквозная ревизия i18n-каталога RU: отсутствие запрещённой лексики SRS (док 01 §8), единый спокойный тон, обязательные дисклеймеры на месте, согласованность терминов (СДА/«верхнее», единообразие «давление»/«АД»), корректные params-подстановки.

## 3. Бизнес-контекст

Регуляторная (R-1) и этическая рамка продукта живёт в текстах: одно слово «диагноз» в UI перечёркивает позиционирование «не медизделие». Ревизия перед релизом — обязательный гейт (SRS 01 §8).

## 4. Технический контекст

- **Архитектура:** формулировочные рамки — арх./SRS 01 §8; каталоги — TASK-013-структура.
- **Обоснование:** полу-автоматический проход: скрипт-скан запрещённых/рискованных корней по всем `ru.json` + ручное чтение экранов (тон не грепается). Риск-корни: `диагноз|лечен|назнач|показани|гипертония у вас|вы больны|страдаете` — попадание = ручной разбор (некоторые легитимны в отрицаниях: «мы не ставим диагнозов» — whitelist-подход: скан находит, ревьюер решает).

## 5. Объём

- **Включено:** скрипт `tools/scripts/copy-audit.mjs`: скан всех `src-renderer/i18n/**/ru.json` + RU-констант main (critical-texts, refusal-texts, system-prompt): (1) запрет-корни → таблица находок (файл/ключ/строка); (2) обязательные подстроки (дисклеймер-ключи — непустые, содержат «не является медицинской консультацией»; emergency — «103»); (3) dangling params (ключ использует {param}, отсутствующий в значении и наоборот — простая проверка фигурных скобок); отчёт markdown; ручная тон-ревизия: чтение всех экранов на фикстурных данных (скриншот-обход) по чек-листу тона (спокойствие, отсутствие императивов-паник, отсутствие вины — FR-4.4), правки текстов; сверка терминов (единый глоссарий-словарик в файле docs/terminology.md — создать: СДА=«верхнее», ДДА=«нижнее», «измерение», «период», «разбор»).
- **Не включено:** EN-каталоги (нет), копирайтинг новых текстов (только ревизия существующих).
- **Будущая работа:** copy-audit в PR-пайплайн (шаг lint-семейства) — включить сразу после создания скрипта (дёшево).

## 6. Файлы
