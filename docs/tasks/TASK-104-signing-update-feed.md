## 2. Цель

Подписанные Authenticode артефакты (установщик, unpacked-exe), конфигурация electron-builder под подпись, publisherName для updater'а, update feed (latest.yml на GitHub Releases); механика проверена локально тестовым сертификатом до получения боевого.

## 3. Бизнес-контекст

Неподписанный установщик = паника антивирусов/SmartScreen и блокировка автообновлений (updater проверяет подпись — NFR-11). Сертификат — внешний процесс закупки (стартует со спринта 6): эта задача не может быть начата «в чистом виде» до его получения, но вся механика — да (тестовый самоподписанный).

## 4. Технический контекст

- **Архитектура:** NFR-11, D15 — арх. 10 §2.
- **Обоснование:** OV-сертификат (достаточно для подписи; SmartScreen-репутация набирается) против EV (мгновенная репутация, дороже, требует токен) — РЕШЕНИЕ: OV как MVP-дефолт, EV — пересмотр по данным жалоб; решение зафиксировать в ADR-0005. Хранилище сертификата: GitHub Secret (.pfx + пароль) — при EV-токене потребуется подпись-сервис (HSM) — меняет пайплайн (рисковая заметка в ADR).

## 5. Объём

- **Включено:** electron-builder: `win.certificateFile/certificatePassword` (из env-секретов CI; локально — env-файл вне git), `signtoolOptions` (sha256, timestamp-сервер — обязательный RFC3161: подпись переживает истечение сертификата), `publisherName` (совпадает с подписью — требование updater'а); сборка `app-update.yml` (generic provider: URL GitHub Releases latest, channel stable); тест-механики ДО сертификата: самоподписанный сертификат (PowerShell New-SelfSignedCertificate) → подпись → проверка Get-AuthenticodeSignature → Valid (доверие в локальном хранилище); updater-проверка подписи: локальный http-фид (test-хелпер: latest.yml + подписанный exe-фикстура) → downloadUpdate принимает; документация процесса закупки (`docs/dev/certificates.md`: где купить, что дать в секреты, срок).
- **Не включено:** публикацию (105), EV/HSM (ADR-0005 — решение по факту жалоб), macOS (пост-MVP).
- **Будущая работа:** продление сертификата — календарное напоминание в release-процессе (114).

## 13. Бизнес-логика

Порядок настройки: (1) test-cert механика подписи; (2) фид latest.yml-механика (поля version/path/sha512 — builder генерирует; проверить ручным фидом); (3) боевой сертификат когда придёт: подмена секрета, контрольная подпись, сводка в ADR. Timestamp обязателен (тест: подпись с timestamp «переживает» перевод системных часов — мок-проверка невозможна, контроль — наличие tsa-URL в signtool-вызове лога).

## 14. Безопасность

Секреты: .pfx+пароль — GitHub Encrypted Secrets, локально — env вне git (.gitignore проверка); пароль никогда в логах; updater не принимает неподписанные (конфиг verifyUpdateCodeSignature дефолт).

## 15. Производительность
