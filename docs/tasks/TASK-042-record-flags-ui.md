## 2. Цель

Строки истории с признаками получают компактные бейджи: «возможная опечатка» (вычисляется на лету), «неровный пульс» (поле записи), «критическое значение» (политика) — с расшифровкой легендой/тултипом; EC-10 поддержан.

## 3. Бизнес-контекст

Пользователь и врач должны видеть «нестандартные» записи без открытия каждой (FR-2.1-дух, US-17-основа). Бейдж «неровный пульс» — единственный способ увидеть, что измерение может быть недостоверным (флаг тонометра, EC-10).

## 4. Технический контекст

- **Архитектура:** флаги вычисляются, не хранятся (кроме irregularPulse — поле записи): критический — TASK-020, опечатка — TASK-018. Вычисление в main или renderer? РЕШЕНИЕ: критический и irregular — в renderer по DTO (политика тривиальна — но дублирование правила!); правильнее: main отдаёт флаги в DTO списке. ОБЪЁМ: расширение `MeasurementDto` полями `critical: 'high'|'low'|undefined` (server-computed в list-хендлере через политику) и `irregularPulse` (уже есть); typo в списке НЕ показываем (нужна история-медиана — дорого и спорно на списке; typo виден только в момент ввода). Это уточнение контракта TASK-028 — аддитивно.
- **Обоснование:** server-computed флаг — единственный источник истины (та же политика домена, TASK-020), renderer не дублирует правило.

## 5. Объём

- **Включено:** contracts: `MeasurementDto.critical?: 'high'|'low'` (аддитивно, optional); list-хендлер проставляет critical через `assessCritical`; UI: `FlagBadges` в строке — иконки+текст-тултип: high/low (ссылка на панель TASK-041 — кнопка «Что это значит?» открывает панель записи), irregular («Неровный пульс: измерение может быть неточным»); легенда флагов (tooltip-обучающая строка над списком при наличии хоть одного флага); тесты.
- **Не включено:** typo-бейдж в истории (§4), фильтр «только с флагами» (post-MVP).
- **Будущая работа:** счётчик критических за период — появится в статистике TASK-052 (FR-4.3).

## 6. Файлы

- **Создать:** `src-renderer/features/measurement/ui/FlagBadges.tsx` + тесты; ключи i18n.
- **Изменить:** `packages/contracts` (DTO optional-поле), `list-measurements.ts` (проставление), `MeasurementRow.tsx` (бейджи), `history` каталог.

## 7. Модель предметной области

DTO-расширение (аддитивное, backward-совместимое — конверт v не меняется, арх. 05 §6): `critical?: 'high'|'low'`.

## 9. Бэкенд

List-хендлер: после маппинга DTO — `critical: assessCritical(sys, dia)`. Стоимость O(n) тривиальна.

## 10. Фронтенд

Бейджи: компактные (иконка + сокращение), полный текст — tooltip/aria-label; high/low бейдж кликабелен → открывает CriticalPanel (модально над списком, с dismiss).

## 11. API

Аддитивное поле ответа list (и add — для единообразия: add уже возвращает criticalValue отдельно — остаётся как есть, дублирование допустимо и документируется).

## 15. Производительность

## 16. Доступность

Бейджи: aria-label полный («Критическое значение: 190 на 125. Что это значит?» — кнопка); tooltip дублирует aria-label (не единственный носитель); контраст иконок AA; не только цвет (иконка-форма различна: ! для high, ↓ для low, ~ для irregular).

## 17. Интернационализация

Ключи: `flags.criticalHigh/low`, `flags.irregular`, `flags.legend`, tooltip-тексты; подстановки значений в aria-label.

## 19. Стратегия тестирования

Хендлер: DTO с sys=190 → critical='high' в ответе list; renderer: бейджи рендерятся по DTO-фикстурам (high, low, irregular, комбо high+irregular, без флагов); клик high-бейджа открывает CriticalPanel; a11y-атрибуты.

## 20. Критерии приёмки

- [ ] Запись 190/125 в истории → бейдж «критическое» с иконкой !; клик → панель TASK-041.
- [ ] Запись с irregularPulse → бейдж «неровный пульс» с иконкой ~ и объясняющим tooltip'ом (EC-10).
- [ ] Записи без флагов — без бейджей.
- [ ] Иконки различимы без цвета (тест: разные aria-label'ы/иконки).
- [ ] Контракт-тест: DTO опциональное поле не ломает старые потребители (схема аддитивна).
