## 2. Цель

`depcruise` проверяет граф зависимостей пакетов против матрицы архитектуры; нарушение = ошибка сборки; скрипт интегрируется в CI в TASK-014.

## 3. Бизнес-контекст

Гарантия долгосрочной модульности: при росте до health-log (вес/сон/глюкоза, SRS 01 §4) граф не должен размягчаться незаметно. Вторая сеть защиты после зон ESLint (TASK-003): ESLint ловит файловые зоны, cruiser — межпакетные направления.

## 4. Технический контекст

- **Архитектура:** матрица зависимостей — `docs/architecture/03-modules.md` §4 (единственный источник семантики).
- **Пакеты:** все.
- **Обоснование:** dependency-cruiser вместо madge/ts-prune — декларативные правила + валидация как код. Компромисс: ещё один инструмент — оправдан ролью «архитектурного теста».

## 5. Объём

- **Включено:** `.dependency-cruiser.cjs` с правилами: (1) `renderer-not-node`: из `apps/desktop/src-renderer` запрещены `node:*`, `electron`, `better-sqlite3`, `@hl/*` кроме `@hl/contracts`; (2) `domain-purity`: из `src/main/modules/*/domain` разрешены только внутренние файлы домена и `@hl/kernel`; (3) `application-ports`: application не импортирует adapters (внутри своего модуля) и чужие модули; (4) `module-public-api`: импорт `../<module>/…` минуя `<module>/index.ts` запрещён; (5) `packages-layering`: contracts→kernel разрешено, обратно — нет; scales-data ничего не импортирует. Скрипт `depcruise` = `depcruise . --config`. Фикстуры-проверки правил (см. §19).
- **Не включено:** визуализация графа (опция `--output-type dot` упомянута в комментарии, не автоматизируется).
- **Будущая работа:** правило запрета прямого net-импорта — вместе с EgressGateway (TASK-075).

## 13. Бизнес-логика

Ключевое правило для будущих модулей: **`module-public-api`** — межмодульное взаимодействие только через публичный `index.ts` (арх. 03 §2). Паттерн правила: forbidden `src/main/modules/(?<from>[^/]+)/((?!index)[^/]+)` → to `src/main/modules/(?<to>[^/])/…` при from ≠ to. Точный синтаксис правится по документации версии, семантика неизменна.

## 14. Безопасность

Правило (1) дублирует модель угроз: renderer недоверенная зона без Node-доступа (арх. 08 §4).

## 15. Производительность

## 19. Стратегия тестирования

Архитектурный тест = сам `depcruise` на фикстурах: `tools/depcruise-fixtures/bad-renderer-node.ts` (нарушает 1), `bad-cross-module-internal.ts` (нарушает 4), `ok-contracts-to-kernel.ts` (не нарушает). Скрипт `test:depcruise-rules`: прогон cruiser на каталоге фикстур с ожиданием конкретных violated-rule-имён; основной `depcruise` игнорирует фикстуры.
