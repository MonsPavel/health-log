## Правила заполнения (обязательны для каждого документа)

1. **Самодостаточность.** Документ читается в изоляции. Все факты, необходимые для реализации, — внутри. Ссылки на SRS/архитектуру (`docs/…`) — только как источники истины для контекста; факты дублируются в документе. Ссылки вида «см. TASK-YYY» в разделах содержания запрещены; в §1 (метаданные) ID зависимостей — разрешены.
2. **N/A-правило.** Неприменимый раздел помечается «N/A — <одна строка причины>». Пустых разделов нет.
3. **Контракты, не код.** Сигнатуры типов, DDL, схемы zod — это спецификация и допускаются; тела функций, готовые реализации и конфиги-копипаста — нет.
4. **Измеримость.** Каждый пункт §20 проверяется командой, тестом или наблюдаемым действием. Слова «корректно», «удобно», «быстро» без числа запрещены.
5. **Единая терминология.** Термины — из глоссария SRS (`docs/README.md`) и доменной модели (`docs/architecture/02`).
6. **Правда о сети.** Любое сетевое поведение — только через EgressGateway (арх. 08 §5); телеметрия наружу запрещена (FR-7.2).
