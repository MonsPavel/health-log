## 2. Цель

Сборка RC: сборка помечена, установлена на чистую машину и на машину с накопленными данными; ручной прогон всех 10 UC SRS (док 06); триаж найденных дефектов (блокер/пост-MVP); буфер исправлений; финальный go/no-go-чеклист → кандидат в v1.0.

## 3. Бизнес-контекст

Последний барьер перед пользователями: автотесты доказывают компоненты — RC-прогон доказывает целостный продукт в руках человека (включая «боевые» данные многолетнего объёма и беспорядочные действия). Публичный релиз — отдельное бизнес-решение (регуляторная проверка R-1), техническая готовность фиксируется здесь.

## 4. Технический контекст

- **Архитектура:** N/A — процесс; все гейты уже пройдены (DoD 112).
- **Обоснование:** две машины: (A) чистая Windows 10/11 — путь новичка (установка→онбординг-пустые состояния→данные); (B) машина с накопленными реальными/синтетическими данными за месяцы (реалистичный объём 1–5k записей) — производительность ощущений, миграции копий.

## 5. Объём

- **Включено:** (1) сборка RC из main (тег `v1.0.0-rc.1`, пайплайн 105 → подписанный артефакт); (2) чек-лист ручного прогона `docs/release/rc-checklist.md`: все 10 UC SRS по шагам основных И альтернативных потоков (таблица: UC/шаг/результат/дефект-ссылка); (3) прогон на машине A: установка→запуск→ввод→история→динамика→ИИ (fake или модель)→экспорт→копия→wipe; (4) прогон на машине B: реальный объём → отзывчивость (сводка/динамика/PDF)→ восстановление копии → обновление по фиду; (5) триаж: каждый дефект — блокер RC (чинить сейчас) / major (чинить или документировать Known Issues) / пост-MVP (в бэклог); (6) буфер исправлений + повтор прогонов затронутых UC; (7) go/no-go: DoD-112 ✅ + все UC PASS + Known Issues подписаны → RC-вердикт (подписи владельца в документе).
- **Не включено:** публичное распространение (отдельное решение: юридическая консультация R-1 обязательна до этого), маркетинг.
- **Будущая работа:** пост-релизный мониторинг — без телеметрии: каналы обратной связи (GitHub issues, reviews) — процессы вне продукта.
