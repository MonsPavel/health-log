## 2. Цель

Workflow `release.yml`: на тег `v*` — Windows-runner: полная сборка → подпись → пакетирование → полный E2E (Windows) + крэш-тест + size-audit гейт → draft release с артефактами и заготовкой notes → публикация вручную. От тега до draft — без ручных шагов.

## 3. Бизнес-контекст

«Человек публикует релиз» — последняя ручная точка контроля (арх. 10 §3): автоматика готовит и доказывает, решение выпустить — за мейнтейнером. E2E на Windows-runner здесь (TD-6 закрывается): критический путь на целевой ОС перед пользователями.

## 4. Технический контекст

- **Архитектура:** арх. 10 §3; гейты — §4 (DoD).
- **Обоснование:** Windows-runner для E2E — целевая платформа (Electron-тесты требуют GUI-session — windows-latest даёт); ubuntu-шаги не повторяются. Кэш pnpm/моделей как в 014/092.

## 5. Объём

- **Включено:** `release.yml`: trigger push tag `v*`; job windows: checkout → pnpm → install → lint/typecheck/depcruise → unit/integration (vitest) → `pnpm dist` (с подписью из секретов TASK-104) → e2e: `pnpm test:e2e` (все спеки, включая data-care/recovery/edge) → `pnpm test:crash` (N=10, TASK-102) → `pnpm size:audit` (гейт ≤200 МБ exit-код) → eval-отчёт? НЕТ: полный eval на полной модели — ручной предрелизный чеклист (nightly покрывает 1B); артефакты: установщик+latest.yml+отчёты → softprops/draft release с тегом; release notes: заготовка из шаблона (TASK-114) + автоген changelog-commits; публикация — ручная (кнопка в Releases). Отчётный job summary (таблица гейтов).
- **Не включено:** macOS/Linux jobs (пост-MVP), авто-публикацию (никогда), eval на полной модели в CI (стоимость; чек-лист вручную).
- **Будущая работа:** параллельные jobs (e2e ∥ bench) при >30 мин.

## 13. Бизнес-логика

Гейты-порядок: ранние дешёвые (lint/test) → тяжёлые (E2E/crash) → сборка артефактов. Падение любого → draft не создаётся. Правило ретраев: только инфраструктурные флаки e2e (retry 1), гейт-тесты без ретраев.

## 14. Безопасность

Секреты подписи — только в release-окружении; permissions minimal; артефакты — подписанные (проверка в job-шаге Get-AuthenticodeSignature перед attach — самопроверка пайплайна).

## 15. Производительность

Бюджет прогона ≤40 мин (E2E ~15 + crash ~5 + сборка ~10 + тесты ~5); превышение — шардировать.

## 19. Стратегия тестирования

## 20. Критерии приёмки

- [ ] Пробный тег: draft release создан, артефакты подписаны (самопроверка-шаг зелёный), notes-заготовка на месте.
- [ ] Падение E2E-шага → draft НЕ создан (контрольный прогон с искусственным сбоем).
- [ ] size-audit превышение → красный (мок-лимит 1 МБ).
- [ ] Крэш-тест PASS в логе (гейт).
- [ ] Публикация — вручную; удаление test-тега после отладки.
- [ ] Прогон ≤40 мин.
