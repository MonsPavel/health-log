## 2. Цель

Полноэкранный оверлей блокировки (пароль → unlock, backoff-сообщение, индикатор Argon2-работы), экран настройки: включение пароля с обязательным предупреждением о невосстановимости, смена/снятие пароля, выбор автоблока; heartbeat пользовательской активности для корректного автоблока.

## 3. Бизнес-контекст

Пользовательский UX защиты: П4 оставляет ноутбук маме — блокировка должна быть понятной и не пугающей; предупреждение «забыли пароль — данные невосстановимы» — обязательный текст (NFR-2, тест).

## 4. Технический контекст

- **Архитектура:** оверлей вне роутера (арх. 06 §4); события lock — TASK-094.
- **Обоснование:** полноэкранный оверлей (не отдельное окно): мгновенно закрывает весь контент от «случайного взгляда»; снимается только unlock'ом.

## 5. Объём

- **Включено:** `LockOverlay`: подписка на `lock:engaged|required` + `vault/status` при старте (если mode=passphrase и locked — оверлей сразу); поле пароля (type=password, Enter=unlock), кнопка «Разблокировать» с состоянием «Проверка…» (~0,5 с Argon2 — честный индикатор), ошибка → инлайн «Неверный пароль», backoff → обратный отсчёт (disabled кнопка с «Подождите N с»); блокировка скринридер-доступа к контенту под оверлеем (aria-hidden + inert); `SecuritySettings`: секция «Защита паролем»: выключено → кнопка «Включить» (диалог: новый пароль ×2 + предупреждение-чекбокс «Я понимаю, что без пароля данные не восстановить» — чекбокс обязателен, тест) → set-passphrase; включено → смена (старый+новый), снять (старый), выбор автоблока (5/15/60/выкл select); heartbeat: renderer шлёт `app/heartbeat` на pointerdown/keydown (throttle 30 с) — активность для автоблока; тесты.
- **Не включено:** подсказку пароля (hints — ослабление, никогда), биометрию.
- **Будущая работа:** Windows Hello — пост-MVP.

## 12. Управление состоянием

## 13. Бизнес-логика

Кейсы: старт с passphrase+locked → оверлей сразу (данные скрыты даже в момент загрузки); backoff — кнопка disabled с live-отсчётом; успешный unlock → оверлей исчезает, фокус в контент; смена пароля: неверный старый → инлайн; чекбокс-гейт включения.

## 14. Безопасность

Ни одного контентного байта в DOM под оверлеем (inert+unmount? Решение: содержимое под оверлеем выгружается — маршруты не рендерятся при locked — строже inert; тест: запрос истории при locked возвращает LOCKED — уже гвардия; DOM-тест — данных нет).

## 15. Производительность

Оверлей мгновенный (без запросов при показе).

## 16. Доступность

Поле пароля — label+autocomplete="current-password"; ошибка — aria-describedby+focus на поле; отсчёт — aria-live polite; Esc ничего не делает (нет безопасного действия — блок обязателен).

## 17. Интернационализация

Ключи: `lock.title/unlock/checking/wrong/wait`, `security.passphrase.*` (включение/смена/снятие/предупреждение/чекбокс), `security.autolock.*`.

## 19. Стратегия тестирования

Тесты: оверлей по событию locked; DOM-тест «история не в DOM при locked»; unlock happy (мок канала) + wrong + backoff-отсчёт; чекбокс-гейт включения пароля; heartbeat throttle; предупреждение-текст golden (обязательная строка «невосстановим»).

## 20. Критерии приёмки

- [ ] Включение пароля: без чекбокса кнопка мертва; с чекбоксом — работает; предупреждение содержит «невосстановим» (golden).
- [ ] Перезапуск с паролем → оверлей до любых данных; контента в DOM нет (тест).
- [ ] Неверный пароль → инлайн-ошибка; backoff → отсчёт + disabled (мок).
- [ ] Смена пароля: старый неверный — инлайн; верный — успех, перезапуск с новым.
- [ ] Autolock: heartbeat продлевает (моки канала); 5 мин тишины → оверлей.
- [ ] axe: оверлей/настройки без нарушений; фокус в поле пароля при показе.
