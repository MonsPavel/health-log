## 2. Цель

Чистый конвертер «все записи → CSV» (UTF-8 с BOM, разделитель `;`, RFC 4180-экранирование) + use case экспорта всего журнала; файл Excel-дружелюбен при русской локали.

## 3. Бизнес-контекст

Владение данными (принцип 3 SRS): экспорт — страховка пользователя и мост к врачу/таблицам (US-27). Excel-совместимость — не косметика: именно её попытается открыть П5 (врач) и сам пользователь.

## 4. Технический контекст

- **Архитектура:** Reporting context — арх. 02 §3.4; конвертер — чистый (тестируемость), ФС — порт.
- **Модуль:** `reporting`.
- **Обоснование:** `;`-разделитель — дружелюбие ru-Excel (запятая — десятичный разделитель в ru-локали); BOM обязателен иначе Excel откроет UTF-8 как CP1251-кашу. Свой конвертер вместо библиотеки: 30 строк, полный контроль кавычек (RFC 4180) — зависимости не нужны.

## 5. Объём

- **Включено:** `toCsv(rows: ExportRow[]): string` (заголовок, BOM `\uFEFF` префикс, кавычки полей с `;"\n`, удвоение внутренних кавычек); `ExportRow`-маппинг агрегата: `id, profileId, datetime ISO (utc+смещение — «2026-09-24T08:12:00+03:00» — однозначность), sys, dia, pulse, irregular (true/false), arm, note, source`; use case `ExportCsv(profileId): Promise<{csv: string; count: number}>` — все записи через listByPeriod(all, пачками по 1000 — конкатенация); коды ошибок `EXPORT/FAILED`; юнит-тесты конвертера (кавычки/переносы/юникод/эмодзи в заметке), интеграционный тест use case (5 записей tmp-БД → точный CSV-текст).
- **Не включено:** диалог сохранения и запись файла (TASK-065), фильтры периода в экспорте (всегда всё — решение: экспорт = полнота; фильтрованный CSV — пост-MVP).
- **Будущая работа:** фильтрованный экспорт, XLSX (никогда — CSV достаточно).

## 6. Файлы

- **Создать:** `main/modules/reporting/{domain/csv.ts,application/export-csv.ts}` + тесты (golden-строки CSV).

## 7. Модель предметной области

`ExportRow` — плоская форма; datetime — ISO со смещением (не две колонки) — читаемо человеком и парсится машиной однозначно.

## 8. База данных

Чтение через порт (пачки 1000 — ограничение памяти на 50k: строка CSV 50k×~60 байт ≈ 3 МБ — приемлемо целиком).

## 13. Бизнес-логика

Экранирование: поле оборачивается в кавычки при наличии `;"\r\n`; внутренние `"` → `""`; перенос строки в заметке сохраняется внутри кавычек. Порядок строк: takenAt asc (хронология для врача). BOM только в начале файла.

## 14. Безопасность

CSV-инъекция (формулы `=cmd()` в заметке) — риск для Excel: решение — НЕ санитизировать (данные пользователя для него самого), но задокументировать предупреждение в README экспорта (открытие чужих CSV). PHI в CSV — ожидаемо (это выгрузка пользователя).

## 15. Производительность

50k записей → строка 3 МБ <2 с (тест-ориентир 5k ≤300 мс); конкатенация через массив+join.

## 19. Стратегия тестирования

Golden: фикстурный набор (заметка с `;`, кавычками, переносом, эмодзи) → точная строка CSV (snapshot); property: roundtrip-парсинг собственным mini-парсером тестов; интеграция: use case на tmp-БД.

## 20. Критерии приёмки

- [ ] Golden-тест: заметка `болит; голова "сильно"` в CSV корректно закавычена; Excel-ручная проверка открытия (скриншот в PR).
- [ ] BOM присутствует; разделитель `;`; порядок asc.
- [ ] Пустой журнал → валидный CSV с заголовком.
- [ ] 5k записей ≤300 мс (тест-таймер).
- [ ] Эмодзи/юникод без искажений (roundtrip).
