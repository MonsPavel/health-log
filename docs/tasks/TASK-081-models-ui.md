## 2. Цель

Экран ИИ: список моделей из манифеста (размер/языки/мин. RAM/лицензия), запрос согласия на сеть при первой загрузке, прогресс/пауза/докачка, состояния ошибок, «настроить позже»; предупреждения о несовпадении языка модели и слабом железе; выбор активной модели.

## 3. Бизнес-контекст

FR-5.8 + US-24: прозрачность (объём до загрузки), уважение решения («позже» не навязывается повторно), совместимость языка модели с интерфейсом (FR-5.9) и железа (NFR-5 честность). Приложение полноценно без модели — экран это демонстрирует.

## 4. Технический контекст

- **Архитектура:** экранный слой над ModelStore/LlmEngine; согласие modelsDownload — экран настроек приватности (099) позже, запрос здесь.
- **Обоснование:** онбординг-паттерн: баннер «ИИ не настроен» на экране ИИ (не модальный), ненавязчиво (UC-07 A3).

## 5. Объём

- **Включено:** канал `ai/models/list → [{descriptor, state, bytesLoaded}]`, `ai/models/download {modelId}` (запускает + подписка ai:progress), `ai/models/pause|resume|reset {modelId}`, `ai/models/select {modelId}` (prefs.aiSettings.modelId → ensureModel при входе на экран чата/резюме); `AiModelsScreen` (часть /ai — вкладка «Модель»): карточки моделей (имя, версия, размер МБ/ГБ, языки-бейджи, RAM-требование, лицензия), кнопки по состоянию (Скачать/Пауза/Продолжить/Выбрать/Удалить? — удаление модели: НЕТ в MVP, диск чистится wipe'ом; решение), прогресс-бар с МБ и процентом; запрос согласия: первый «Скачать» → диалог «Приложение скачает X ГБ с {host}. Согласие можно отозвать в Приватности» → prefs.netConsents.modelsDownload=true; предупреждения: язык модели ≠ язык UI → бейдж-предупреждение (не блокировка); RAM машины < minRamGb (os.totalmem на main — поле в list-ответе) → предупреждение «может работать медленно»; «позже»: ссылка «Настроить позже» — баннер схлопывается (prefs.aiSettings.dismissedUntil — до первого захода в ИИ-чат? РЕШЕНИЕ: dismissed навсегда до явного «Настроить» из настроек — просто); тесты.
- **Не включено:** удаление файлов моделей, автозагрузка при онбординге (P1-фаза онбординга отдельно — баннер-паттерн достаточен).
- **Будущая работа:** несколько установленных моделей с переключением (Store поддерживает, UI — пост-MVP).

## 11. API

## 12. Управление состоянием

useQuery ['ai','models'] + события → invalidate; согласия — через prefs/patch.

## 13. Бизнес-логика

Кейсы: первая загрузка без согласия → диалог → отказ = отмена (без сети — gateway бы заблокировал, UI перехватывает раньше); «позже» → баннер скрыт, экран моделей доступен из настроек ИИ всегда; выбор модели при состоянии paused → предложение продолжить.

## 14. Безопасность

Согласие показывается ДО первого запроса (UI-перехват до gateway-блока); host в тексте согласия — из URL манифеста (реальный домен, не «интернет»).

## 19. Стратегия тестирования

Компонентные: карточки по state-фикстурам (все 6 состояний), согласие-диалог до загрузки (мок invoke: download не вызван до подтверждения), предупреждения (язык en при ru-UI; RAM 8<16), прогресс из события обновляет; e2e (HL_FAKE+мок http из тест-хелперов 080): скачать dev-модель → installed → select.

## 20. Критерии приёмки

- [ ] Все 6 состояний карточки рендерятся верно (тест-таблица).
- [ ] Первый «Скачать» → согласие-диалог; отказ → сети не было (gateway-журнал пуст, spy).
- [ ] Прогресс обновляется из ai:progress (fake-события).
- [ ] Предупреждения язык/RAM показываются по фикстурам (не блокируют).
- [ ] «Настроить позже» — баннер не возвращается; экран моделей доступен вручную.
- [ ] e2e: dev-модель скачать → выбрать → статус выбранной.
