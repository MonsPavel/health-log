## 2. Цель

Self-check при старте: целостность БД (PRAGMA quick_check), версия схемы, наличие ключа, состояние LLM-воркера, консистентность prefs — результат в память контейнера + раздел «О приложении»: версии приложения/шкал/модели/схемы, статус self-check, время старта.

## 3. Бизнес-контекст

NFR-3/NFR-10: повреждение должно обнаруживаться явно (не «мистические глюки»), версии — видимы (поддержка и eval-отчёты ссылаются). Self-check — источник правды для recovery-экрана (101) и диагпакета (103).

## 4. Технический контекст

- **Архитектура:** арх. 09 §8 (self-check), NFR-10 (версии видны).
- **Обоснование:** quick_check (не full integrity) — компромисс скорости (мс против секунд на 50k); full — по кнопке «Полная проверка» в диагностике (включить опцию — дёшево).

## 5. Объём

- **Включено:** `SelfCheckService`: после открытия БД (контейнер): `quick_check` → ok|corrupt; schema_version чтение; vault-режим; worker-статус (если ИИ-модуль есть); prefs-валидация (zod уже при чтении — флаг); `SelfCheckReport {dbOk, schemaVersion, vaultMode, worker?, prefsOk, checkedAtUtc, startupMs}`; хранение в контейнере; канал `app/selfcheck → report` + `app/meta → {appVersion, formatVersions…}`; UI: «Настройки → О приложении»: строки версий (приложение/схема БД/активная шкала code+version/модель id+version если есть), статус-блок self-check (зелёный/красный с деталями), кнопка «Полная проверка БД» (full integrity — прогресс, результат), время старта; тесты.
- **Не включено:** авто-восстановление при corrupt (TASK-101), фиксация в лог при каждом старте (включено — одна строка лога).
- **Будущая работа:** расписание периодических проверок (не нужно — старт достаточно).

## 6. Файлы

- **Создать:** `main/app/selfcheck.ts`; contracts `app/meta|selfcheck`; `ipc/handlers/app-info.ts`; `src-renderer/features/settings/ui/AboutSection.tsx` + тесты; ключи i18n.
- **Изменить:** `container.ts` (запуск self-check после миграций, хранение отчёта), лог.

## 7. Модель предметной области

`SelfCheckReport` — иммутабельный снимок старта; полная проверка — отдельный запрос (не мутирует стартовый отчёт, отдельный результат в UI).

## 8. База данных

PRAGMA quick_check; full: PRAGMA integrity_check; schema_version из meta.

## 9. Бэкенд

Сбой quick_check → отчёт dbOk=false → контейнер продолжает старт (БД открыта, но флаг выставлен) → recovery-экран решает (101): разделение «обнаружить» и «реагировать» — тест.

## 10. Фронтенд

Красный статус self-check → бейдж в настройках + ссылка на восстановление (101-экран).

## 11. API

`app/selfcheck {} → SelfCheckReport`, `app/meta {} → {appVersion, schemaVersion, scaleVersion, modelVersion?}`, `app/integrity-full {} → {ok, details}` (долгий — progress не нужен, <10 с).

## 12. Управление состоянием

useQuery ['selfcheck'] — статичен за сессию (старт); full — useMutation.

## 13. Бизнес-логика

Кейсы: corrupt-БД → dbOk=false, остальной отчёт заполнен (частичная диагностика); отсутствие ключа при существующей БД → vault-строка отражает (KEY_MISSING — но контейнер упал раньше? Порядок: vault проверяется ДО открытия; самчек после — фиксирует mode; KEY_MISSING-случай уходит в диалог 011/101 — не в отчёт; задокументировать).

## 14. Безопасность

Отчёт не содержит путей/PHI (только факты/версии) — безопасен для диагпакета.

## 15. Производительность

quick_check 50k ≤100 мс; startup-бюджет: self-check ≤150 мс общего старта (замер в тесте).

## 16. Доступность

Статусы — текст+иконка; таблица версий — definition-list семантика.

## 17. Интернационализация

Ключи: `about.*` (версии, статусы, полная проверка); версии — параметры.

## 18. Телеметрия

Лог: одна строка self-check-резюме на старт (dbOk, schemaVersion, startupMs).

## 19. Стратегия тестирования

Интеграционные: healthy tmp-БД → dbOk=true, версии заполнены; повреждённая (байт-флип в файле фикстуры) → dbOk=false + остальное заполнено; full-check кнопка (мок long-операции); UI: строки версий, красный бейдж при dbOk=false.

## 20. Критерии приёмки

- [ ] Healthy-старт: отчёт полный, лог-строка присутствует, ≤150 мс (замер).
- [ ] Повреждённая БД: dbOk=false, приложение стартует в recovery-режим (заглушка 101 — здесь только флаг).
- [ ] «О приложении»: все версии видны (скриншот-тест).
- [ ] Полная проверка: запуск/результат/инвалидация.
- [ ] Отчёт без путей/PHI (тест-инвариант полей).
