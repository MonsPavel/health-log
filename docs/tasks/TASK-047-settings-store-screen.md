## 2. Цель

Постоянное хранилище настроек в БД (миграция v3: `app_setting`), use cases get/set, каналы `prefs/get|set`, экран настроек: тема, размер текста, формат даты — применение мгновенное, без перезапуска, персистентно.

## 3. Бизнес-контекст

US-36: крупный текст и тёмная тема — критичны для П3; настройки в БД (не localStorage) попадают в резервные копии и мигрируют между машинами (FR-6.4-семантика). Позиция: до крупного режима (048) и простого режима (049), которые на нём строятся.

## 4. Технический контекст

- **Архитектура:** Settings & Profile — арх. 02 §3.6; хранилище — 04 §3 (app_setting); миграции — 04 §5.
- **Модуль:** `settings-profile`; миграция v3.
- **Обоснование (нумерация миграций, уточнение реестра):** v2 = FTS (TASK-045), **v3 = app_setting (эта задача)**; далее по мере фаз: v4 reference_scale (TASK-051), v5 ai_summary (TASK-087), v6 chat_message (TASK-089), v7 network_event (TASK-075). localStorage-ключи темы/масштаба из TASK-013 мигрируются: при первом prefs/get — перенос в БД и удаление из localStorage (one-time migrate).

## 5. Объём

- **Включено:** миграция v3 `app_setting (key TEXT PK, value_json TEXT NOT NULL, updated_at_utc INTEGER NOT NULL)`; `SettingsStore` (адаптер: get/set по ключу с zod-валидацией значения схемы; повреждённый JSON → дефолт + лог warn); `PreferencesService`: схема `Prefs {theme: 'system'|'light'|'dark', textScale: '100'|'112.5'|'125', dateFormat: 'auto'|'dmy'|'mdy', advancedMode: boolean, netConsents: {updatesCheck: boolean}}` (единый документ `prefs` — не по-ключево: атомарные чтения); каналы `prefs/get {} → Prefs`, `prefs/set {patch: Partial<Prefs>} → Prefs`; валидация patch (zod .partial(), merge в сервисе); UI: экран «Настройки» — секции «Вид» (тема — радиогрупп, размер текста — сегмент, формат даты — select), применение сразу через событие `prefs:changed` (новое событие в HlEventMap) → renderer перечитывает; localStorage→БД миграция; тесты.
- **Не включено:** редактирование netConsents UI (TASK-099 — поле в схеме уже), ИИ-настройки (TASK-081 — схема расширяема), профили.
- **Будущая работа:** per-key granular схемы — при росте документа >20 полей.

## 6. Файлы

- **Создать:** `shared/db/migrations/v3-app-setting.ts`; `modules/settings-profile/{application/preferences-service.ts,adapters/settings-store.ts}`; contracts `prefs/*`; `ipc/handlers/prefs.ts`; `src-renderer/features/settings/ui/{SettingsScreen.tsx,AppearanceSection.tsx}`; `model/use-preferences.ts` (useQuery + useMutation); тесты (миграция, сервис, хендлеры, UI, localStorage-миграция).

## 7. Модель предметной области

`Prefs` — VO настроек (иммутабельный); сервис валидирует: неизвестные ключи patch отбрасываются (strict), типы — zod; событие `prefs:changed` — сигнал рендереру (значения — только имена изменённых ключей, не PHI-проблема, но компактность).

## 8. База данных

DDL v3 (§5); seed: пусто (дефолты в коде PreferencesService: DEFAULT_PREFS — источник правды значений по умолчанию).

## 9. Бэкенд

Порядок: zod → merge с текущими → валидация результата → запись → событие. Отказ записи → err STORAGE/*.

## 10. Фронтенд

`usePreferences()` — useQuery(['prefs']) + мутация set; применение темы/масштаба — подписка на prefs в провайдерах (заменяет прямое чтение localStorage из TASK-013); optimistic update (patch локально, откат при ошибке) — простой случай, без конфликтов.

## 11. API

`prefs/get`: `{}` → `Prefs` (полный документ); `prefs/set`: `{patch}` → `Prefs` (обновлённый полный). Ошибки: VALIDATION/FAILED (невалидный patch), STORAGE/*.

## 12. Управление состоянием

Ключ `['prefs']`; инвалидация — событие `prefs:changed` (main-источник) + локальный optimistic; миграция localStorage→БД: при первом prefs/get, если `hl.theme`/`hl.textScale` существуют → включить в документ, удалить ключи localStorage.

## 13. Бизнес-логика

Формат даты: `auto` = Intl по локали; `dmy`/`mdy` — явный выбор (влияет на TASK-013 утилиту — параметр locale/preset расширяется prefs-значением; обновление утилиты входит в объём). Тема/масштаб применяются к `<html>` немедленно (тот же механизм TASK-013, источник сменился).

## 14. Безопасность

value_json — zod-валидация при каждом чтении (повреждение → дефолт); сеть не участвует; netConsents-поле — читается только EgressGateway (TASK-075), UI-редактор — TASK-099.

## 15. Производительность

prefs/get — один SELECT (запрос в памяти-кэше адаптера тоже допустим — но источник истины БД; кэш-инвалидация по событию самой же записи — просто без кэша: SELECT микросекунды).

## 16. Доступность

Радиогруппы/сегменты — aria; переключение масштаба сразу видно (скринридер объявит изменения полей — стандартно); фокус сохраняется при перерисовке секции.

## 17. Интернационализация

Ключи секций/опций; формат дат — Intl + prefs-пресет; все новые тексты — каталог (check:i18n).

## 18. Телеметрия

Лог: `prefs.set keys=[theme]` (имена ключей, не значения — значения не чувствительны, но единообразие).

## 19. Стратегия тестирования

Интеграционные: миграция v3; сервис get/set/merge/повреждённый JSON→дефолт; хендлеры zod; localStorage→БД миграция (фикстура localStorage). UI: смена темы → html[data-theme] и вызов канала; optimistic-откат при ошибке.

## 20. Критерии приёмки

- [ ] Миграция v3: таблица существует; повторное применение — no-op.
- [ ] set theme=dark → перезапуск → тема dark (персистентность в БД).
- [ ] Повреждённый value_json → дефолты + warn-лог, без креша.
- [ ] localStorage hl.theme → перенесён в prefs и удалён из localStorage (тест).
- [ ] Неизвестное поле patch → отброшено, валидные применены (strict-merge тест).
- [ ] Смена масштаба текста применяется мгновенно (без перезапуска).
