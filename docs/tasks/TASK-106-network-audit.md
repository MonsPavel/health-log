## 2. Цель

Повторяемая процедура: запуск релизной сборки с фиксацией ВСЕХ сетевых соединений ОС в сценариях (чистый запуск без согласий → ожидание нуля; с согласиями → только заявленные хосты), сверка наблюдаемого с журналом приложения, отчёт-шаблон; результат прикладывается к каждому релизу.

## 3. Бизнес-контекст

BG-2 без доказательства — декларация: AC-4.1 («трафик совпадает с белым списком и журналом») — главный аргумент доверия. Проверка ОС-уровня ловит и «скрытые» соединения зависимостей, которые код-ревью не увидит.

## 4. Технический контекст

- **Архитектура:** AC-4.1; известное ограничение updater-байтов (TASK-096 §22) — процедура фиксирует факт проверки, байты updater'а отмечает как «приблизительные».
- **Обоснование:** инструмент — `netsh trace`/`Get-NetTCPConnection` polling (Windows-native, без установки) + опционально Fiddler для содержимого HTTPS-сигнатур (SNI); polling каждые 500 мс ловит короткие соединения достаточно (соединения updater'а живут секунды).

## 5. Объём

- **Включено:** `tools/scripts/net-audit.mjs`: обёртка над polling Get-NetTCPConnection (pid-фильтр на процессы приложения) → лог соединений (ts, remote-ip:port, reverse-dns host, state); сценарный драйвер: шаги выполняются вручную оператором по чек-листу, скрипт пишет timeline; `docs/architecture/audits/audit-template.md`: (S1) чистая установка, согласий нет, 5 минут работы с полным функционалом кроме сети → ожидание: 0 соединений; (S2) включить согласие моделей → скачать модель → ожидание: только хост манифеста; (S3) согласие обновлений → проверить → ожидание: только github.com/api. (S4) отзыв согласий → повтор → 0; сверка: каждое наблюдение имеет запись в журнале приложения (экспорт журнала из экрана «Приватность» — ручной скриншот/выгрузка) и наоборот; отчёт-заполнение; чек-лист PASS/FAIL.
- **Не включено:** автоматический прогон в CI (ручная процедура на релизе — качественный мониторинг содержимого невозможен скриптом; скрипт — сборщик данных), Linux/macOS варианты (пост-MVP).
- **Будущая работа:** авто-дифф журнала↔наблюдений (сейчас — глазами по шаблону).

## 13. Бизнес-логика

Критерии FAIL: любое соединение вне заявленных хостов в любом сценарии; расхождение «наблюдаемо, но журнала нет» (кроме updater-байтов-оговорки); отсутствие blocked-записей при попытках без согласий (значит gateway не сработал). Пограничное: ОС-уровень соединения до nslookup — reverse-dns может резолвить CDN — допуск по IP-диапазонам хоста (зафиксировать в шаблоне).

## 14. Безопасность

Сама процедура без внедрения трафика (только наблюдение); дампы не содержат содержимого TLS (только метаданные) — безопасно прикладывать.
