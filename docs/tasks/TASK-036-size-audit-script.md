## 2. Цель

Скрипт `size-audit`: замер установщика и распакованной сборки, сравнение с лимитом 200 МБ (NFR-5), отчёт по топ-крупным компонентам (Electron, нативные модули, бандлы) с рекомендациями.

## 3. Бизнес-контекст

Бюджет размера (D1a) — риск архитектуры Electron: превышение 200 МБ (NFR-5) = триггер стратегического решения (миграция на Tauri). Ранний контроль: если уже на P1 установщик >180 МБ — решение принимается на 3-м месяце, а не перед релизом.

## 4. Технический контекст

- **Архитектура:** D1a, NFR-5 — арх. 01 §2, 05.
- **Инфраструктура:** tools/scripts.
- **Обоснование:** Node-скрипт без зависимостей (fs.stat + рекурсивный du); не входит в PR-CI (сборка тяжёлая) — запуск вручную/на теге (интеграция TASK-105).

## 5. Объём

- **Включено:** `tools/scripts/size-audit.mjs`: параметры `--dist <путь к release-каталогу>`; измеряет: размер .exe-установщика; размер win-unpacked целиком; топ-10 файлов/каталогов по размеру; сравнение с лимитом 200 МБ → exit 0/1; человекочитаемый отчёт (таблица) + JSON-режим (`--json` для будущего CI); предупреждение-зона: >180 МБ → warning «близко к лимиту».
- **Не включено:** автоматический инкремент-анализ между релизами (будущая работа — дифф отчётов).
- **Будущая работа:** интеграция гейта в тег-пайплайн (TASK-105), историческая статистика.

## 6. Файлы

- **Создать:** `tools/scripts/size-audit.mjs`; скрипт `size:audit` в корне.
- **Изменить:** нет.
