## 2. Цель

Минимальный JobScheduler в main (реестр задач, интервалы, фейковые часы для тестов) + первая задача: «копии нет >14 дней → мягкая ненавязчивая подсказка не чаще раза в неделю» (R-4).

## 3. Бизнес-контекст

Копия бесполезна, если её не делают: подсказка — единственная автоматическая защита от «умер ноутбук — дневник сгорел». Каркас планировщика нужен будущим напоминаниям измерений (FR-10, пост-MVP) и техзадачам (арх. 09 §1) — создаётся здесь, на первой реальной задаче.

## 4. Технический контекст

- **Архитектура:** JobScheduler — арх. 09 §1 (реестр, интервалы, окно простоя — упрощённо в MVP: без окна простоя, только интервалы и дедупликация показа).
- **Обоснование:** 50-строчный scheduler (setInterval + реестр + last-run в prefs) вместо node-cron: пять задач не стоят зависимость; тесты на FixedClock. Интервал в MVP — только «при каждом старте проверь условие» (не живой таймер): подсказка о копии проверяется на старте; живые интервалы появятся с напоминаниями (расширение каркаса, не переделка).

## 5. Объём

- **Включено:** `JobScheduler`: `register({name, runOnStart?, intervalMs?, run(ctx)})`; `tick(now)` — вызов задач с истёкшим интервалом; lastRun хранение в prefs (`jobState`); задача `backup.reminder`: условие — последняя копия старше 14 дней ИЛИ отсутствует при ≥7 записях (метаданные: путь/дата последней копии — prefs поле, обновляется TASK-073 onSuccess); событие `job:backup-reminder` → renderer баннер на дашборде (один раз в неделю максимум — lastShown в prefs; кнопки «Создать копию» (диалог 073) и «Позже»); подключение scheduler к контейнеру (tick при старте); тесты с FixedClock.
- **Не включено:** живые setInterval-задачи (напоминания — пост-MVP), тихие часы, окно простоя.
- **Будущая работа:** FR-10 напоминания (живой таймер + уведомления ОС) — расширение этого каркаса.

## 10. Фронтенд

Баннер: жёлто-нейтральный (не красный), текст «Пора сделать резервную копию дневника — 2 минуты», кнопки «Создать копию»/«Позже» (Позже → lastShown=now, скрыть до недели).

## 11. API

Событие `job:backup-reminder {}` — доставка баннера; действие кнопки — открытие BackupDialog (локально).

## 12. Управление состоянием

lastRun/lastShown — в prefs (персистентны); баннер — локальный state от события.

## 13. Бизнес-логика

Кейсы: записей <7 → не напоминаем (нечего терять — правило); копия свежая (<14д) → тишина; копия старше → баннер 1×/7д; «Позже» — пауза 7д точно (FixedClock тест); после создания копии баннер не показывается (lastBackup обновлён).

## 20. Критерии приёмки
