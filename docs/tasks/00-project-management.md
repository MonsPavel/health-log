## 1. Объём и сегментация

115 задач (TASK-001…115) = 8 батчей генерации = 12 спринтов (спринт = 2 недели при 8–10 ч/неделю). Оценки: S ≤1 ч, M 1–2,5 ч, L 2,5–4 ч; суммарно ~210–260 ч → **6 месяцев до RC** при партийном ритме одного разработчика.

Два известных узких места с повышенной неопределённостью: **TASK-022** (SQLCipher-сборка) и **TASK-077** (node-llama-cpp ABI/производительность) — оба в начале своих эпиков сознательно, чтобы риск вскрылся рано. Внешние процессы вне графа задач: **сертификат подписи** (нужен к TASK-104; закупка стартует в спринте 6) и **отбор моделей** для манифеста (к TASK-079; стартует в спринте 7).

## 4. Возможности параллельной разработки

Для одного человека параллелизм = переключение lanes при блокировке/усталости; для двух+ агентов — независимые lanes:

| Lane | Состав (пример) | Относится к |
|---|---|---|
| A «Инфраструктура/качество» | 003, 004, 005, 014, 015, 036, 092, 106 | CI, линтеры, скрипты |
| B «Домен/хранилище» | 006, 016–027, 037, 045, 052–054, 070–072 | main-процесс |
| C «UI» | 013, 028–035, 038–043, 046–049, 055–061, 073, 081, 088, 090, 095 | renderer |
| D «ИИ/сеть» | 075–091, 096 | ai-insight, platform |
| E «Внешние процессы» | закупка сертификата, отбор моделей, юр. проверка формулировок | вне кода |

Правило: lane B не ждёт lane C и наоборот — интерфейс взаимодействия зафиксирован контрактами (`@hl/contracts`).

## 9. Реестр технического долга

Продуктовый уровень — `docs/roadmap/README.md` §TD-1…TD-12 (валиден). Реализационные дополнения (фиксируются здесь по мере появления спецификаций): (а) dev-флаг `fake-LLM` для стабильных e2e — вводится TASK-078, вывод — при стабильных дешёвых прогонах реальной 1B-модели в CI; (б) grep-based проверка i18n-ключей — TASK-013, замена на eslint-plugin-i18next при первых ложных срабатываниях; (в) substring-FTS без русской морфологии — TASK-045, пересмотр при пользовательском спросе на поиск по словоформам.

## 10. Будущая дорожная карта (после RC)

Пост-MVP эпики без изменений относительно SRS 10 §2–3 (напоминания → профили → импорт → теги/лекарства → недельные ИИ-отчёты → EN/macOS/Linux → стандарт шкалы в настройках; далее — FR-12 интеграции, расширение health-log). Синхронизация/облако и «миллионы пользователей» из общих требований качества — за пределами MVP и будут проектироваться отдельными ADR при появлении соответствующего продуктового решения; текущая архитектура не создаёт для них тупиков (контракты, домен и read models переносимы).
