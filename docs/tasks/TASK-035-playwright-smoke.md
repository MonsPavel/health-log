## 2. Цель

E2E-сценарий на Playwright `_electron`: запуск приложения с изолированным temp-userData → ввод измерения через реальную форму → запись видна в истории; перезапуск приложения → запись на месте. База E2E-набора проекта.

## 3. Бизнес-контекст

Критический путь UC-01 под автотестом с первой недели фич — страховка всех последующих рефакторингов формы/списка/хранилища (арх. 10 §1: E2E держим минимальным, но путь «ввёл → вижу» — святым).

## 4. Технический контекст

- **Архитектура:** testing architecture — арх. 10 §1 (E2E-слой); запуск — dev-сборка main (не packaged — быстрое обнаружение; packaged-smoke вручную в TASK-034; CI — TD-6/P7).
- **Пакет:** `apps/desktop/tests/e2e`.
- **Обоснование:** Playwright `_electron.launch` — официальный способ; изоляция через переменную окружения `HL_TEST_USER_DATA=<tmp>` которую контейнер (TASK-027) уважает в тестовом режиме (дополнение к bootstrap: параметр уже есть — пути параметризованы; прокинуть env → контейнер).

## 5. Объём

- **Включено:** playwright.config.ts (проект e2e-electron, testDir tests/e2e, timeout 30 с, workers 1 — Electron-глобальное состояние); helper `launchApp({userData})`: _electron.launch с args main-entry и env HL_TEST_USER_DATA; сценарий `critical-path.spec.ts`: (1) окно появилось, заголовок; (2) открыть форму, ввести 125/82/70 кликами и клавиатурой, Enter; (3) подтверждение отсутствия флаг-диалога (чистые значения); (4) в истории появилась запись «Сегодня 125/82»; (5) закрыть приложение → launchApp снова (тот же tmp-userData) → запись на месте (персистентность+шифрование); скрипт `test:e2e`; фикстура tmp-userData (mkdtemp, очистка после).
- **Не включено:** CI-интеграция (TD-6 → TASK-105), сценарии флагов/диалогов (TASK-043), packaged-запуск.
- **Будущая работа:** трейс-артефакты падений (`trace: on-first-retry`).

## 22. Риски

- HMR/dev-сервер в e2e не используется: запуск собранного main (tsbuild) — сценарий требует предварительной сборки (скрипт pre-шаг в test:e2e).

## 24. Проверка
