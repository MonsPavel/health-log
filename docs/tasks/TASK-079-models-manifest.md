## 2. Цель

Статический JSON-манифест поддерживаемых моделей в ресурсах приложения + zod-схема: `{id, name, version, file, url, sha256, sizeBytes, languages, minRamGb, license, notesKey}`; процедурное требование: отбор моделей (каких включить) — внешний процесс (PM-план, спринт 7), манифест фиксирует форму.

## 3. Бизнес-контекст

FR-5.8: пользователь видит размер/язык/версию ДО загрузки; целостность — sha256 до запуска (защита от подмены/обрыва). Манифест — единственный источник «что можно поставить».

## 4. Технический контекст

- **Архитектура:** реестр — арх. 07 §6.
- **Обоснование:** манифест в комплекте приложения (не сеть): смена списка = обновление приложения — предсказуемо и не требует доверенного канала в рантайме. URL — прямые https на выбранный хостинг (HuggingFace/GHLFS — решение на этапе отбора; манифест хранит абсолютный URL).

## 5. Объём

- **Включено:** `resources/models-manifest.json`: схема zod в contracts (`ModelDescriptor`), 1–2 записи-кандидата (заполнить после отбора; на момент задачи — одна dev-запись с `url: 'PLACEHOLDER'` и пометкой, что реальный отбор — внешний процесс); `listModels(): ModelDescriptor[]` (валидация при загрузке — битый манифест → отказ старта ИИ-модуля с логом, приложение работает); юнит-тесты схемы (валидно/невалидно), тест ресурса.
- **Не включено:** загрузку/обновление манифеста из сети (отклонено §4), зеркала URL (пост-MVP).
- **Будущая работа:** смена списка = релиз приложения; отбор реальных моделей — до TASK-081 приёмки.

## 6. Файлы

- **Создать:** `apps/desktop/resources/models-manifest.json`; `packages/contracts/src/models.ts`; `main/modules/ai-insight/adapters/models-registry.ts` + тесты.

## 7. Модель предметной области

`ModelDescriptor {id, name, version, file (имя в каталоге models), url (https), sha256 (hex64), sizeBytes, languages: ['ru','en'], minRamGb, license, notesKey?}` — notesKey: ключ i18n особой пометки (напр. «требует 16 ГБ RAM»).
