## 2. Цель

Вставка из буфера обмена в поле sys: распознавание паттернов «120/80», «120, 80», «120 80» → заполнение обоих полей; нераспознаваемый мусор («не помню», «1a2») → мягкая ошибка без изменения введённого (EC-18).

## 3. Бизнес-контекст

Пользователи копируют значения из SMS/фото-заметок тонометра; вставка одной строкой экономит 5–8 секунд ввода (пара к US-1). EC-18 SRS: толерантный разбор, не потеря введённого.

## 4. Технический контекст

- **Архитектура:** UX-фича формы — арх. 06 §5.
- **Обоснование:** парсинг на paste-событии поля sys (и dia — симметрично, если вставили в dia одним числом — не трогаем); чистая функция `parseBpPair(text) → {sys, dia} | undefined` — тестируемость без DOM.

## 5. Объём

- **Включено:** `parseBpPair` (regex: `^\s*(\d{2,3})\s*[/,;\-\s]\s*(\d{2,3})\s*$`); интеграция в `MeasurementForm`: onPaste в полях sys/dia — если пара распознана → заполнить оба поля (sys в sys, dia в dia), preventDefault, фокус в pulse; одиночное число ≤3 цифр — штатная вставка в текущее поле; иначе (мусор/2+ числа >3 цифр) — тост-подсказка «Не удалось разобрать вставку — введите вручную», содержимое полей НЕ изменено; тесты парсера (unit) + формы (paste-события).
- **Не включено:** вставку в поле pulse (одиночное число работает штатно), распознавание «SYS 120 DIA 80» словесных форматов.
- **Будущая работа:** распознавание фото тонометра (FR-12.3, future).

## 6. Файлы

- **Создать:** `src-renderer/features/measurement/model/parse-bp-pair.ts` + тест; интеграция в `DigitPad`/`MeasurementForm`.
- **Изменить:** `MeasurementForm.tsx` (paste-обработчики), i18n-ключи.

## 7. Модель предметной области

`parseBpPair(text: string): {sys: number; dia: number} | undefined` — возвращает объект только если ОБА числа в доменных границах (50–300 / 20–200 — константы дублируются из контракта TASK-028 с комментарием-синхронизацией); иначе undefined. Разделители: `/ , ; -` и пробелы.
