## 2. Цель (Objective)

`silentLogger(): HlLogger` — единственная фабрика молчаливого логгера для тестов (`apps/desktop/src/main/shared/logger/silent-logger.ts`); инлайн-литералы вида `{ debug: () => undefined, … }` в тестах заменены на неё. Новые тесты больше не могут скопировать частичный стаб, отваливающийся на отсутствующем методе (класс ошибки TASK-116: `{ info }` без `warn/error` у ScaleServiceLogger).

## 3. Бизнес-контекст (Business Context)

Интеграционные тесты регулярно передают «молчащий» логгер в use case/адаптеры. Каждый файл пишет литерал под минимальную поверхность — при расширении интерфейса логгера (или опечатке) тест падает по типам уже в новой задаче. Полный `HlLogger`-стаб структурно покрывает все утиные логгер-поверхности проекта (ScaleServiceLogger, ExportJsonLogger, депы WorkerPool) — один helper закрывает все случаи.

- **Домены/модули:** shared/logger + 9 тест-файлов с литералами (grep `debug: () => undefined` и т.п.).
- **Пакеты:** apps/desktop.
- **API:** N/A.

- **Обоснование:** альтернатива — по фабрике на каждый узкий интерфейс — плодит сущности ради экономии шести no-op методов; полный HlLogger структурно шире и совместим со всеми потребителями.

## 5. Объём (Scope)

- **Включено:** `silentLogger(): HlLogger` (шесть no-op методов, сигнатуры HlLogger); замена ИНЛАЙНОВЫХ МОЛЧАЛИВЫХ литералов в тестах на `silentLogger()`. Стабы-шпионы и собирающие логгеры (recordingLogger, logger.info = vi.fn) не трогаются — они несут поведенческую нагрузку.
- **Не включено:** смена продуктовых логгеров; выведение silentLogger в отдельный пакет; фиксация вызовов (это spy-задача).
- **Будущая работа:** по мере появления новых логгер-интерфейсов — использовать silentLogger по умолчанию в интеграционных тестах.
