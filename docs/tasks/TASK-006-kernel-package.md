## 2. Цель

Пакет `@hl/kernel` с четырьмя базовыми примитивами — `Result<T>`, `AppError`, `Instant`, `Clock` — полностью покрытый юнит- и property-тестами, без единой внешней зависимости.

## 3. Бизнес-контекст

Всё приложение держится на трёх вещах: ошибки не роняют пользователя (NFR-12), время измерений переживает перелёты и перевод часов (EC-06/07, FR-1.1), вычисления детерминированы в тестах (NFR-10). Kernel — единственный пакет, который зависит «ни от чего», поэтому он первый и самый стабильный код проекта: его контракт почти не будет меняться весь MVP.

## 4. Технический контекст

- **Архитектура:** shared kernel — `docs/architecture/02-domain-model.md` §2; правило «domain не импортирует ничего кроме kernel» — 03 §4.
- **Пакеты:** `packages/kernel` (нулевые зависимости).
- **API:** AppError и Instant станут частью контрактов IPC (TASK-008 сериализует их в AppErrorDto).
- **Обоснование:** свой мини-Result вместо библиотек (neverthrow): 40 строк, нулевая зависимость, полный контроль сериализации. Альтернатива neverthrow: зрелость, но чужая семантика ошибок в контрактах — не оправдана.

## 5. Объём

- **Включено:** контракты и реализация: `Result<T, E = AppError>` (ok/err/isOk/isErr/unwrap-семантика только для тестов — `unsafeUnwrap`), `AppError` (см. §7), фабрики `AppError.of()`, `Instant` (см. §7), порт `Clock` + `SystemClock` + `FixedClock` (тесты), реестр кодов ошибок `ErrorCode` (строковый union, начальный состав: `APP/INTERNAL`, `APP/NOT_IMPLEMENTED`, `VALIDATION/FAILED` — расширяется последующими задачами), константы `AI_MIN_MEASUREMENTS = 7`, `AI_MIN_DAYS = 3` (порог честного отказа FR-5.4 — живёт здесь, чтобы правило существовало в одном месте).
- **Не включено:** доменные типы измерений (TASK-016+), сериализация для IPC (TASK-008), i18n-каталог (тексты — в рендерере).
- **Будущая работа:** TraceId/correlation-поля AppError — при появлении многокомпонентных потоков (P5).

## 7. Модель предметной области

Контракты (спецификация, не реализация):

- `type Result<T, E = AppError> = { ok: true; value: T } | { ok: false; error: E }` — исключения не пересекают границы слоёв (арх. 02 §5).
- `class AppError { code: ErrorCode; messageKey: string; params?: Record<string, string|number>; cause?: unknown; }` + `static of(code, messageKey, params?, cause?)`. Инвариант: `messageKey` — всегда ключ i18n-каталога рендерера (никаких пользовательских текстов в main).
- `type Instant = { utcMs: number; tzOffsetMin: number }` + операции: `wallTime(): {y,m,d,h,min}`, `toIso(): string`, `Instant.fromIso(s): Instant` (roundtrip-инвариант), сравнение `compare(a,b)` по `utcMs` (сортировка — только UTC, настенное время — только для утро/вечер и группировки дней, арх. 04 §2).
- `interface Clock { nowMs(): number; tzOffsetMin(): number }`, `SystemClock` (Date/intl), `FixedClock(ms, tz)` (тесты, детерминизм NFR-10).

## 13. Бизнес-логика

Инварианты Instant: (1) `fromIso(toIso(x))` ≡ x; (2) настенное время вычисляется как UTC + offset, поддержка отрицательных смещений и переходов через полночь; (3) два Instant с разным offset сравнимы по utc. Пограничные случаи из SRS EC-06/07 (перелёт, DST) — обязательные тест-кейсы: измерение 23:58 → 00:03 следующего дня; ±60 минут смещение не меняет настенное время исторической записи.
