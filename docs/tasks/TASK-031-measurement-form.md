## 2. Цель

Экран/модальность ввода: СДА, ДДА, ЧСС, рука, флаг «неровный пульс», заметка, дата-время (по умолчанию «сейчас», правка и заднее число); мгновенная клиентская валидация по zod-схемам contracts; сохранение Enter'ом и большой кнопкой; цель — ввод за ≤15 секунд.

## 3. Бизнес-контекст

Ввод — самое частое действие продукта (US-1/US-4): привычка живёт или умирает на трении (BG-1). Крупные цифровые кнопки — требование персон П1/П3 (NFR-6, цели нажатия ≥44px).

## 4. Технический контекст

- **Архитектура:** форма — арх. 06 §5; состояние — §3; маршрут — `/journal` (вкладка ввода) + глобальный CTA с дашборда.
- **Пакет:** renderer feature `measurement`.
- **Обоснование:** клиентская валидация — та же zod-схема контракта (TASK-028): единая истина; сервер (main) всё равно перепроверяет — UX vs истина разделены.

## 5. Объём

- **Включено:** компонент `MeasurementForm`: поля с крупными цифровыми кнопками (0–9, backspace, очистить) для трёх числовых полей; автофокус в sys; переход sys→dia→pulse по заполнению (3 цифры sys — авто-переход, эвристика: 2–3 цифры достаточно); рука — сегмент-контрол left/right (запоминает последний выбор в zustand-черновике); чекбокс «неровный пульс»; заметка — textarea ≤500 с счётчиком; дата-время: по умолчанию «сейчас» (отображается по Intl, TASK-013-утилита), кнопка «Изменить» → простые поля дата/время (input type=date/time — TD-11 упрощение), выбор прошлого разрешён, будущего — клиентская ошибка; сохранение: Enter и кнопка «Сохранить»; вызов `measurements/add`; состояние сохранения: мгновенное подтверждение-тост «Сохранено» + очистка полей (рука/флаги остаются); ошибки: тост/подсветка полей по zod+серверным ошибкам; zustand-черновик (persist) — объём TASK-039, здесь только базовый store без persist.
- **Не включено:** диалоги флагов (032), persist-черновик (039), smart-paste (040).
- **Будущая работа:** голосовой ввод (future SRS).

## 10. Фронтенд

Состояния: idle → submitting (кнопка disabled + спиннер) → saved (тост, очистка) / error (подсветка). Пустое состояние «первое измерение» — учебная подсказка над формой (FR-9.2). Состояние ошибки сервера (например FUTURE_TIME если часы ушли) — тост с messageKey. Офлайн: N/A — приложение всегда локально (арх. 09 §11).

## 11. API

Потребляет `measurements/add` (TASK-028/029). Ответ: `{measurement, flags}` — флаги прокидываются наверх (родительский экран решает — диалоги TASK-032; контракт props: onSuccess(result)).

## 12. Управление состоянием

`form-store` (zustand): `{sys, dia, pulse, irregular, arm, note, when: 'now'|{date,time}}` + actions; муtация — useMutation; инвалидация списков — onSuccess: `queryClient.invalidateQueries({queryKey:['measurements']})` (событие measurement:changed дублирует — двойная защита, ок).

## 13. Бизнес-логика

Клиентская валидация = zod-схема add (TASK-028): ошибки подсветкой полей, без блокировки ввода. Авто-переход полей: 3 цифры → next (2-значные значения <100 завершаются Enter/кнопкой — не угадываем). Арифметика «сейчас»: takenAt собирается на момент submit (не на момент открытия формы!). Заднее число: datetime-local строка → utcMs через Intl/локальную зону устройства + tzOffsetMin от Date.getTimezoneOffset (инвертированный знак — фиксировать утилитой kernel Instant).
