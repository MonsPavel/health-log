## 2. Цель

Повторный запуск приложения не создаёт второй экземпляр: существующее окно восстанавливается и получает фокус; второй процесс завершается молча.

## 3. Бизнес-контекст

Пограничный случай EC-24 (SRS 07): два экземпляра на одном SQLCipher-файле — повреждение данных и «мистические» ошибки блокировок. Пользователь может запустить ярлык дважды случайно; система обязана это пережить. Задача до TASK-022 (БД), потому что защита должна существовать до того, как появится что защищать.

## 4. Технический контекст

- **Архитектура:** EC-24 `docs/architecture/07-edge-cases.md`; bootstrap — `docs/architecture/01-high-level.md` §1.
- **Пакеты:** `apps/desktop` (main).
- **Обоснование:** штатный `app.requestSingleInstanceLock()` — идемпотентный механизм Electron на user-data-lockfile; альтернативы (свои файловые локи/порты) избыточны и рискованны.

## 5. Объём

- **Включено:** в `bootstrap.ts` до `whenReady`: `const gotLock = app.requestSingleInstanceLock()`; если false → `app.quit()` (без диалога — пользователь увидит фокус существующего окна); обработчик `second-instance` → восстановить окно (restore, если свернуто; show; focus). Событие `second-instance` получает массив argv (будущее: deep-link/open-file — не используется в MVP, комментарий-расширение).
- **Не включено:** передача файлов/ссылок из второго экземпляра (будущая работа), конфликтование userData между dev/prod (решено изоляцией окружений — арх. 09 §6; лок разный автоматически).
- **Будущая работа:** обработка `open-file` на macOS (вне MVP).

## 6. Файлы

- **Создать:** `apps/desktop/src/main/app/single-instance.ts` (функция `ensureSingleInstance(onSecondInstance)` — тестируемая обёртка).
- **Изменить:** `apps/desktop/src/main/app/bootstrap.ts` (вызов до whenReady), `create-window.ts` (экспорт `focusExistingWindow()` — restore/show/focus, используется обработчиком).

## 13. Бизнес-логика

Гонка «два запуска одновременно»: механизм Electron разрешает её атомарно (один получает лок). Поведение при отказе лок-файла (повреждение) — Electron пересоздаёт; приложение не обрабатывает вручную (документировано).

## 19. Стратегия тестирования

Юнит-тест обёртки: мок `app.requestSingleInstanceLock` → false → app.quit вызван; true → not quit; second-instance → focusExistingWindow: spy restore/show/focus в трёх состояниях окна (норм/минимизировано/скрыто). Интеграционная проверка двойного запуска — ручная (см. §24), т.к. поднимает реальный Electron.
