## 2. Цель

Единый perf-отчёт релиза: все цели NFR-4/5 замерены на релизной сборке — старт ≤3 с, график <1 с (bench 062), PDF <30 с (069), экспорт 50k <60 с, ИИ-латентности (первые токены ≤10 с / ответ ≤60 с на референсе B), размер ≤200 МБ; при провалах — точечные оптимизации и повтор; отчёт коммитится.

## 3. Бизнес-контекст

DoD SRS 10 §2: цели производительности подтверждены замерами, не обещаниями. Отчёт — базовая линия всех будущих релизов (регрессия = сравнение с ним).

## 4. Технический контекст

- **Архитектура:** NFR-4/5; benches уже существуют (062/069/036) — задача агрегирует + добавляет замеры старта и экспорта 50k (уникальные здесь).
- **Обоснование:** старт: packaged-запуск → время до первого осмысленного кадра (perf-mark в renderer при маунте App, чтение через e2e-хелпер) — честная метрика пользовательского старта; экспорт 50k: генератор синтетики 062 → CSV-экспорт замер.

## 5. Объём

- **Включено:** замеры: (1) старт packaged ×5 медиана (dev-машина + отмеченная конфигурация); (2) chart-bench прогон; (3) pdf-bench прогон; (4) экспорт 50k CSV — замер канала (генерация 50k, invoke, таймер); (5) ИИ: если dev-модель доступна — 3 генерации резюме (firstToken/total); иначе строка «модель недоступна — замерено ранее в TASK-077 база-линии» (честная фиксация); (6) size-audit; сводный отчёт `docs/release/perf-mvp.md` (таблица цель/факт/вердикт, окружение, методика); при провале: профилировка→оптимизация→повтор (буфер фазы; типовые: старт — ленивые импорты; экспорт — стриминг).
- **Не включено:** оптимизации «на всякий случай» (только по факту провала цели), замеры на слабом железе-стенде (если физически недоступен — замер на dev-машине с пометкой конфигурации; референс B — лучшее усилие).
- **Будущая работа:** стенд референсного железа (пост-MVP, когда появится).

## 6. Файлы
