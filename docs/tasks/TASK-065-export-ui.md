## 2. Цель

Каналы `report/export-csv|export-json` (save-dialog → генерация → запись файла → путь-результат), FileSaver-порт, простая очередь файловых операций (экспорт не пересекается с копией БД), UI: кнопки экспорта в настройках/отчётах с прогрессом и ошибками.

## 3. Бизнес-контекст

US-27: пользователь физически получает файл. Диалог выбора места — всегда (никаких «тихих» записей в известные каталоги — принцип безопасности и предсказуемости, арх. 02 §3.4).

## 4. Технический контекст

- **Архитектура:** порты FileSaver — арх. 02 §3.4; очередь операций — решение дорожной карты (экспорт ↔ копия БД не пересекаются).
- **Модуль:** `reporting` + `main/platform` (FileSaver-адаптер поверх electron dialog/writeFile).
- **Обоснование:** очередь — обычный мьютекс-семафор (promise-цепочка) на файловые операции экспорта/копий; VACUUM INTO и запись CSV не должны бежать параллельно (I/O-шторм и блокировки). Альтернатива (без очереди) — гонки на слабых дисках.

## 5. Объём

- **Включено:** порт `FileSaver {saveCsv/saveJson/savePdf (pdf — TASK-068): (defaultName, bytes|string): Promise<{path}|undefined-отмена>}` + electron-адаптер (dialog.showSaveDialog с фильтрами, writeFile, кодировка utf8); FileOpQueue (serialize: enqueue → await prev → run; ошибки пробрасываются, очередь не ломается); каналы: `report/export-csv {profileId} → {path}|{canceled: true}`, `report/export-json` аналогично; UI: секция «Данные» на экране настроек? РЕШЕНИЕ: кнопки экспорта на экране «Отчёты» (маршрут /reports — станет домом экспорта+PDF+копий) — `ExportButtons` компонент: CSV/JSON, состояние loading (спиннер на кнопке), тост успеха с путём (обрезка до basename + полный title), обработка отмены (тихо), ошибки — тост messageKey; тесты (use case очередь, хендлеры, UI).
- **Не включено:** выбор подмножества данных, автонейминг-настройки (шаблон `health-log-export-YYYYMMDD.csv` — фикс).
- **Будущая работа:** экспорт выбранного периода (post-MVP), «поделиться» (не для десктопа).

## 8. База данных

Чтение через use case'ы 063/064.

## 9. Бэкенд

Очередь: экспорт CSV/JSON и будущие копии (TASK-070) идут через один FileOpQueue (инстанс в контейнере); диалог модален для main (await) — renderer ждёт ответ канала; отмена диалога → canceled (не ошибка).

## 10. Фронтенд

Кнопки disabled во время операции (одновременно один экспорт); путь-результат: тост с basename (полный в title-атрибуте); ошибки диска (нет места/права) → messageKey EXPORT/FAILED + hint «выберите другое место».

## 11. API

`report/export-csv|json` (см. §5); ошибка записи → EXPORT/FAILED; отмена → `{canceled:true}`.

## 12. Управление состоянием

useMutation per-кнопка; invalidate не нужен (нет изменений данных).

## 13. Бизнес-логика

Имя файла по умолчанию: `health-log-export-YYYYMMDD-HHmm.csv|json` (локальное время); перезапись существующего — стандартный диалог ОС спрашивает; очередь: второй вызов во время первого → ждёт (не отклоняется) — семантика serialize; таймаут операций нет (большие экспорты легитимны), но UI показывает занятость.

## 14. Безопасность

Путь файла — результат диалога ОС (не строка от renderer! renderer присылает только тип экспорта — путь выбирает main-диалог); защита от «renderer просит записать в произвольный путь» — архитектурно исключена.

## 15. Производительность

Запись 3 МБ — мгновенно; UI не блокируется (async).

## 16. Доступность

Кнопки с aria-busy при загрузке; тост — role=status; путь в title — не единственный носитель (текст basename полный).

## 17. Интернационализация

Ключи: `export.csv/json`, `export.done` (params basename), `export.failed`, `export.hint`; фильтры диалога — описания на EN идентификаторах + расширения.

## 18. Телеметрия

Лог: `export csv path-basename=… count=… durationMs` (basename может содержать дату — ок; полный путь — только basename, USER-имя в пути!).

## 19. Стратегия тестирования

Очередь: unit — serialize порядок (две задачи → вторая после первой), исключение не ломает очередь, третья задача выполняется; хендлеры: tmp-каталог — файл создан с содержимым use case, отмена диалога (mock) → canceled; UI: клик → loading → тост.

## 20. Критерии приёмки

- [ ] Экспорт CSV из UI: диалог → файл на диске == golden CSV (сверка байт).
- [ ] Отмена диалога → без тоста-ошибки, кнопка разблокирована.
- [ ] Очередь: экспорт во время (мок-долгой) копии — сериализован (unit-тест порядка).
- [ ] Ошибка записи (мок read-only каталог) → тост failed+hint, очередь живая (следующая операция работает).
- [ ] Имя по умолчанию с датой/временем (тест паттерна).
