## 2. Цель

В каждой строке истории — меню действий: «Изменить» (форма открывается с заполненными значениями, сохранение = update) и «Удалить» (подтверждение с текстом «необратимо» → delete); отмена удаления сохраняет запись.

## 3. Бизнес-контекст

US-2/US-8: исправление ошибок и защищённость от случайности — пара «можно исправить / нельзя потерять случайно». Подтверждение удаления — обязательный барьер (FR-2.3).

## 4. Технический контекст

- **Архитектура:** переиспользование формы ввода — арх. 06 §5 (форма — единственный редактор записи).
- **Пакет:** renderer feature `measurement`.
- **Обоснование:** форма с режимом `edit(existingDto)` вместо отдельного экрана правки: одна точка валидации/UX; режим управляется store-полем `editingId`.

## 5. Объём

- **Включено:** меню-кнопка в `MeasurementRow` (⋮): «Изменить», «Удалить»; форма в режиме edit: заголовок «Изменение записи», заполнение полей из DTO (включая дату-время — настенное), submit → `measurements/update`, флаги обновления (typo/critical) → тот же ConfirmFlagsDialog-поток (TASK-032) с текстами «правка применена»; Esc/«Отмена» → возврат к режиму add без изменений; удаление: Radix AlertDialog «Удалить запись от {дата} {время}? Действие необратимо» → «Удалить»/«Отмена» → `measurements/delete` → invalidate; after-delete: тост «Удалено» + опция «Отменить»? НЕТ — отмена = закрыть диалог (данных уже нет); «отмена сохраняет запись» из US-8 = отказ ДО подтверждения. Мутации useMutation update/delete; тесты.
- **Не включено:** массовое удаление (TASK-073 wipe — другое), drag-правки, бейджи флагов (TASK-042).
- **Будущая работа:** undo-тост с восстановлением из памяти (5 с) — отклонено: конфликт с «необратимо» семантикой; не делаем.

## 10. Фронтенд

Режим формы: `form-store.startEdit(dto)` заполняет поля (включая when: настенная дата/время из Instant-полей), `cancelEdit()` очищает к дефолтам; заголовок формы меняется (ключ `form.editTitle`); подтверждение флагов при edit: текст «правка применена» — тот же диалог, кнопка «Оставить» = принять правку, «Удалить и исправить» — НЕТ в режиме edit (возврат к исходной = restore из DTO: повторный update со старыми значениями — НЕТ, упрощаем: в режиме edit диалог только «Понятно» + бейджи; решение зафиксировано: criticalValue при edit показывает ту же панель срочности, typo-подсказка показывает «Оставить»-only).

## 11. API

`measurements/update`, `measurements/delete` (готовы).

## 12. Управление состоянием

## 13. Бизнес-логика

Пограничные: правка удалённой записи (конфликт: другой путь удалил? один UI — но репо вернёт NOT_FOUND) → тост «Запись уже удалена», форма сбрасывается; удаление последней записи дня → пустая группа дня исчезает (группировка renderer сама); delete при открытой форме edit той же записи — тост NOT_FOUND-обработка.

## 20. Критерии приёмки

- [ ] «Изменить» → форма с значениями записи; изменение 125→127 → в истории 127; дата правки видна (updated порядок не меняется).
- [ ] Отмена правки (Esc) — запись неизменна.
- [ ] «Удалить» → диалог «необратимо» с датой записи; «Отмена» — запись на месте; «Удалить» — запись исчезла из списка без перезагрузки.
- [ ] Будущее время при правке → тост FUTURE_TIME, форма остаётся открытой со значениями.
- [ ] Фокус возвращается в строку списка после любого действия; axe критических нарушений нет.
