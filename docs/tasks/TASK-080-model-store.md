## 2. Цель

`ModelStore`: загрузка модели через EgressGateway (`models.download`) — проверка свободного места, докачка после обрыва (HTTP Range), sha256-верификация, атомарное переименование в `userData/models/`; прогресс-события `ai:progress`; пауза/возобновление пользователем.

## 3. Бизнес-контекст

FR-5.8 + EC-15: 2–3 ГБ без докачки и проверки = предательство доверия; обрыв Wi-Fi — норма жизни. Атомарность: недокачанный файл никогда не притворяется готовым.

## 4. Технический контекст

- **Архитектура:** жизненный цикл моделей — арх. 07 §6; сеть — только gateway (08 §5).
- **Модуль:** `ai-insight/adapters/model-store`.
- **Обоснование:** файлы: `<models>/<file>.part` (докачка) → проверка хеша → rename в `<file>` (атомарно на той же ФС). Retry-политика: 3 автоматических ретрая с бэкоффом (1/5/25 с) на сетевые ошибки, затем состояние paused — пользователь продолжает вручную.

## 5. Объём

- **Включено:** `ModelStore`: `download(modelId): Promise<Result>` — flow: модель в манифесте? место на диске (sizeBytes + 100 МБ запас, иначе `AI/DISK_FULL`) → HEAD запрос (поддержка Range? если нет — грузим целиком, докачка невозможна — отмечаем в состоянии) → цикл Range-запросов через gateway → append в .part (fs appendFile) → прогресс-события (throttle 250 мс) → sha256 потоково → mismatch → удалить .part, `AI/HASH_MISMATCH` → rename → `downloaded`-статус; `pause()/resume()` (пользователь: пауза — закрыть соединение, состояние paused c bytesLoaded); `status(modelId)`, `listInstalled()`; persist состояния докачки (bytesLoaded) в prefs? РЕШЕНИЕ: .part-файл сам — состояние (размер файла = скачано), плюс meta-json рядом `{modelId, sha256, total}`; тесты на локальном http-сервере фикстур.
- **Не включено:** несколько одновременных загрузок (одна — решение UI 081 тоже предполагает), mirror-фоллбеки.
- **Будущая работа:** дельта-обновления моделей — не планируется.

## 6. Файлы

- **Создать:** `ai-insight/adapters/model-store.ts` + интеграционные тесты (локальный node-http сервер: обрывы/Range/mismatch-фикстуры); contracts `ai/models` (статусы: `not_installed|downloading|paused|installed|verifying|error`).

## 7. Модель предметной области

Состояния загрузки (§5) — машина: not_installed→downloading⇄paused→verifying→installed; error — терминальное с reset-возможностью.

## 13. Бизнес-логика

Кейсы EC-15: обрыв → retry×3 → paused; resume → Range с bytesLoaded; сервер без Range (HEAD-проверка) → полный рестарт загрузки с предупреждением в состоянии; mismatch после полной загрузки → удалить .part (не хламим диск); место: до старта и перед финальным rename.

## 14. Безопасность

Только через gateway (согласие modelsDownload — UI 081 запрашивает); sha256 обязателен; файлы только в models/каталоге (path traversal: file из манифеста — валидация имени regex `[a-z0-9.-]+`).

## 15. Производительность

Прогресс-события throttle 250 мс (не флуд в IPC); скорость — по сети, пул не участвует.

## 18. Телеметрия

Журнал gateway (байты) + лог: `model download state=… bytes=…`.

## 19. Стратегия тестирования

Локальный http-сервер тестов: полный happy; обрыв (сервер рвёт соединение после N байт) → retry → докачка Range (сервер логирует Range-заголовок); сервер без Range-поддержки → полный путь; mismatch (фикстура-файл с другим хешем в манифесте-моке) → удаление .part; пауза/резюм; DISK_FULL (мок fs-статс).

## 20. Критерии приёмки

- [ ] Happy: загрузка → installed, sha256 совпадает, файл атомарно появился (нет .part).
- [ ] Обрыв+resume: сервер получил Range с offset — докачка без рестарта (тест-лог сервера).
- [ ] Мismatch → .part удалена, статус error c RESET-возможностью.
- [ ] Недостаток места → AI/DISK_FULL до начала.
- [ ] Прогресс-события ≤4/сек (throttle-тест).
- [ ] Перезапуск приложения с недокачанным .part → статус paused, resume работает.
