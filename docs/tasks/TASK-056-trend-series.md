## 2. Цель

Серии точек для графика: сырые точки (время, sys, dia, pulse, флаги, различение утро/вечер) с автоматической агрегацией день = среднее + диапазон при >500 точках; порог и форма — в контракте.

## 3. Бизнес-контекст

График «всё время» на 15k записей должен остаться читаемым (FR-3.5) и быстрым (NFR-4): «ёж в тумане» бесполезен. Переключение «сырые ↔ дни» — поведение read model, а не забота UI.

## 4. Технический контекст

- **Архитектура:** read path — арх. 05 §5; читаемость — FR-3.5.
- **Модуль:** `analytics/application`.
- **Обоснование:** порог 500 — из арх. 06 §8/дорожной карты; агрегат = среднее+min+max на настенный день (согласовано с TASK-046-семантикой дней); различение утро/вечер сохраняется в агрегате (два средних на день? РЕШЕНИЕ: в агрегированном виде различение утро/вечер упрощается до двух маркеров — dayPoint содержит morningAvg и eveningAvg раздельно, если есть).

## 5. Объём

- **Включено:** `TrendSeries` read model: `getTrendSeries(profileId, period): TrendResponse`; `TrendResponse {mode: 'raw'|'daily', points?: RawPoint[], days?: DayPoint[]}`; `RawPoint {utcMs, tzOffsetMin, sys, dia, pulse?, part: 'morning'|'evening'|'other', critical?: 'high'|'low'}`; `DayPoint {wallDate, sysAvg, sysMin, sysMax, diaAvg, diaMin, diaMax, morningSysAvg?, eveningSysAvg?, count}`; порог `RAW_POINTS_LIMIT = 500` (константа контекста); канал `trend/series` (контракт + хендлер, период-тип переиспользуется из TASK-054); тесты: порог (499/501), агрегация, время на 10k (совместно с TASK-062).
- **Не включено:** сглаживание скользящим средним (US-12, Could — отдельным переключателем пост-MVP поверх raw-режима).
- **Будущая работа:** zoom/brush интерактив (пост-MVP).

## 7. Модель предметной области

Порог считается по количеству записей в периоде; при >500 — daily-режим. part точки: day-part правило TASK-052 (константы общие — импорт из domain/stats). critical — политика TASK-020 (server-computed, согласовано с TASK-042).

## 8. База данных

Чтение через порт listByPeriod (без изменений).

## 9. Бэкенд

Чистая сборка над точками; детерминизм: сортировка по utc asc (график слева-направо), tie-break id.

## 10. Фронтенд

N/A (TASK-057).

## 11. API

`trend/series {profileId, period} → TrendResponse`; пустой период → `{mode:'raw', points: []}`; ошибки STORAGE/*.

## 12. Управление состоянием

Ключ `['trend', profileId, period]`; инвалидация `measurement:changed`.

## 13. Бизнес-логика

Границы порога: ровно 500 → raw; 501 → daily (тест-пара). DayPoint: настенный день точки (wallTime); день с одной записью — avg=min=max; morningSysAvg только при наличии утренних в дне. daily-ответ сортирован по wallDate asc.

## 14. Безопасность

N/A.

## 15. Производительность

10k точек: сборка ≤200 мс (тест-ориентир; рендер — TASK-062); payload daily-режима на 10 лет (~3650 дней) — компактный.

## 16. Доступность

N/A (точки сопровождаются таблицей-альтернативой TASK-059, данные те же).

## 17. Интернационализация

wallDate — ISO-строка; локализует UI.

## 18. Телеметрия

Лог: `trend/series period=… mode=raw points=N durationMs=…`.

## 19. Стратегия тестирования

Юнит+интеграция: порог-пара (499/501); агрегация фикстуры (3 точки в день: avg/min/max + части); сортировки; пустой период; критический-флаг прокинут; 10k генератор → daily ≤200 мс.

## 20. Критерии приёмки

- [ ] 499 точек → raw; 501 → daily (тест-пара на генераторе).
- [ ] DayPoint: avg/min/max верны на фикстуре 3 точек; morning/evening раздельны при наличии.
- [ ] Сырые точки содержат part и critical (сквозной тест с 190/125).
- [ ] Сортировка asc стабильна (tie-break id) — тест.
- [ ] Пустой период → `{mode:'raw', points:[]}`.
