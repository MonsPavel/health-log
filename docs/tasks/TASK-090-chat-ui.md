## 2. Цель

Вкладка «Чат» (/ai): лента истории (роли визуально различны), поле ввода вопроса (Enter = отправить), стрим ответа в ленту, отказ-ответы стилем «системного сообщения», выбор периода (как в разборе — общий контекст), кнопка «Очистить чат» с подтверждением, BUSY-состояние, дисклеймер-футер.

## 3. Бизнес-контекст

US-19: диалог своими словами — второй режим ИИ. Отказы визуально отделены (пользователь понимает: «система отказалась», а не «ошибка»). Период-переключатель общий с разбором — единая ментальная модель «о чём спрашиваю».

## 4. Технический контекст

- **Архитектура:** арх. 06 feature ai; каналы 089.
- **Обоснование:** лента без виртуализации (глубина 6+новые — маленькая); скролл-якорь вниз при новых сообщениях.

## 5. Объём

- **Включено:** `ChatScreen`: инициализация `ai/chat/list`; лента сообщений (user — справа акцент, assistant — слева нейтрал, refusal — серый с info-иконкой); поле ввода (textarea 1–3 строки, Enter=отправить, Shift+Enter=перенос, кнопка «Отправить»); во время генерации: ввод disabled + «Стоп»; выбор периода (компонент периода 057-паттерн, локальный state, дефолт 30d); «Очистить чат» — confirm-диалог («История будет удалена необратимо») → clear; дисклеймер-футер несъёмный; BUSY-тост «Дождитесь завершения текущей генерации»; модель не настроена → CTA-карточка (как 088); empty-state истории: подсказки-примеры вопросов (3 кликабельных чипа: «Как менялось давление?», «Чем отличаются утро и вечер?», «Были ли необычные значения?» — вставка в поле); тесты; e2e fake.
- **Не включено:** markdown-рендер, ссылки на записи, аватары/анимации.
- **Будущая работа:** ссылки на записи в ответах (post-MVP).

## 10. Фронтенд

Стрим в «виртуальном» assistant-бабле (append deltas); финал — замена на сохранённое сообщение (invalidate); ввод disabled при генерации (BUSY-превенция UI+сервер двойная).

## 11. API

`ai/chat/send|result|list|clear`; события ai:token/status.

## 12. Управление состоянием

Ключ `['chat', pid]`; оптимистичный user-бабл (отображается сразу, финал подтверждает — при ошибке удаления из ленты); период — локальный state.

## 13. Бизнес-логика

Кейсы: пустой вопрос → кнопка disabled; генерация → ввод заблокирован; отказ-бабл — стиль; очистка — подтверждение, лента пустеет, empty-state с чипами; BUSY — тост (двойная защита с disabled).

## 19. Стратегия тестирования

Тесты: отправка (Enter+кнопка) — invoke с периодом; стрим-бабл аппендится; refusal-стиль по refusal_class; чипы вставляют текст в поле (не отправляют); очистка: confirm-отмена/подтверждение; BUSY-тост; disabled-состояния; a11y-атрибуты.

## 20. Критерии приёмки

- [ ] Отправка вопроса → user-бабл сразу, стрим ответа, финал — оба сохранены (перезагрузка — история на месте).
- [ ] «Какие таблетки…» → серый отказ-бабл с дисклеймером (e2e fake — AC-5.1).
- [ ] Enter отправляет, Shift+Enter переносит.
- [ ] «Очистить чат»: отмена — история цела; подтверждение — empty-state с чипами.
- [ ] Генерация → ввод disabled + «Стоп» работает.
- [ ] BUSY (генерация резюме в другой вкладке — e2e-эмуляция) → тост.
- [ ] role=log/aria — тест атрибутов; axe чисто.
