## 2. Цель

Пакет `@hl/scales-data`: машиночитаемая офисная шкала ESC/ESH 2018 (таблица 4.1 SRS) с версией, источником и обязательными примечаниями (домашние пороги ≥135/85 ↔ офисные ≥140/90; неприменимость особым группам), валидируемая zod-схемой.

## 3. Бизнес-контекст

Шкалы — справочные данные, которые меняются с клиническими рекомендациями (R-10): хранить их версионируемыми данными с указанием источника (FR-4.5), а не зашивать в код классификатора. Это же требование честности: пользователь видит, откуда пороги.

## 4. Технический контекст

- **Обоснование:** JSON-данные + типы, а не TS-объекты в коде классификатора — обновление шкалы = правка данных, не логики; расхождение стандартов ESC/ESH vs AHA — OQ-6, дефолт ESC/ESH зафиксирован в SRS.

## 5. Объём

- **Включено:** файл данных `scales/bp-office-esc2018.json`: `{code: 'bp_office_esc2018', version: '1.0.0', sourceLabel: 'ESC/ESH 2018', language: 'ru', categories: [...], homeNote, specialGroupsNote}` — категории таблицы 4.1 (§7); zod-схема ScaleData + тесты: валидация данных, непрерывность/непересечение порогов, экспорт типизированного константа `BP_OFFICE_ESC2018`; комментарий-примечание «верифицировать по первоисточнику перед публичным релизом» (OQ-6).

- **Будущая работа:** AHA 2017 вариант (настройка стандарта — пост-MVP OQ-6), шкалы для будущих показателей health-log.

## 7. Модель предметной области

Данные шкалы (контракт):

```
categories (порядок = от оптимальной к тяжёлой):
1 {code:'optimal',       label:'Оптимальное',        sysMin:null, sysMax:119, diaMin:null, diaMax:79}
2 {code:'normal',        label:'Нормальное',          sysMin:120,  sysMax:139, diaMin:80,   diaMax:89}   ← «и/или»-семантика
3 {code:'high_normal',   label:'Высокое нормальное',  sysMin:130,  sysMax:159, diaMin:85,   diaMax:99}
4 {code:'hypertension1', label:'АГ 1 степени',        sysMin:140,  sysMax:159, diaMin:90,   diaMax:99}
5 {code:'hypertension2', label:'АГ 2 степени',        sysMin:160,  sysMax:179, diaMin:100,  diaMax:109}
6 {code:'hypertension3', label:'АГ 3 степени',        sysMin:180,  sysMax:null, diaMin:110, diaMax:null}
```

⚠️ Уточнение семантики против «и/или»: корректная машина классификации (TASK-053) использует ПОРОГИ ГРАНИЦ каждой категории по каждому измерению отдельно, правило «категория = худшая из двух». Поэтому данные хранятся как пары границ: `sysRange: [min,max]`, `diaRange: [min,max]` для каждой категории (включительно), а JSON-выше — презентационная выдержка. Итоговая форма данных: `categories: [{code, label, sysRange:{min,max}, diaRange:{min,max}}]` + `homeBPNote` («среднее домашнее АД ≥135/85 соответствует офисному ≥140/90») + `specialGroupsNote` («пороги не применимы при беременности, у детей и подростков, при некоторых заболеваниях — обсудите с врачом»). Точный JSON-скелет фиксируется в schema.ts (zod) этого пакета.
