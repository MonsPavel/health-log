## 2. Цель

Переключатель «Простой режим» (по умолчанию ВКЛ): продвинутые настройки скрыты; П2-пользователь отключает и получает всё. Механизм — минимальный типизированный реестр флагов (арх. 09 §4) поверх prefs.

## 3. Бизнес-контекст

FR-9.3: «отсрочка сложности» — П1/П3 не должны видеть выключатели, смысл которых не понимают; П2 не должен бороться за доступ к глубине. Один флаг обслуживает обе персоны. Позиция: после настроек (047) — это первое применение prefs.

## 4. Технический контекст

- **Архитектура:** FeatureFlagService — арх. 09 §4 (defaults в коде, overrides — в prefs на MVP; удалённое управление отклонено навсегда — сеть).
- **Обоснование:** отдельный сервис флагов (а не просто поле prefs): единая точка чтения, типизированный реестр (`FlagName = 'advancedMode' | 'reports.aiSection' | 'ai.chat' …` — реестр пополняют будущие фичи), готовность к dev-override файлу (позже). MVP-реализация: флаг = поле prefs с дефолтом; сервис — типизированная обёртка.

## 5. Объём

- **Включено:** `FlagsService` (renderer-side hook `useFlags()` + main-side опционально позже): реестр `FLAGS: Record<FlagName, {default: boolean; labelKey}>`; флаг `advancedMode` (default **false** = простой режим); скрытие в UI: раздел настроек «Продвинутые» (формат даты, будущие: выбор модели ИИ, бета-канал) виден только при advancedMode=true; переключатель «Простой режим» в основных настройках; продвинутый экран не теряет данные при скрытии (prefs сохраняются); тесты.
- **Не включено:** скрытие навигации целиком (разделы журналов/ИИ не прячутся — прячутся только advanced-опции внутри экранов; решение: навигация стабильна — предсказуемость для П3), remote-flags (никогда — TD-стиль арх. 09 §4).
- **Будущая работа:** флаги `reports.aiSection`, `ai.chat` — появятся в P4/P5 в этом же реестре.

## 6. Файлы

- **Создать:** `src-renderer/lib/flags.ts` (реестр+хук), секция настроек, тесты; ключи i18n.
- **Изменить:** `SettingsScreen.tsx` (переключатель + условная секция), prefs-схема TASK-047 (поле advancedMode уже в DEFAULT_PREFS — confirm; если нет — аддитивное расширение схемы).

## 7. Модель предметной области

`FlagName` union; `useFlags(): Record<FlagName, boolean>`; `useSetFlag(name, value)` — пишет в prefs (advancedMode ↔ prefs.advancedMode — маппинг 1:1 в MVP, реестр — будущая надстройка; документируется).

## 19. Стратегия тестирования

Тесты: дефолт (чистые prefs) → продвинутая секция отсутствует в DOM; включить → секция есть, формат даты виден; выключить → секции нет, значение формата сохранилось (перезапуск → prefs хранит); реестр флагов: добавление нового флага не ломает существующих (тип-тест).

## 20. Критерии приёмки

- [ ] Чистый запуск: продвинутая секция отсутствует (DOM-тест).

- [ ] Перезапуск после включения — режим сохранён.
- [ ] Реестр типизирован: неизвестный флаг = ошибка компиляции (type-тест).
