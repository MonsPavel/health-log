## 2. Цель

Панель фильтров над историей: пресеты периода (7д/30д/90д/всё), фильтр руки (все/левая/правая), фильтр «есть заметка»; состояние фильтров — в URL query; активный фильтр меняет запрос list.

## 3. Бизнес-контекст

US-7 (просмотр с фильтром по периоду) — базовая навигация при тысячах записей; врач спрашивает «последние 30 дней». URL-состояние: фильтр не теряется при перезапуске/навигации, ссылку можно вернуть (арх. 06 §4).

## 4. Технический контекст

- **Архитектура:** фильтры уже в контракте list (TASK-028: fromUtcMs/toUtcMs/arm/hasNote) и порте — здесь только UI-слой + вычисление границ периодов.
- **Пакет:** renderer feature `measurement`.
- **Обоснование:** пресеты вычисляются от «сейчас» (устройства) в момент применения фильтра — не хранятся абсолютными датами (пересчёт при каждом использовании — ожидаемое поведение «последние 7 дней»).

## 5. Объём

- **Включено:** `HistoryFilters` компонент: сегмент-контрол периода (7д/30д/90д/всё/произвольный-заглушка до TASK-046), select руки, чекбокс «только с заметками»; URL-синхронизация: `?period=30d&arm=left&noted=1` (useSearchParams); хук `useMeasurementFilters()` → `MeasurementQuery`-фрагмент (fromUtcMs = now − N*24h при пресете; toUtcMs = ∞); подключение к useMeasurements (ключ кэша включает фильтры); сброс фильтров кнопкой (URL в дефолт: period=30d); тесты.
- **Не включено:** произвольный диапазон (TASK-046), фильтр по пульсу/флагам (post-MVP), сохранение фильтров между сессиями (URL достаточно).
- **Будущая работа:** «всё» с 50k записей — пагинация уже есть; агрегат-флаг (post-MVP).

## 6. Файлы

- **Создать:** `src-renderer/features/measurement/ui/{HistoryFilters.tsx}`, `model/filters.ts` (парсер/сериализатор URL↔Query + пресеты), тесты.
- **Изменить:** `HistoryScreen.tsx` (панель + хук), `use-measurements.ts` (параметры в ключе).

## 7. Модель предметной области

`HistoryFilterState = {period: '7d'|'30d'|'90d'|'all'|'custom', arm?: 'left'|'right', noted?: boolean}`; `toQuery(state, nowUtcMs): {fromUtcMs?, toUtcMs?, arm?, hasNote?}` — чистая функция (тестируемость); парсер URL → state с валидацией (мусор в URL → дефолт).

## 10. Фронтенд

Инвалидация: смена фильтра → новый ключ кэша → fetch; предыдущий результат остаётся в кэше (быстрый возврат); счётчик «N из M» обновляется. Пустой результат при активных фильтрах — пустое состояние с предложением сбросить фильтры (не «вообще нет данных»).

## 11. API

Потребляет `measurements/list` с фильтрами (готово).

## 12. Управление состоянием

URL = источник истины фильтров (сериализуемо, шаро-пригодно внутри машины); кэш-ключ включает сериализованный query — разные фильтры не конфликтуют.

## 13. Бизнес-логика

Границы пресета: fromUtcMs = `nowUtcMs − 7*86400000` включительно (порт: включительные границы — TASK-021); «всё» → from undefined; пограничный: запись ровно на границе 7 дней — включена. nowUtcMs берётся на момент применения (клик), не на каждый рендер.

## 14. Безопасность

Мусор URL (`?period=<script>`) → валидация парсера → дефолт (никаких dangerouslySetInnerHTML).

## 15. Производительность

Смена фильтра — мгновенная (индекс + лимит 200); префетч соседних пресетов — не нужен.

## 16. Доступность

Сегмент-контрол: role="radiogroup"/radio или кнопки с aria-pressed; labels у select/checkbox; клавиатура полностью; фокус не сбрасывается при смене фильтра (список обновляется, фокус на панели фильтров остаётся).

## 17. Интернационализация

Ключи: `filters.period.7d/30d/90d/all/custom`, `filters.arm.any/left/right`, `filters.noted`, `filters.reset`, `history.empty.filtered` («С фильтрами ничего не найдено — сбросьте фильтры»).
