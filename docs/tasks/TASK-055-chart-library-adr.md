## 2. Цель

Сравнить 2–3 кандидата (visx, Recharts, ECharts — фикс. список из дорожной карты) прототипами тренда СДА/ДДА на реальных требованиях (арх. 06 §8), выбрать и зафиксировать решение в ADR `docs/architecture/adr/0003-chart-library.md`.

## 3. Бизнес-контекст

График — главный экран понимания динамики (US-10); замена библиотеки после написания экранов = переписывание UI-слоя аналитики. Час спайка экономит недели. Решение принимается по требованиям, не по вкусу.

## 4. Технический контекст

- **Архитектура:** требования к графику — `docs/architecture/06-frontend.md` §8; решение — в юрисдикции ADR (решения фиксируются, арх. README).
- **Обоснование кандидатов:** visx (низкоуровневый, полный контроль, «собери сам»), Recharts (декларативный React, быстрая скорость старта, хуже с кастомными опорными линиями/агрегацией), ECharts (мощный, тяжёлый ~300КБ+, canvas — экранридеру хуже, но производительность на больших данных).

## 5. Объём

- **Включено:** прототип-тренд на каждом кандидате (временные файлы в `tools/spikes/chart-*/`, не в src): линии СДА/ДДА по 500 точкам, опорная линия 140 с подписью источника, различение утро/вечер (форма точки), тултип, переключение агрегации день=avg+range (500→30 точек); замеры: bundle-size (gzip), время рендера 500/5000 точек, LOC прототипа; чек-лист критериев (§13) с оценкой каждой; ADR-0003: решение, альтернативы, компромиссы, последствия; удаление прототипов.
- **Не включено:** интеграцию победителя (TASK-057), пульс-график (058).
- **Будущая работа:** пересмотр ADR при новых требованиях (например, экспорт графика в PDF — TASK-067 учтёт решение: PNG-снимок через canvas/SVG-сериализацию — вопрос в чек-листе).
