## 2. Цель

Финальный эшелон: `ResponseGuard.check(answer, ctx) → {action: 'pass'|'replace', text}` — эвристики запрещённых паттернов в ОТВЕТЕ модели (рекомендации препаратов/доз, «диагноз:», «прекратите приём»); срабатывание → замена на отказ-шаблон + лог-событие; fail-safe: сомнение = замена.

## 3. Бизнес-контекст

Промпт — мягкий контроль; релизный гейт AC-5.1 требует гарантий на каждой модели (R-12): пост-фильтр ловит нарушения, проскочившие промпт. Замена на безопасный отказ (а не молчание/обрезка) — предсказуемое поведение.

## 4. Технический контекст

- **Архитектура:** эшелон 3 — арх. 07 §4; fail-safe решение.
- **Обоснование:** паттерны на ОТВЕТ (не на вопрос — вопрос классифицирует префильтр 086); RU-фокус + числовые паттерны доз (`\d+\s?(мг|мл|таблет)` в рекомендательном контексте); различение: «врач назначил 5 мг» (описание факта из заметок — ПАСС при условии отсутствия императива) vs «принимайте 5 мг» (замена) — эвристика императивов рядом с дозой.

## 5. Объём

- **Включено:** `ResponseGuard`: правила (данные, не if-лес): `Rule {id, pattern (RegExp), action: 'replace', refusalClass, noteKey}`; стартовый состав правил: (R1) императивы приёма+препарат: `(принимай\w*|пейте|пей|начните принимать|увеличьте дозу|уменьшите дозу|отмените|прекратите прием)`; (R2) конкретная доза+единица: `\d+([\.,]\d+)?\s?(мг|мл|мкг|таблетк)`; (R3) «диагноз: <что-либо>`/«у вас <название-болезни>» форматы; (R4) «вам нужно лекарств…`; логика: R1 ∪ (R2∧императив-контекст в предложении) → replace; R3 → replace; иначе pass; замена — отказ-шаблон класса (086 шаблоны — интерфейс-зависимость: принимает фабрику шаблонов параметром, чтобы не циклиться); лог события `guardrail.replace {ruleId, refusalClass}` (без текста — PHI); дисклеймер-добавление: к пропущенному ответу obligations не добавляются здесь (добавляет 087 при сборке — разделение); тесты-фикстуры «красных ответов» (тексты, которые реальные модели генерируют — 10–15 фикстур) — все заменяются; «безопасные ответы» (10+) — проходят.
- **Не включено:** семантический анализ/классификатор на модели-судье (пост-MVP, если эвристик станет мало), редактирование текста (только полная замена).
- **Будущая работа:** процесс пополнения правил: находка eval → правило+фикстура (комментарий).

## 13. Бизнес-логика

Императив-контекст: R2-доза срабатывает, если в том же предложении есть императив R1-паттерна ИЛИ «рекомендую|стоит принять|назначьте себе»; упоминание дозы в пересказе заметок пользователя («вы отметили приём 5 мг») → pass (тест-кейс!). Отказ-текст — фабрикой (единый тон).

## 14. Безопасность

Fail-safe: regex-катастрофа (timeout) → replace (не pass) — обёртка try; правило «сомнение = замена» в комментарии.

## 15. Производительность

Регексы на ответ ≤2 КБ — микросекунды; вызов раз на генерацию.

## 19. Стратегия тестирования

Фикстуры unsafe (12–15 реалистичных: «Рекомендую принимать Эналаприл 10 мг…», «Диагноз: гипертоническая болезнь…», «Прекратите приём…») → все replace с ожидаемым классом; safe (12+: описание данных, «обсудите с врачом», пересказ заметок с дозой) → pass; граница «вы отмечали 5 мг» — pass; «принимайте 5 мг» — replace.
