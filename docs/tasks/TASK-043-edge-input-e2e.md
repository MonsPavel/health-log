## 2. Цель

Автоматизированные E2E-сценарии: EC-01 (sys≤dia — блокировка с понятным текстом), EC-03 (185/115 → подтверждение + панель), EC-04 (дубль → подсказка, сохранение по выбору), AC-1.4 (258 при медиане 128 → подсказка опечатки); CRUD-цикл из TASK-038.

## 3. Бизнес-контекст

Барьеры качества данных — поведение, которое регрессирует тихо (любой рефакторинг формы/диалогов). SRS AC-1.2/1.3/1.4 обязаны быть защищены автоматикой, а не ручной памятью.

## 4. Технический контекст

- **Архитектура:** E2E-слой — арх. 10 §1; helpers из TASK-035 (`launchApp`, tmp-userData).
- **Обоснование:** E2E, не юнит-тесты: проверяется сквозной UX-поток (ввод → диалог → решение → список), который юнитами не покрывается.

## 5. Объём

- **Включено:** `edge-inputs.spec.ts` с 6 сценариями: (1) EC-01: 125→130 в dia (sys<dia) → ошибка формы, сохранение недоступно, значения не потеряны; (2) EC-03: 185/115 → диалог «Проверьте значения» → «Сохранить» → панель срочности видна; «Исправить» → форма со значениями; (3) сохранение 190/125 → панель FR-7.4 с «103»; (4) дубль: та же запись дважды за <2 мин → диалог дубля → «Оставить» — обе записи в списке; (5) typo: фикстура-история (seed через IPC-вызовы 14 дней 128/82) → ввод 169/82 → подсказка с «128» → «Оставить»; (6) CRUD-цикл: создать → изменить 125→127 → удалить → подтверждение → список пуст. Сидинг истории: через `window.hl.invoke('measurements/add', …)` в цикле (быстрее кликов) — допустимо для arrange-фазы.
- **Не включено:** EC-05+ (ночь/таймзоны — юнит-покрытие домена), проверка локалей.
- **Будущая работа:** визуальная регрессия панелей (скриншот-тесты) — при стабильности.
