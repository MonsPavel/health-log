## 2. Цель

Один `tsconfig.base.json` со строгими настройками; каждый пакет наследует его и компилируется; корневой скрипт `typecheck` проверяет все пакеты одной командой.

## 3. Бизнес-контекст

Контракты IPC и доменные инварианты (SRS FR-1.2, FR-5.3) — это типы; их надёжность = типовая строгость. Строгий TS с первого дня дешевле ретрофита строгих флагов на 115 задачах кода. Позиция в P0 верна: любые позже написанные файлы сразу проходят через строгий компилятор.

## 4. Технический контекст

- **Архитектура:** пакеты-слои арх. 03 §3; типы — часть контракта D6 (`docs/architecture/05-api-ipc.md` §1).
- **Пакеты:** все 4 пакета TASK-001.
- **Обоснование:** `moduleResolution: NodeNext` для пакетов (Node-главный процесс, честные ESM/CJS-выпуски) и `bundler` для рендерера (Vite). Альтернатива — единый `bundler` везде: проще, но скрывает несоответствия Node-резолвинга в main-процессе; компромисс — два профиля, зафиксированы в base как два «пресета»-конфига.

## 5. Объём

- **Включено:** `tsconfig.base.json` (строгие флаги); `tsconfig.node.json` (пресет NodeNext для packages + main); `tsconfig.web.json` (пресет bundler для renderer, DOM-lib); per-package tsconfig extends; корневой скрипт `typecheck` = `tsc --build` по всем проектам; сборка пакетов переведена на `tsc` (emit в `dist/`).
- **Не включено:** paths-алиасы между пакетами (импорты — через имена `@hl/*`, разрешаются workspace-зависимостями); конфиг Vite (TASK-007).
- **Будущая работа:** изоляция типов Electron (глобальные d.ts) — с TASK-007.

## 6. Файлы

- **Создать:** `tsconfig.base.json`, `tsconfig.node.json`, `tsconfig.web.json`, `packages/*/tsconfig.json`, `apps/desktop/tsconfig.json` (минимальный, расширяется в TASK-007).
- **Изменить:** `package.json` всех пакетов (scripts build → `tsc -b`, types/exports на `dist`).

## 13. Бизнес-логика

Обязательные флаги `tsconfig.base.json` (полный список, отклонение = ревизия): `strict: true`, `noUncheckedIndexedAccess: true`, `noImplicitOverride: true`, `noFallthroughCasesInSwitch: true`, `noUnusedLocals: true`, `noUnusedParameters: true`, `verbatimModuleSyntax: true`, `isolatedModules: true`, `forceConsistentCasingInFileNames: true`, `skipLibCheck: true` (скорость; типы библиотек не наша ответственность), `exactOptionalPropertyTypes: false` (намеренный долг TD-IMP-1: слишком трение на ранней стадии; пересмотр — после P1).

## 14. Безопасность

Косвенная: строгие типы закрывают целый класс undefined-ошибок на границах IPC. `skipLibCheck` не ослабляет проверки нашего кода.

## 19. Стратегия тестирования

Проверка компиляции = тест: заведомо небезопасный файл-фикстура (доступ к возможно-undefined индексу, неявный any) НЕ компилируется. Фикстура живёт в `tools/tsconfig-fixture/`, не входит в `tsc --build` основного графа, проверяется отдельным скриптом `scripts/check-strict.ts` (запускает tsc на фикстуре, ожидает код ошибки TS). 

## 20. Критерии приёмки

- [ ] `pnpm typecheck` (tsc --build) зелёный на всех пакетах.
- [ ] Фикстура с `noUncheckedIndexedAccess`-нарушением даёт ошибку TS18048/TS2532 при проверке скриптом `check-strict`.
- [ ] `packages/kernel/dist/index.{js,d.ts}` создаётся сборкой; `exports` в package.json указывают на dist.
- [ ] Ни один пакет не переопределяет строгие флаги на «мягкие» (grep-проверка в PR-ревью).

## 24. Проверка

Автоматически: `pnpm typecheck` — exit 0; `pnpm exec tsx scripts/check-strict.ts` — «fixture rejected as expected». Ручная: внести в любой пакет `const x: number | undefined = {}; const y = x.foo;` → `pnpm typecheck` красный. Откат: revert коммита; конфликтов с TASK-001 нет (строго надстройка).
