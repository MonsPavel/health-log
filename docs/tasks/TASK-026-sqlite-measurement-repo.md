## 2. Цель

Реализация порта TASK-021 над better-sqlite3: CRUD + listByPeriod с фильтрами; каждая мутация поднимает `meta.data_version` в той же транзакции; сериализация агрегата ↔ строки таблицы.

## 3. Бизнес-контекст

Атомарность «запись + счётчик версии» — механика бейджа «данные изменились» (FR-5.7) и инвалидации кэшей; её нельзя добавить потом поверх «просто INSERT» без переделки всех мутаций. Отсюда: транзакция в самом адаптере с первого дня.

## 4. Технический контекст

- **Архитектура:** адаптер реализует порт — арх. 02 §5; data_version — 04 §4.
- **Модуль:** `measurement/adapters`.
- **Обоснование:** «сырой» SQL через Drizzle query-builder: типобезопасность без потери прозрачности SQL (фикс. решения: Drizzle ORM). Альтернатива raw-SQL строки: полный контроль, но нет типов; компромисс — Drizzle для таблиц, raw для агрегатов P3.

## 5. Объём

- **Включено:** `SqliteBpMeasurementRepository implements BpMeasurementRepository`: мапперы row↔агрегат (boolean↔0/1, Instant↔2 колонки, pulse null); подготовленные statements; транзакция mutаций (`db.transaction`: INSERT/UPDATE/DELETE + UPDATE meta.data_version=data_version+1); listByPeriod со всеми фильтрами порта (WHERE-сборка через Drizzle, ORDER BY taken_at_utc DESC, id DESC); методы read — без транзакций; интеграционные тесты: тот же контрактный набор TASK-021 + тест транзакции (вставка вызывается с намеренным сбоем после INSERT → ни записи, ни bump).
- **Не включено:** FTS (TASK-045), статистические запросы (TASK-052 — raw SQL рядом).
- **Будущая работа:** пакетные вставки (импорт, post-MVP) — один transaction вокруг N add.

## 6. Файлы

- **Создать:** `apps/desktop/src/main/modules/measurement/adapters/sqlite-measurement-repository.ts` (+ row-mapper), интеграционный тест (tmp-БД: openEncrypted с тестовым ключом → миграция v1 → контрактный набор + транзакционный тест).

## 7. Модель предметной области

Реализация порта из TASK-021 §7 без изменений сигнатур (это и есть проверка совместимости). Row-mapper: `irregular_pulse` 0/1 ↔ boolean; `pulse` NULL ↔ undefined; `note` NULL ↔ undefined; Instant ↔ (taken_at_utc, tz_offset_minutes).

## 8. База данных

Использует v1 (TASK-025) без изменений. Дополнительно здесь: ничего; индекс уже есть.

## 9. Бэкенд

better-sqlite3 синхронный — методы оборачивают в `Promise.resolve` (контракт асинхронный). Ошибки БД (SQLITE_CONSTRAINT и пр.) маппятся: UNIQUE/NOT NULL → `STORAGE/CONSTRAINT` (новый код), остальное → `STORAGE/FAILED` — наружу только коды, детали в лог (TASK-010).

## 12. Управление состоянием

Косвенно: после каждой мутации наружу должен уйти сигнал — событие `data:versionBumped` публикует use case (TASK-029), не адаптер (разделение: адаптер знает про БД, use case — про события). Проверка: в этом файле нет импорта EventBus.

## 13. Бизнес-логика

data_version: read из meta; мутация в транзакции: bump + запись; сбой → полный rollback (тест: «сбой после INSERT» — как имитировать: вызвать adapter.add с агрегатом, у которого намеренно сломана зависимость? Нет — тест делает `db.transaction` обёртку... Проще: тест вызывает внутреннюю функцию mutatе с заранее подменённым вторым statement'ом (инъекция fail-point в конструкторе, только для тестов, параметр `failAfterFirstStatementForTesting`). Принять этот механизм, задокументировать. delete несуществующего → NOT_FOUND (проверка changes=0 после DELETE). update несуществующего → NOT_FOUND.

## 14. Безопасность

Параметризованные запросы только (Drizzle — по умолчанию; запрет string-конкатенации SQL — линт-правило ревью); profileId в каждом запросе — обязателен (порт, TASK-021 §14).

## 15. Производительность

Prepared statements кэшируются в конструкторе (better-sqlite3 требование); batch-вставка 1000 записей в одной транзакции ≤1 с (базовая линия ADR-0002); listByPeriod на 10k записей ≤100 мс (тест-ориентир; полный NFR-9 — TASK-111).

## 19. Стратегия тестирования

Интеграционный: tmp-БД (openEncrypted с фиксированным тестовым ключом hex) → migrate v1 → запуск контрактного набора `runRepositoryContract` (TASK-021) на Sqlite-реализации; плюс: (8) транзакционный fail-point тест — после сбоя: count=0, data_version не изменился; (9) roundtrip всех полей включая pulse=NULL, irregular=true, note с юникодом/эмодзи.

## 20. Критерии приёмки

- [ ] Контрактный набор TASK-021 (7 групп) зелёный на SQLite-реализации.
- [ ] Fail-point тест: сбой → rollback полный (записи нет, версия прежняя).
- [ ] Roundtrip юникода/эмодзи в note без искажений.
- [ ] Ошибки constraint → STORAGE/CONSTRAINT (тест вставки дубликата id).
- [ ] В файле нет импорта EventBus (grep — разделение ответственности).
