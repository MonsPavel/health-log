## 2. Цель

Типизированная внутренняя шина событий в main-процессе (`EventBus`) и механизм доставки событий в рендерер (`window.hl.on(name, handler)`), с типизированным реестром имён и payload-ов.

## 3. Бизнес-контекст

Три продуктовых поведения невозможны без событий: бейдж «данные изменились» у ИИ-резюме (FR-5.7), живой журнал сетевой активности (FR-7.1), экран блокировки (FR-7.5). Запрос-ответ IPC (TASK-008) не подходит — события асинхронны по природе. Каркас строится до первого события, чтобы имена и форма доставки не менялись.

## 4. Технический контекст

- **Архитектура:** поток событий — `docs/architecture/01-high-level.md` §5, 05 §4 (реестр событий).
- **Пакеты:** `@hl/contracts` (типы событий), `apps/desktop` (шина + мост).
- **Обоснование:** своя 50-строчная типизированная шина вместо EventEmitter: строгая типизация имён/payload и отсутствие зависимости. Альтернатива rx.js — избыточна.

## 5. Объём

- **Включено:** contracts: тип `HlEventMap` — карта «имя события → payload» с начальным составом: `data:versionBumped {newVersion: number}`, `measurement:changed {profileId: string}` (имена зафиксированы сейчас, публикуются позже — TASK-026); `app:log {level, messageKey}`; preload: `window.hl.on(name, cb): unsubscribe`; main: `EventBus` (on/once/off/emit, Map<name, Set<handler>>), `broadcastToWindows(name, payload)` — отправка всем живым webContents через `webContents.send('hl:event', {name, payload})`; cleanup: отписка dead-окон (проверка isDestroyed при отправке + удаление при 'destroyed').
- **Не включено:** прикладные публикации (задачи-потребители), очередь/буферизация для скрытых окон (события «протекают мимо» — рендерер перечитывает состояние через query-инвалидацию, это осознанная семантика).
- **Будущая работа:** payload-валидация на принимающей стороне рендерера — при первом расхождении версий (обе стороны всегда одной версии в MVP — арх. 05 §6).

## 6. Файлы

## 9. Бэкенд

`emit` шины синхронный; исключение в одном подписчике не должно рвать цепочку остальных — try/catch на каждый handler + лог. Broadcast — fire-and-forget: ошибки send (уничтоженное окно) глушатся с логом debug.

## 10. Фронтенд

Хук `useHlEvent(name, handler)` — useEffect с корректной отпиской (строгий режим React 18: двойной mount не должен дублировать обработчики — проверка в тесте хука опциональна, семантика unsubscribe обязательна).

## 11. API

Событийный «endpoint»: единый канал `hl:event` c `{name, payload}`; payload-типы — из `HlEventMap`; новые события = расширение карты в contracts (без изменения механизма). Версионирование: обе стороны одной сборки (арх. 05 §6).

## 12. Управление состоянием

Назначение событий в архитектуре состояния (арх. 06 §3): триггер `queryClient.invalidateQueries` — конкретная интеграция появится с фичами (TASK-030+); здесь — только доставка.

## 13. Бизнес-логика

Семантика доставки: at-most-once, только активным окнам; нет гарантий порядка между разными событиями; внутри одного имени — FIFO. Это документируется в коде шины: потребители не должны строить state-машину на событиях, только инвалидировать/обновлять.

## 14. Безопасность

Payload событий не содержит PHI (события — сигналы: версии, id, статусы; значения измерений/заметки не передаются). Проверка фиксируется тестом-контрактом карты событий: имена полей payload из белого списка.

## 15. Производительность

Broadcast N окон × M событий — тривиально при 1 окне; шумодав: события с частотой >20/с (стрим токенов) пойдут отдельным каналом `hl:stream` в P5 (заготовка комментария), не через эту шину.

## 18. Телеметрия

## 19. Стратегия тестирования

Юнит-тесты шины: подписка/отписка, once, изоляция исключений подписчиков, порядок FIFO в рамках имени. Мост: fake webContents (spy send): broadcast доставляет payload обоим окнам, destroyed-окно глушится, unsubscribe убирает доставку. React-хук: тест с Testing Library — рендер/анмаунт, отписка вызвана.

## 20. Критерии приёмки

- [ ] Тест: emit в main → fake-window получил `{name, payload}`; второе окно — тоже; destroyed — не получил и не упал.
- [ ] Исключение в первом подписчике не мешает второму (оба вызываны), ошибка в логе-спае.
- [ ] `useHlEvent` отписывается при unmount (spy unsubscribe вызван).
- [ ] `HlEventMap` содержит `data:versionBumped` и `measurement:changed` с типами из §5.
- [ ] Payload-тест-контракт: нет полей sys/dia/pulse/note/content в любом payload карты.

## 22. Риски
