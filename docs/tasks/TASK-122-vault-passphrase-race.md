## 2. Цель

На свежем профиле включение пароля (Настройки → «Защита паролем» → «Включить»)
нестабильно фиксируется: UI показывает «Вход по паролю включён — при запуске и
после простоя», канал `vault/set-passphrase` отвечает ok (диалог закрывается,
ошибки нет), но `vault.key` на диске остаётся `mode: 'safeStorage'` (mtime =
момент создания файла при старте) — после перезапуска пароль не спрашивается.
Подозрение (не проверено): поздняя первичная запись ensureKey (создание
safeStorage-файла при старте) завершается ПОСЛЕ записи setPassphrase и
перезаписывает её старым состоянием; в шапке адаптера задокументирована
«переупаковка safeStorage-blob'а при первом чтении» — проверить её условия.

## 3. Объём

- **Включено:** воспроизведение (цикл: свежий профиль → быстрый setPassphrase
  сразу после старта, N≥20 прогонов); устранение гонки (упорядочивание записей:
  setPassphrase через pending-очередь адаптера или повторное чтение-проверка
  перед записью — по результату воспроизведения); регресс-тест (int: параллель
  ensureKey × setPassphrase, финальный файл = passphrase).
- **Не включено:** пересмотр формата vault.key (v2), изменение UX включения пароля.

## 4. Критерии приёмки

- [ ] Воспроизведён автотестом (детерминированно или статистически N≥20).
- [ ] После фикса: setPassphrase на свежем профиле фиксируется в файле всегда
      (UI-статус согласован с disk-состоянием).
- [ ] Полный gate зелёный.

## 5. Проверка

Инт-тест гонки + ручная проверка на машине A RC (включение пароля сразу после
установки — шаг чек-листа 115). Откат: revert.
