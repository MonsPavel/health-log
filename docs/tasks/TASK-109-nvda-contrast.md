## 2. Цель

Ручной прогон ключевых сценариев со скринридером NVDA (ввод, история, динамика+таблица, ИИ-резюме/чат, отчёты, копии, настройки/блокировка) по чеклисту-документу с исправлениями; аудит контраста всех пар токенов обеих тем на ≥4.5:1 (AA) с правками значений.

## 3. Бизнес-контекст

Скринридер-недоступность = исключение П3-класса пользователей полностью (NFR-6: «скринридер — полноправная персона»); автоматизация скринридеров недостоверна — единственный честный путь: ручной чеклист, задокументированный как процесс релиза.

## 4. Технический контекст

- **Архитектура:** NFR-6 (NVDA — Should), арх. 06 §7.
- **Обоснование:** NVDA — целевой скринридер Windows (бесплатный, распространённый); VOC: проверки на «осмысленность озвучивания» (порядок фокуса, подписи, live-регионы), не на «нет axe-ошибок».

## 5. Объём

- **Включено:** чеклист-документ `docs/a11y-nvda.md`: для каждого из 7 сценариев: шаги навигации с NVDA (курсорные режимы, forms-mode), ожидаемое озвучивание (что должно прозвучать на каждом шаге), критерии PASS (осмысленно, без «кнопка кнопка», порядок логичен); фактический прогон с фикстурными данными (seed через e2e-хелперы или руками), дефекты → исправления (типовые: отсутствующие aria-label на иконках, live-регионы стрима — polite, фокус не уходит в тултипы); контраст: скрипт-расчёт всех пар из tokens.css (fg/bg комбинации, включая disabled-состояния — для них критерий 3:1 минимум + текстовая альтернатива) → отчёт → правка токенов не удовлетворяющих; повторный прогон.
- **Не включено:** JAWS/VoiceOver (пост-MVP по спросу), автоматизация.
- **Будущая работа:** NVDA-прогон в каждый мажорный релиз (в процесс 114).

## 6. Файлы

## 13. Бизнес-логика

Контраст-инвариант: любые пары текст/фон, которые реально сочетаются в UI, ≥4.5:1 (обычный текст), ≥3:1 (крупный текст ≥18.66px bold / 24px — rem-масштабы учитываются при расчёте: на «очень крупном» больше пар попадают в 3:1-категорию — скрипт должен знать маппинг токен→размер); disabled — 3:1 + aria-disabled. Чеклист-критерии (примеры): форма ввода — «каждое поле озвучивает подпись и значение»; ИИ-стрим — «политый текст читается по завершению, не буква-за-буквой» (aria-live дизайн); блокировка — «под оверлеем ничего не читается».
