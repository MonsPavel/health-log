## 2. Цель

Чистая функция `detectTypo(history, candidate) → flag`: если новое значение СДА или ДДА отклоняется от медианы последних 14 дней более чем на 40 мм рт. ст. — сигнал «вероятная опечатка».

## 3. Бизнес-контекст

Персона П3 (тремор рук): 215 вместо 125 — одна опечатка портит средние и провоцирует ложную тревогу ИИ (SRS FR-1.6). Правило бережное: только подсказка, решение за пользователем — реальные аномальные значения сохраняются (EC-03).

## 4. Технический контекст

- **Архитектура:** доменный сервис — `docs/architecture/02-domain-model.md` §3.1; UX-поток — UC-01 A2.
- **Модуль:** `measurement/domain`.
- **Обоснование:** медиана (не среднее) — устойчивость к уже содержащимся опечаткам и редким пикам; окно 14 дней — баланс «привычка уже видна / сезон не уехал». Параметры — константы домена `TYPO_WINDOW_DAYS=14`, `TYPO_THRESHOLD_MMHG=40` (правка = ревизия SRS).

## 5. Объём

- **Включено:** функция `detectTypo(history: BpMeasurement[], candidate: {sys, dia}): TypoFlag | undefined`, тип `TypoFlag {field: 'sys'|'dia', median: number, value: number, deviation: number}`; константы окна/порога; юнит + property тесты.
- **Не включено:** выборка истории из БД (use case TASK-029), UI (TASK-032), порог для пульса (пульс не проверяется — тремор влияет и на него, но норма пульса шире в 3 раза; решение зафиксировано как сознательное, SRS FR-1.6 говорит только про мм рт. ст.).
- **Будущая работа:** персонализированный порог (адаптация к волатильности пользователя) — post-MVP, если ложные срабатывания станут жалобой.

## 6. Файлы

- **Создать:** `apps/desktop/src/main/modules/measurement/domain/typo-heuristic.ts` (+ constants в `constants.ts` из TASK-016), тесты.

## 7. Модель предметной области

Сигнатура: `detectTypo(history: ReadonlyArray<BpMeasurement>, candidate: {sys: number; dia: number}): TypoFlag | undefined` (undefined = сигнала нет; оба поля проверяются независимо — флаг по худшему отклонению). История — до 100 последних записей за окно (порядок не важен — функция сама фильтрует по окну относительно «сейчас» кандидата? НЕТ: функция принимает уже отфильтрованный список — детерминизм; фильтрацию окна делает use case через Instant-сравнение). Уточнение контракта: history = записи за последние 14 дней от moment кандидата; функция не знает про время вовсе (pure math: медиана массива).

## 13. Бизнес-логика

Вычисление: для каждого поля: медиана чётного массива = среднее двух центральных (стандартное определение, тест-фиксируется); отклонение `abs(value − median)`; flag если `> 40` (строго). Пустая история или <2 записей → undefined (нет базы сравнения — не подсказываем, EC-09-дух). Пограничные: отклонение ровно 40 → нет флага (строгое больше); медиана от уже содержащих опечаток историй — поведение по определению медианы (устойчивость).

## 19. Стратегия тестирования

Golden-кейсы: 14 дней по 128/82, кандидат 128/82 → нет; кандидат 168/82 → флаг sys (median 128, dev 40 — нет, строго! → уточнение: dev=40 → нет; 41 → да); кандидата 258 → флаг. Property: перестановка истории не меняет результат (медиана порядок-инвариантна); удвоение каждой записи истории не меняет медиану. Пустая/1 запись → undefined.

## 20. Критерии приёмки

- [ ] История 14 дней по 128/82: кандидат 168/82 → TypoFlag {field:'sys', median:128, deviation:40}? НЕТ — ровно 40 не срабатывает; 169 → срабатывает (тест фиксирует оба).
- [ ] История с одной скрытой опечаткой 258: медиана не сдвинута (тест на устойчивость).
- [ ] Пустая история и 1 запись → undefined.
- [ ] Чётная/нечётная длина истории — медиана по стандартному определению (кейсы 3 и 4 записей).
- [ ] Константы 14/40 — в constants.ts, единственные литералы.
