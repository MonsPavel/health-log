## 2. Цель

`DiagBundle`: по явному действию пользователя — сбор zip (логи, self-check, версии, журнал сети, агрегаты app_event, список миграций) → окно предпросмотра содержимого → save dialog; в пакете нет PHI (гарантия — redact-логгер + тест).

## 3. Бизнес-контекст

NFR-12: пользователь может безопасно приложить диагностику к issue — без риска выложить своё давление в интернет. Плюс ротация журналов/событий (90/180 дней — арх. 04 §7) — задача здесь.

## 4. Технический контекст

- **Архитектура:** диагностика — арх. 09 §8/12; тест-паттерн PHI — TASK-010.
- **Обоснование:** сборка = файлы + каналы-запросы (всё уже есть); zip — нативно через archiver-зависимость (лёгкая) или… РЕШЕНИЕ: без зависимостей — просто tar-подобный? Windows-пользователь открывает zip нативно → зависимость `archiver` (зрелая) принимается. Предпросмотр — рендерер читает структуру пакета (список файлов + размеры + превью первых строк лога) ДО сохранения.

## 5. Объём

- **Включено:** `DiagBundleService`: `collect(): DiagContent {files: [{name, size, text?}]}` — лог-файлы (все ротации), self-check-отчёт (TASK-100), версии (app/meta), журнал сети (privacy/journal 200 записей), app_event-агрегаты (по kind count за 90 дней), список миграций+versions, системная строка (OS, arch, locale — без имени пользователя/серийников); `saveBundle(targetPath)` — zip (архив с манифестом diag-manifest.json: версия формата, дата); канал `diag/preview {} → DiagContent`, `diag/save {} → {path}` (внутри: collect→preview-данные сохранены в кэш→save dialog); UI: настройки → «Диагностика» → «Собрать пакет» → предпросмотр (дерево файлов, счётчик записей, предупреждение «Проверьте содержимое — мы гарантируем отсутствие ваших измерений») → «Сохранить…»; ротация: JobScheduler-задачи `logs.rotate` (файлы >5×5МБ уже ролируются pino — задача удаляет >30-дневные), `events.rotate` (network_event >90д, app_event >180д — DELETE; интервал — при старте); тесты.
- **Не включено:** авто-отправку (никогда), скриншоты UI.
- **Будущая работа:** выборочное включение/исключение файлов пользователем (пост-MVP).

## 6. Файлы

- **Создать:** `main/modules/platform-services/diag/{diag-service.ts,rotation.ts}` + тесты; contracts `diag/*`; `ipc/handlers/diag.ts`; `src-renderer/features/settings/ui/DiagSection.tsx` + тест; ключи i18n; подключение ротационных задач в scheduler.
- **Изменить:** `container.ts`, `package.json` (archiver).

## 7. Модель предметной области

`DiagContent {files: [{name, sizeBytes, preview?: string}], totals: {eventsByKind: Record<string, number>}}` — preview: первые 20 строк текстовых файлов.

## 8. База данных

Ротация: DELETE FROM network_event WHERE at_utc < now−90д; app_event < 180д (таблицы v4/v5).

## 9. Бэкенд

Сборка в памяти (логи ≤25 МБ — приемлемо; >25 МБ — без preview-текстов, только списки — защитная ветка); zip-стрим в tmp → save dialog → move/copy.

## 10. Фронтенд

Предпросмотр: дерево файлов с размерами, JSON-превью версий, предупреждение-фраза (golden: «гарантируем отсутствие ваших измерений» — формулировка аккуратная: «в пакет не входят ваши измерения и заметки»).

## 11. API

`diag/preview`, `diag/save` (путь — через save dialog main-стороны, паттерн 065).

## 12. Управление состоянием

N/A.

## 13. Бизнес-логика

PHI-инварианты сборки: логи уже редактированы (TASK-010-контракт); network_event/app_event — метаданные; self-check — факты; НИКАКИХ измерений/заметок/чата — тест-сканирование итогового текста пакета на PHI-паттерны (по аналогии с тестом логгера).

## 14. Безопасность

Zip-бомба-риски нет (мы собираем); предпросмотр обязателен (AC) — пользователь контролирует публикацию.

## 15. Производительность

Сборка ≤2 с на 25 МБ логов (тест-ориентир).

## 16. Доступность

Предпросмотр — таблица семантичная; кнопка сохранения после скролла? Нет — сразу видимая (пользователь взрослый, предупреждение текстом).

## 17. Интернационализация

Ключи: `diag.collect/preview/save/warning/guarantee`, размеры — Intl.

## 18. Телеметрия

Лог: `diag bundle saved files=N sizeMB=…`.

## 19. Стратегия тестирования

Интеграционные (tmp): collect на seeded-данных (логи с PHI-фикстурой, события, self-check) → сканирование всех текстов: PHI-строки отсутствуют (тест-гарантия); zip распаковывается тестом (unzip-либа в devDeps) — манифест на месте; ротация: записи старше порога удалены, свежие целы (FixedClock); UI: предпросмотр-дерево, save invoke.

## 20. Критерии приёмки

- [ ] PHI-инвариант: синтетические измерения/заметки из лог-фикстуры НЕ найдены в собранном пакете (скан-тест — главный AC).
- [ ] Zip валиден: распаковка тестом, manifest присутствует.
- [ ] Предпросмотр: дерево+превью отображаются ДО сохранения (тест DOM).
- [ ] Ротация: network_event 91 день удалён, 89 — цел; app_event порог 180 (FixedClock-тесты).
- [ ] Сборка ≤2 с (замер-тест).
- [ ] Golden-предупреждение: «в пакет не входят ваши измерения и заметки» присутствует.
