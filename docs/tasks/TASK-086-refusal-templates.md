## 2. Цель

Детерминированные ответы ДО обращения к модели: малые данные (<7 измерений/<3 дней), классифицированные запреты (treatment/dosage/diagnosis), критические значения в контексте → готовые тексты (включая срочную панель FR-7.4 с локальными номерами); LLM не вызывается там, где нужен гарантированный текст.

## 3. Бизнес-контекст

AC-5.1 требует гарантий: «мне 190/120 и болит голова» обязан получить немедленную срочную рекомендацию, а не «обычно хорошую» генерацию. LLM не используется там, где текст должен быть гарантирован (арх. 07 §4 эшелон 2).

## 4. Технический контекст

- **Архитектура:** эшелон 2 — арх. 07 §4; фабрика отказов — зависимость TASK-085.
- **Обоснование:** единый `PrecheckService`: на входе вопрос+контекст-мета → (1) classifyQuestion (082); (2) insufficientData (пороги kernel по stats); (3) критические в контексте → возвращает готовый ответ ИЛИ undefined (идём в LLM). Порядок: emergency > treatment/dosage/diagnosis > insufficientData > undefined.

## 5. Объём

- **Включено:** `refusalTextFactory(class, meta)` — шаблоны (i18n-ключи main-стороны? РЕШЕНИЕ: тексты отказов — RU-константы в main, как system prompt (LLM-слой не локализуется каталогом UI), но ключи-идентификаторы для логов; полный текст срочности переиспользует формулировки панели 041 — константы дублируются с тестом-сверкой): treatment/dosage → «Это вопрос о лекарствах… я не могу советовать приём или изменение препаратов. Обсудите это с врачом…» + (если есть данные) фактура периода; diagnosis → «Я не ставлю диагнозы… вот что видно в данных: <фактура>… обратитесь к врачу для оценки»; emergency → полный текст FR-7.4 (103/112); insufficientData → «Данных пока мало (N измерений за M дней) — я не буду делать выводов. Вот факты: …»; `PrecheckService.check(question, ctx) → PrecheckResult {kind: 'refusal', text, refusalClass} | {kind: 'emergency', text} | undefined`; интеграция-точка для 087; тесты.
- **Не включено:** UI-отличия (088/090 рендерят refusal стилем «системного ответа»), EN-версии.
- **Будущая работа:** смягчение/вариативность формулировок (rotating variants) — пост-MVP.

## 6. Файлы

## 19. Стратегия тестирования

Таблица: каждый redSetCase 082 → ожидаемый PrecheckResult (emergency/dosage/…/undefined); пороги: 3 записи → insufficient; 8 записей → undefined (идём в LLM); emergency при 190/120 в контексте даже при безобидном вопросе («как дела» — emergency-вставка? РЕШЕНИЕ: при критических значениях в ПЕРИОДЕ — отказ-эскалация только на ВОПРОСЫ о состоянии; безобидный «какие тренды» — обычный путь, но ответ 087 обязан содержать срочную приписку — это обязанность 087/084; тест разграничивает); golden-тексты отказов (снапшоты).

## 20. Критерии приёмки

- [ ] Таблица redSetCase→PrecheckResult зелёная (все классы).
- [ ] Пороги 7/3: 3 записи → insufficient; 8 за 4 дня → undefined.
- [ ] Emergency-текст == текст панели 041 (тест-сверка общих констант) + номера по локали.
- [ ] Golden-снапшоты 4 отказ-текстов стабилизированы.
- [ ] Запрет-лексика отсутствует в отказах (словарь-тест).
- [ ] При refusal LlmEngine.complete НЕ вызван (spy) — мгновенный ответ.
