## 2. Цель

## 3. Бизнес-контекст

Продукт — локальный дневник давления (SRS `docs/01-vision.md`). Ни одна фича не может быть реализована, пока не зафиксирована физическая структура репозитория: архитектура (`docs/architecture/03-modules.md`) требует монорепо с пакетами-слоями, чтобы границы зависимостей проверялись инструментами, а не конвенцией. ## 22. Риски

- Конфликт версий pnpm/node у разработчиков — снят фиксацией `packageManager`/`engines` + corepack.
- «Пустой» build может скрыть неверные exports — проверка импорта `@hl/kernel` из desktop в §20.

## 23. Будущие соображения

При добавлении второго приложения (мобильный компаньон, пост-MVP) workspace расширяется новым `apps/*` без перестройки. Turborepo/Nx не нужны до ~10 пакетов (порог пересмотра — в TD-реестре `docs/tasks/00-project-management.md` §9 не фиксируется: избыточность очевидна).

## 24. Проверка

Автоматически: `pnpm install && pnpm -r build` — exit 0; `node -e "require('@hl/kernel')"` из `apps/desktop` резолвит пакет (после простого ts→js обхода допускается проверка разрешения симлинка: `ls node_modules/@hl/kernel` → symlink в packages/kernel). Ручная: `git status --short` не содержит артефактов. Откат: `git revert` коммита задачи — проект возвращается в пустое состояние; риск отката нулевой.
