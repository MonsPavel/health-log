## 2. Цель

Доменный сервис `Classifier.classify(avgSys, avgDia, scale) → {category?, notes[]}`: категория среднего за период по активной шкале (правило «худшая из двух измерений») с обязательными примечаниями: домашний порог ≥135/85, дисклеймер, неприменимость особым группам; заполнение резервируемого поля PeriodStatistics.

## 3. Бизнес-контекст

Классическая ошибка приложений: пользователь измеряет дома, ему показывают офисную шкалу без оговорки — молчаливое смещение на 5 мм рт. ст. (SRS R-11, FR-4.2). Примечания неотделимы от результата (структура данных) — UI физически не может показать категорию без оговорок.

## 4. Технический контекст

- **Архитектура:** классификатор — арх. 02 §3.2; шкала — TASK-050/051.
- **Модуль:** `analytics/domain`.
- **Обоснование:** правило «категория = худшая из двух» (sys и dia классифицируются независимо, берётся более тяжёлая) — стандартная семантика; данные шкалы хранят диапазоны категорий (TASK-050 §7) — классификатор не содержит порогов вовсе.

## 5. Объём

- **Включено:** `classify(avgSys, avgDia, scale): Classification`; тип `Classification {category: ScaleCategory|undefined; notes: ClassificationNote[]}`; `ClassificationNote = {kind: 'homeBP'|'specialGroups'|'insufficientData', text: string}` (text из данных шкалы — homeBPNote/specialGroupsNote); правило всегда добавляет homeBP и specialGroups заметки при наличии категории; при insufficientData (пороги kernel) → category=undefined + note insufficientData; интеграция: PeriodStatistics получает поле `classification?: Classification` (заполняет сборщик TASK-052 — расширение вызова, аддитивное); реперные тесты.
- **Не включено:** пульс-классификация (не классифицируем — только справка 60–100 на UI потребителя), гипотензия-категория (low-флаг — политика TASK-020, не шкала).
- **Будущая работа:** выбор стандарта (AHA) — параметр scale уже абстрагирует.

## 6. Файлы

- **Создать:** `modules/analytics/domain/classifier.ts` + тесты; расширение `period-statistics.ts` (заполнение поля).

## 7. Модель предметной области

Алгоритм: найти категорию, где `avgSys ∈ sysRange` (первая по порядку); найти категорию по dia; результат = более тяжёлая из двух (индекс в отсортированном массиве больше); вне всех диапазонов (невозможно при стыковке, но защита) → последняя/первая по стороне выхода. Крайние значения: avgSys < sysMin оптимальной (напр. 110) → оптимальная (open-граница).

## 13. Бизнес-логика

Реперные кейсы (из SRS AC-3.3): avg 138/86 → high_normal; 136/84 → normal + ОБЕ заметки (homeBP: «≥135/85 соответствует офисному ≥140/90»); 145/85 → hypertension1 (sys решает); 120/95 → hypertension1 (dia решает); 119/79 → optimal; 181/70 → hypertension3. Округлённые avg из TASK-052 подаются как есть (классификатор не перечитывает). insufficientData → без категории (пороги kernel — единый источник).

## 19. Стратегия тестирования

Реперные кейсы §13 — exhaustive по краям категорий (граничные значения диапазонов: 120 ровно → normal, 119 → optimal, 180 → hypertension3); обе заметки присутствуют всегда при категории; insufficientData-ветка; интеграция со сборщиком 052: поле заполняется на фикстуре (b).

## 20. Критерии приёмки

- [ ] Все реперные кейсы §13 зелёные (включая пограничные значения диапазонов).
- [ ] Категория всегда сопровождается homeBP+specialGroups заметками (тест).
- [ ] insufficientData (3 записи) → category undefined + note.
- [ ] Правило «худшая из двух» подтверждено кейсами 145/85 и 120/95.
- [ ] PeriodStatistics-фикстура (b) содержит заполненную classification.
