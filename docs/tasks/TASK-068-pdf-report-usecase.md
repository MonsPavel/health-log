## 2. Цель

Сквозной UC-05: экран «Отчёты» → выбор периода (переиспользование TASK-046) → чекбокс «включить ИИ-разбор» (доступен, если резюме за период есть) → предпросмотр состава → «Сформировать и сохранить» → пул рендерит → save dialog → файл; пустой период не формируется.

## 3. Бизнес-контекст

UC-05 (визит к врачу) — целевой сценарий BG-3: отчёт собирается <30 с и принимается врачом. Сборка — из read models; ИИ-текст — опционален и маркирован (шаблон TASK-067), выбор — за пользователем.

## 4. Технический контекст

- **Архитектура:** use case оркестрация — арх. 02 §5; очередь FileOpQueue (TASK-065) — рендер PDF занимает очередь? РЕШЕНИЕ: очередь файловых операций (TASK-065) сериализует только ЗАПИСЬ; рендер идёт в worker pool параллельно; сохранение — через очередь.
- **Модуль:** `reporting/application` + renderer `features/reports`.
- **Обоснование:** предпросмотр = список состава (таблица/средние/график/регулярность — чек-лист, не рендер PDF в UI: react-pdf в renderer тянет тяжёлый рантайм; «предпросмотр» = экран настроек с итогами и точным перечнем разделов; сам PDF открывается после сохранения системным просмотрщиком — FR-6.7).

## 5. Объём

- **Включено:** `BuildPdfReportUseCase.execute(spec) → Result<{pages, durationMs}>`: сборка payload: точки (056 raw/daily — таблице нужен raw: если period>порог — запросить сырые точки последних 2000 напрямую портом, комментарий), stats (054), scale label, aiText — если includeAiSection: получить последнее резюме, пересекающее период (запрос ai_summary — таблица появится в P5! РЕШЕНИЕ: параметр aiText передаётся ВЫЗЫВАЮЩИМ (renderer передаёт выбранное резюме из UI ИИ-экрана или контекст-меню); use case агностичен) → pool.run('pdf.render') → FileOpQueue → FileSaver; канал `report/pdf {spec, aiText?}` → `{path}|{canceled}`; UI экран «Отчёты»: период-контрол (TASK-046), чекбокс ИИ (disabled с подсказкой, если резюме за период нет — проверка локальным кэшем резюме; P5 наполнит), карточка «Состав отчёта» (чек-лист разделов + count записей), кнопка «Сформировать и сохранить» (loading state), после — тост + кнопка «Открыть папку» (shell.showItemInFolder через канал `app/reveal-path`); пустой период → кнопка disabled с подсказкой; тесты.
- **Не включено:** inline-PDF-предпросмотр в окне (решение §4), выбор сортировки/шаблона.
- **Будущая работа:** отправка на печать минуя файл (пост-MVP по спросу FR-6.7).

## 6. Файлы

- **Создать:** `application/build-pdf-report.ts`; contracts `report/pdf`; `ipc/handlers/report-pdf.ts`; `ipc/handlers/reveal.ts`; `src-renderer/features/reports/ui/{ReportScreen.tsx,ReportBuilder.tsx}` + тесты; ключи i18n.

## 7. Модель предметной области

`ReportRequest {period, includeAiSection, aiText?}` → use case собирает ReportSpec (TASK-067) + метрики; ошибки: `REPORT/EMPTY_PERIOD` (нет записей), `REPORT/RENDER_FAILED` (ошибка воркера — cause в лог).

## 8. База данных

Чтение через порты; ai_summary — P5 (здесь только контракт параметра).

## 9. Бэкенд

Порядок: zod → валидация непустости (count>0 — быстрый count-запрос) → сборка payload → pool.run → save (очередь) → ответ. Отмена пользователя (диалог) → canceled (рендер зря — приемлемо, лог).

## 10. Фронтенд

Состояния: настройки → rendering (прогресс неопределённый — спиннер + «до 30 секунд» честно) → done (тост+открыть папку) / error. Чекбокс ИИ: tooltip «Резюме ИИ не является медицинским заключением и будет промаркировано в отчёте».

## 11. API

`report/pdf` (§5), `app/reveal-path {path}` → void (shell.showItemInFolder; путь — только тот, что вернул наш же экспорт — renderer не может попросить произвольный? zod строка… УПРОЩЕНИЕ: reveal принимает путь, но это UX-удобство на своей машине — приемлемо, санитизация не требуется (open в explorer), риск нулевой локально; решение документируется).

## 12. Управление состоянием

Мутация report/pdf; «резюме за период есть» — из кэша ИИ-экрана когда появится (P5); в P4 чекбокс всегда disabled с подсказкой «появится вместе с ИИ-разбором» (честная заглушка).

## 13. Бизнес-логика

Пустой период → REPORT/EMPTY_PERIOD → кнопка disabled заранее (по count из stats — число уже известно). Таблице нужны сырые точки: period>500 → task получает raw последние 2000 (решение шаблона 067 согласовано).

## 14. Безопасность

Файл — через save dialog (путь выбирает пользователь); ИИ-текст маркируется шаблоном (067-тест).

## 15. Производительность

Цель NFR-4: ≤30 с на 5k (bench 069); UI показывает честную оценку.

## 16. Доступность

Чекбокс/кнопки — стандартные; loading state — aria-busy; сообщение «до 30 секунд» — управление ожиданием (WCAG-дружественно).

## 17. Интернационализация

Ключи: `report.title`, `report.period*`, `report.includeAi`, `report.includeAi.hint`, `report.compose.*` (состав), `report.generate`, `report.done`, `report.emptyHint`, `report.progressNote`.

## 18. Телеметрия

Лог: `report/pdf period=… pages=… durationMs=… ai={true|false}`.

## 19. Стратегия тестирования

Use case (моки pool/saver): happy path (порядок render→save), EMPTY_PERIOD, canceled, ошибка рендера → REPORT/RENDER_FAILED. UI: пустой период → disabled; состав-чеклист отражает spec; интеграционный smoke: tmp-БД 50 записей → PDF файл существует >10 КБ (e2e-мини).
