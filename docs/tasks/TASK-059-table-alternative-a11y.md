## 2. Цель

Переключатель «График / Таблица» на экране динамики: таблица тех же данных (дата-время, СДА, ДДА, ЧСС, рука, флаги) с сортировкой; текстовое резюме тренда под графиком (из тех же read models); полное скринридер-представление данных.

## 3. Бизнес-контекст

Двойная ценность (дорожная карта): (1) доступность — скринридер читает таблицу, а не «картинку» (NFR-6); (2) персона П5 — врачу удобнее таблица, «умные» графики он не просит. Единственный источник данных — read models: график и таблица не могут разойтись.

## 4. Технический контекст

- **Архитектура:** арх. 06 §8 (таблица-альтернатива обязательна), 059-принцип «одни данные».
- **Обоснование:** таблица строится из того же TrendResponse (raw-режим точки; daily — дневная таблица) — ноль параллельных вычислений; переключатель — URL `?view=…&as=table` (шаро-пригодно).

## 5. Объём

- **Включено:** сегмент «График/Таблица» (URL `as=chart|table`, дефолт chart); `TrendTable`: колонки Дата-время (Intl), СДА, ДДА, ЧСС, Рука, Флаги (бейджи TASK-042 переиспользование); сортировка по клику заголовка (дата asc/desc, sys, dia — простая сортировка загруженных точек, сервер не трогаем: страница 500 точек локальна); daily-режим — дневная таблица (день, avg±, min–max, count); резюме-строка под графиком из stats (`stats/period` уже запрашивается? НЕТ — отдельный useQuery stats того же периода; переиспользование данных, не дублирование вычислений); aria-связь: график role=img с aria-label = краткое резюме (те же числа); пустые состояния таблицы; экспорт таблицы в буфер (TSV) — Could если ≤30 мин бюджета, иначе out; тесты.
- **Не включено:** печать таблицы (браузерная), пагинация таблицы отдельно от графика (один датасет).
- **Будущая работа:** CSV-кнопка на таблице (указывает на TASK-063 экспорт — не дублировать).
