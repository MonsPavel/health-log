## 2. Цель

Use case `UpdateMeasurement` (полная правка любой записи через `edit`-фабрику агрегата) + его IPC-хендлер; консолидация CRUD-набора (add — TASK-029, delete — TASK-032, list — TASK-030) с общими тестами веток; при правке — пересчёт эвристик без учёта самой правки.

## 3. Бизнес-контекст

## 4. Технический контекст

- **Архитектура:** application-слой — арх. 02 §5; каналы — 05 §3 (`measurements/update` схема готова в TASK-028).
- **Модуль:** `measurement/application` + `main/ipc`.
- **Обоснование:** update = `BpMeasurement.edit` (полная замена агрегата — семантика порта TASK-021) + пересчёт флагов против истории **без самой записи** (иначе запись сама себе «норма»).

## 5. Объём

- **Включено:** use case `UpdateMeasurementUseCase.execute({id, …поля}): Promise<Result<UpdateResult>>`: getById → NOT_FOUND; `edit` с Clock → доменные ошибки; пересчёт TypoHeuristic (история 14 дней без правки записи — фильтр id≠) и CriticalValuePolicy (по новым значениям); duplicate НЕ пересчитывается (правка не создаёт дубль-риск — решение); repo.update; события `measurement:changed` + `data:versionBumped`; хендлер `measurements/update`; консолидационные CRUD-тесты (все 4 канала против одного tmp-контейнера); лог.
- **Не включено:** UI (TASK-038), FTS-синхронизация заметок при update — проверка: FTS появится в TASK-045 с триггерами БД, которые покроют update автоматически (в этой задаче только комментарий-требование).
- **Будущая работа:** аудиторский след правок — никогда (FR-2.4 решение SRS).

## 19. Стратегия тестирования

Юниты (fake repo, FixedClock): happy-path (update+оба события); NOT_FOUND; FUTURE_TIME; typo пересчитан без самой записи (запись сама в истории не портит сравнение); critical по новым значениям; duplicate отсутствует в ответе. Консолидационный интеграционный тест: add→update→list→delete на tmp-контейнере — полный жизненный цикл одной записи, data_version растёт на каждой мутации.

## 20. Критерии приёмки

- [ ] Happy-path: обновлённая запись читается из репозитория, оба события отправлены.
- [ ] Несуществующий id → err NOT_FOUND, БД не изменена.
- [ ] FUTURE_TIME при правке времени вперёд → err без изменений.
- [ ] Typo-история: правка записи на 169 при медиане 128 (без учёта правимой) → flags.typo присутствует.
- [ ] duplicate отсутствует в ответе update (контрактный тест формы ответа).
- [ ] CRUD-цикл: data_version 1→5 (add, update, delete, +2 fixtures-мутации) — точная арифметика в тесте.
