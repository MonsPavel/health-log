## 2. Цель

`HL_TEST_USER_DATA` сегодня подменяет только путь контейнера
(`user-data-override.ts` → buildContainer): БД и vault.key изолированы, но
Chromium-слой (localStorage — в т.ч. `hl.updates.lastCheckAt`, disk/GPU-кэши)
продолжает жить в реальном профиле `%APPDATA%\health-log`. Следствия,
зафиксированные аудитом: e2e-тесты обновлений (TASK-097) зависят от общего
localStorage; аудит «чистая установка» неполон для UI-состояния.

## 3. Объём

- **Включено:** в bootstrap при заданной непустой переменной вызывать
  `app.setPath('userData', override)` ДО создания окна/контейнера (порядок:
  setPath → ready → buildContainer с тем же override); юнит-тест
  user-data-override дополнить контрактом «setPath применяется» (мок app);
  проверка e2e-прогоном: localStorage записанный тестом не появляется в
  реальном профиле.
- **Не включено:** миграции реального профиля; очистка реального профиля.

## 4. Критерии приёмки

- [ ] Юнит: при заданной переменной app.setPath вызывается с тем же путём; без — не вызывается.
- [ ] E2E smoke: тест пишет localStorage-ключ → в `%APPDATA%\health-log/Local Storage` его нет, в tmp-userData есть.
- [ ] Полный gate (test/typecheck/lint) зелёный.
