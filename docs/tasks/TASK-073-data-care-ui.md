## 2. Цель

Экран «Данные» (маршрут /reports секция или отдельный /data — РЕШЕНИЕ: секция на «Отчётах»): создать копию (диалог пароля копии + предупреждение о необратимости забытого пароля), восстановить (файл-пикер → план-предупреждения → подтверждение), удалить всё (двухшагово + предложение экспорта) — сквозные e2e UC-08/UC-10.

## 3. Бизнес-контекст

Пользовательские сценарии UC-08/UC-10 без консоли: мама Анны, Виктор Петрович — UI обязан провести через опасные операции бережно (тексты SRS: «необратимо», «текущие будут заменены»).

## 4. Технический контекст

- **Архитектура:** каналы готовы (070/071/072); экран — тонкий оркестратор диалогов.
- **Обоснование:** все опасные действия — через Radix AlertDialog с safe-action (Esc/отмена — дефолт); последовательность диалогов восстановления (пароль → план → подтверждение) — один мастер-флоу компонента.

## 5. Объём

- **Включено:** `DataSection`: (1) «Создать копию»: кнопка → диалог пароля копии (дважды ввод, политика ≥8, предупреждение «Забыли пароль — данные копии невосстановимы» обязателен — тест) → канал create (mode ask) → тост с путём; (2) «Восстановить»: файл-пикер (dialog через канал file/open-dialog — новый минимальный канал) → ввести пароль → план: показать предупреждения (замена текущих; старее; counts) → чекбокс «Я понимаю, что текущие данные будут заменены» (обязателен для кнопки execute) → execute → экран «Перезапуск…» до relaunch; (3) «Удалить все данные»: предупреждение-список (что удалится, включая копии) → предложение «Сначала экспортировать» (ссылка-кнопка на экспорт 065) → чекбокс подтверждения → execute → перезапуск; состояния loading/ошибки всех операций; тесты.
- **Не включено:** список существующих копий с управлением (пост-MVP), auto-копии (074 — только напоминание).
- **Будущая работа:** слоты копий с датами — пост-MVP по спросу.

## 10. Фронтенд

Мастер-флоу восстановления: шаги (файл→пароль→план→подтверждение→рестарт-экран) с возможностью «назад» до execute; рестарт-экран блокирующий («Данные восстанавливаются… приложение перезапустится») — не закрываемый; ошибки каждого шага — инлайн в диалоге (не тост — контекст важен).

## 11. API

`backup/create`, `backup/restore` (план+execute), `data/wipe` (план+execute), `file/open-dialog` — реализация/регистрация всех.

## 12. Управление состоянием

Локальные state машины диалогов; после execute — приложение умирает (relaunch) — состояние не важно.

## 13. Бизнес-логика

Чекбокс-гейт: кнопка опасного действия активна ТОЛЬКО при отмеченном чекбоксе (тест — защита от Enter-спама); предзаполнение пароля копии при восстановлении — нет (ввод заново).

## 14. Безопасность

Пароль копии — type=password, не логируется, не сохраняется (только в канале); предупреждение о забытой пароле — обязательный элемент (тест текста).

## 19. Стратегия тестирования

Компонентные: флоу копии (пароль-мисматч → инлайн-ошибка), restore-мастер (план с warnings рендерится, чекбокс-гейт кнопки), wipe (экспорт-ссылка, чекбокс-гейт); E2E (сквозные): UC-08 полный (копия → wipe? нет: копия → добавить данные → восстановить → данные копии), UC-10 (wipe → онбординг) — в edge-inputs-стиле, отдельная спека `data-care.spec.ts`.

## 20. Критерии приёмки

- [ ] Копия: диалог пароля с предупреждением; создан файл, тост с именем (AC-2.4-путь).
- [ ] Восстановление: план показывает «заменит 350 записей»; без чекбокса кнопка мертва; после execute — перезапуск и данные копии (сквозной e2e).
- [ ] Восстановление с неверным паролем — инлайн-ошибка, флоу не падает.
- [ ] Удаление: список категорий, ссылка «Сначала экспортировать» работает, чекбокс-гейт, после execute — онбординг.
- [ ] Все диалоги: Esc = безопасное действие; axe чисто.
