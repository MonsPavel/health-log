## 2. Цель

Воспроизводимый bench-скрипт: генерация 10 000 записей в tmp-БД → замер канала trend/series (main) → замер рендера графика (renderer, performance API) → отчёт; целевые: сборка ≤200 мс, рендер ≤800 мс, суммарно <1 с (NFR-4-компонент).

## 3. Бизнес-контекст

«Дневник на годы» (NFR-9) обязан оставаться отзывчивым на третьем году использования; bench — способ поймать деградацию до пользователя, а не после. Замер фиксируется как базовая линия для TASK-111 и будущих релизов.

## 4. Технический контекст

- **Архитектура:** perf-скрипты — `tools/scripts` (арх. 10 §1).
- **Обоснование:** генерация синтетики (детерминированный seed) — не реальные данные: воспроизводимость между машинами/прогонами; режимы raw(500)/daily(10k→дни) оба замеряются.

## 5. Объём

- **Включено:** `tools/scripts/bench-chart.mjs` (+unit-функции): шаги: (1) tmp-userData+tmp-БД, генерация 10k записей за 3 года (детерминированный PRNG с seed, реалистичная форма день/вечер+шум); (2) запуск приложения в e2e-режиме (Playwright launchApp-хелпер переиспользование) на периоде «всё»; (3) замер A: время ответа канала trend/series (инжектированный performance-хук через preload? РЕШЕНИЕ: замер из renderer — performance.now() вокруг invoke); (4) замер B: рендер — performance.mark/measure вокруг маунта графика (точка «данные получены» → «paint завершён» через requestAnimationFrame); (5) отчёт: JSON+текст (медиана 3 прогонов); гейты: A ≤200 мс, B ≤800 мс → exit 0/1; скрипт `bench:chart`.
- **Не включено:** CI-автозапуск (по вызову + на тегах — TASK-105), сравнение между коммитами (будущая работа).
- **Будущая работа:** тренд истории bench (артефакты-отчёты в релизах).

## 6. Файлы

- **Изменить:** `apps/desktop/tests/e2e/helpers/launch.ts` (параметр userDataPath уже есть — переиспользование; expose performance-хук — небольшой инъекционный хелпер `window.hl.__bench` только при env `HL_BENCH=1`).

## 19. Стратегия тестирования

Юнит: генератор (детерминизм seed — два запуска идентичны; распределение день/вечер присутствует), отчёт-форматтер, гейт-логика порогов. Интеграционный smoke bench на 100 записях (быстрый) — проверка механики без 45-секундного прогона.

## 20. Критерии приёмки

- [ ] `pnpm bench:chart` полный прогон на 10k: отчёт создан, медианы записаны, гейты ≤200/≤800 мс → exit 0 (на dev-машине).
- [ ] Искусственное замедление (тrottle в тест-варианте) → exit 1 с отчётом (проверка гейта).
- [ ] Генератор: два прогона с одним seed — байт-идентичные данные (unit).
- [ ] Без `HL_BENCH=1` bench-каналы не зарегистрированы (тест); в packaged — тоже (тест-эмуляция).
- [ ] Быстрый smoke (100 записей) ≤10 с.
