## 2. Цель

Маршрут `/dashboard` становится домашней сводкой: последнее измерение (крупно), средние за 7 дней (СДА/ДДА/ЧСС), категория с примечаниями (классификатор), серия дней (streak) дружелюбно, быстрый CTA «Добавить измерение» и переход к динамике; всё — из существующих read models.

## 3. Бизнес-контекст

«Домашний экран» снижает цену входа в привычку (BG-1): открыть приложение → увидеть своё состояние → измерить. US-16 (серия дней без штрафов) — мягкая геймификация: показывает, поддерживает, не ругает (FR-4.4).

## 4. Технический контекст

- **Архитектура:** экран собирает готовые read models (арх. 03 §2): stats/period (7d) + measurements/list (limit 1) — никаких новых вычислений (принцип задачи).
- **Обоснование:** `/dashboard` — стартовый маршрут приложения (уже дефолт в роутере TASK-013).

## 5. Объём

- **Включено:** карточки: (1) «Последнее измерение»: 125/82, пульс, когда («сегодня 08:12»/вчера/дата Intl), флаг critical → мини-панель TASK-041 (кликабельно); CTA-кнопка «Добавить измерение» крупная; (2) «Среднее за 7 дней»: СДА/ДДА/ЧСС + count; при insufficientData — пометка «мало данных» (TASK-060-текст-стиль); категория+notes (если есть — из classification; если нет — ничего, честно); (3) «Регулярность»: streak «Серия: 5 дней» + «за 30 дней: 22 дня с измерениями» (из stats 30d — второй stats-запрос? РЕШЕНИЕ: один stats/period 7d для средних + один 30d для регулярности — два запроса, оба дёшевы; или расширить? оставляем два — простота); пустые состояния: нет ни одной записи → приветственный экран «Начните дневник» с CTA (обучающий, FR-9.2); тесты.
- **Не включено:** виджеты погоды/сон — никогда; настройка стартового экрана (dashboard всегда стартовый — решение).
- **Будущая работа:** недельный ИИ-отчёт кнопкой (пост-MVP, P5-фаза уже даёт данные).
