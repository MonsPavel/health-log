## 2. Цель

Value Objects давления/пульса/руки с инвариантами и доменными ошибками: `BloodPressure(sys, dia)`, `Pulse`, `Arm`. Любое недопустимое сочетание отклоняется на границе домена с машиночитаемым кодом.

## 3. Бизнес-контекст

Единственная жёсткая валидация дневника (SRS FR-1.2): логически невозможные данные не сохраняются никогда — на этих цифрах стоят статистика (P3) и ИИ-анализ (P5). Единственный источник границ — константы этого модуля: их правка = пересмотр SRS табл. 4.1, не поиск по коду.

## 4. Технический контекст

- **Архитектура:** контекст Measurement, VO — `docs/architecture/02-domain-model.md` §3.1; правило чистоты домена — 03 §4 (domain импортирует только `@hl/kernel`).
- **Модули/пакет:** `apps/desktop/src/main/modules/measurement/domain`.
- **Обоснование:** VO-классы вместо «сырых чисел» в сигнатурах — невозможность собрать невалидное измерение минуя валидацию (make invalid states unrepresentable). Альтернатива (проверка в use case над примитивами) — отклонена: правило размазывается по вызывающим.

## 5. Объём

- **Включено:** типы и фабрики-конструкторы с валидацией: `BloodPressure.create(sys, dia)`, `Pulse.create(value | undefined)`, `Arm ('left'|'right')`; доменные константы границ с комментарием-источником; коды ошибок `MEASUREMENT/INVALID_RANGE`, `MEASUREMENT/SYS_LE_DIA` (добавляются в `@hl/kernel` реестр кодов); юнит- и property-тесты.
- **Не включено:** агрегат (TASK-017), тексты ошибок (ключи появляются в каталоге в TASK-031/032).
- **Будущая работа:** kPa-единицы (post-MVP, FR-8.5) — константы единственные точки правки.

## 6. Файлы

- **Изменить:** `packages/kernel/src/index.ts` (экспорт новых кодов).

## 7. Модель предметной области

Контракты: `BloodPressure { sys: number; dia: number }` (иммутабельный, equality по полям); `Pulse = number` (бренд-тип `PulseBpm`); `Arm = 'left' | 'right'`. Границы (константы `BP_LIMITS`): `SYS_MIN=50, SYS_MAX=300, DIA_MIN=20, DIA_MAX=200, PULSE_MIN=20, PULSE_MAX=300`. Порядок валидации BloodPressure: (1) целые числа? (2) диапазоны? → `INVALID_RANGE` с params `{field, value, min, max}`; (3) `sys > dia`? → `SYS_LE_DIA` с params `{sys, dia}`. Pulse `undefined` = «не измерен» — валидно.

## 19. Стратегия тестирования

Юниты: граничные значения (50/300/20/200/20/300 — валидны; 49/301/19/201/19/301 — нет), sys==dia, sys<dia, дробные. Property (fast-check): для любых sys>dia из диапазона BloodPressure.create успешен, иначе ошибка с корректным params. Моки не нужны. Покрытие домена — к вехе M-1.1 ≥90% (гейт TASK-052).

## 20. Критерии приёмки

- [ ] `BloodPressure.create(120, 80)` → ok; `.create(80, 120)` → err SYS_LE_DIA; `.create(120, 120)` → err SYS_LE_DIA.
- [ ] `.create(49.5, 80)` → err INVALID_RANGE (не целое); `.create(301, 80)` → err с params `{field:'sys', max:300}`.
- [ ] `Pulse.create(undefined)` → ok; `.create(0)` → err; `.create(300)` → ok.
- [ ] Константы `BP_LIMITS` — единственные литералы границ в модуле (grep-проверка).
