## 2. Цель

Структурный логгер (pino) с записью в ротируемые файлы в `userData/logs`, категориями (`app`, `ipc`, `db`, `ai`, `net`, `events`, `job`) и **редакцией PHI на уровне сериализатора**: значения измерений, заметки и содержимое чата физически не попадают в логи.

## 3. Бизнес-контекст

Дневник давления — специальные категории данных (SRS 01 §8). Логи без PHI — разрешение прикладывать их к issue и включать в диагпакет (NFR-12); лог с PHI = канал утечки, который нельзя выпустить наружу никогда. Правило дешевле enforced на уровне логгера, чем на совести каждого вызова.

## 4. Технический контекст

- **Архитектура:** логирование — `docs/architecture/09-platform.md` §7; модель угроз — 08 §6 (строка «Логи как канал утечки»).
- **Пакеты:** `apps/desktop` (main).
- **Обоснование:** pino — быстрый структурный JSON-логгер; ротация pino-roll (лёгкая, без внешних демонов). Альтернатива electron-log: удобен, но нет структурности и redact-механизма нужного уровня.

## 5. Объём

- **Включено:** фабрика `createLogger(category)` — child-логгер pino с полем `category`; назначение — `userData/logs/hl.log` через pino-roll (размер 5 МБ, 5 файлов); уровни: prod `info`, dev `debug`, переопределение `LOG_LEVEL` (dev only); `redact`-конфиг: paths `['sys','dia','pulse','note','content','question','answer','*.note','*.content','measurement','measurements']` + censor `'[redacted]'`; сериализатор верхнего уровня: если объект содержит ключ из чёрного списка на любом уровне (дополнительно к redact-paths — рекурсивный censor-serializer, т.к. pino redact не покрывает произвольную глубину); хелпер `logDiagnostic(error)` — только для ошибок: пишет cause/stack (без PHI-полей — стеки не содержат данные пользователя).
- **Не включено:** UI-управление уровнем (не нужно), экспорт логов (TASK-103), логирование renderer (консоль рендерера в dev; клиентские ошибки идут через IPC в TASK-011).
- **Будущая работа:** сжатие старых логов (ротация справится до 25 МБ предела).

## 13. Бизнес-логика

Правила вызова (документируются в заголовке logger.ts): логируем — операции и их исходы (что сделали, сколько, какой код ошибки), никогда — что именно ввёл пользователь. Пример разрешённый: `addMeasurement durationMs=12 flags=[typo] critical=false`; запрещённый: `addMeasurement 125/82 "болит голова"`.

## 14. Безопасность

Редакция — fail-safe: неизвестные вложенные ключи из чёрного списка цензурируются рекурсивным сериализатором до pino (двойной слой: pino.redact для известных путей + рекурсивный обход). Тест-контракт (§19) защищает правило от регрессий. Аудиторское логирование сетевых операций появится в EgressGateway (TASK-075) — через этот же логгер, категория `net`, без содержимого payload.

## 15. Производительность

Синхронная запись pino в файл допустима (объёмы малы); при профилировке >5 мс/вызов — перевести на pino.transport worker (решение по замеру, не заранее).

## 18. Телеметрия

Логи — единственная «наблюдаемость» main-процесса до диагпакета (арх. 09 §8); наружу не отправляются никогда (FR-7.2). Ротация: 5×5 МБ — ограничение размера на диске.

## 19. Стратегия тестирования

Контракт-тест редакции: логирование объекта `{measurement: {sys: 125, note: 'болит голова'}, durationMs: 12}` → в выходной строке файла нет `125`, `болит`, `sys` как значения; есть `durationMs:12`. Тесты: ротация (эмуляция превышения размера на tmp-каталоге), категории (child-поля), уровни по окружению, буфер до init. Пути логов в тестах — только tmp (конвенция TASK-004).

## 20. Критерии приёмки

- [ ] Тест PHI: ни одно PHI-значение фикстуры не найдено в выходном лог-файле (grep по значениям).
- [ ] `logDiagnostic` пишет stack, но не пишет поля-значения измерений из cause-объекта (если объект содержит PHI-ключи — они цензурены).
- [ ] Файл лога создаётся в `userData/logs/hl.log`; ротация настраивается (тест на tmp).
- [ ] Ранние ошибки до whenReady попадают в файл после инициализации (буферный тест).
- [ ] Уровень: в prod-режиме (эмуляция packaged) debug-сообщения отсутствуют.
