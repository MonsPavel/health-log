## 2. Цель

Реальный движок в llm-worker: загрузка GGUF-модели (node-llama-cpp), генерация со стримингом токенов в протокол TASK-076, отмена, выгрузка, авто-unload после 5 минут простоя; замер базовой скорости на dev-машине.

## 3. Бизнес-контекст

Ядро обещания «объясняет человеческим языком локально» (FR-5.1/5.2). Целевой класс моделей — 3–4B Q4 на CPU (референс SRS NFR-5): предсказуемость на слабом железе важнее пикового качества.

## 4. Технический контекст

- **Архитектура:** D5 — арх. 07 §1; параметры инференса — конфиг с дефолтами (07 §2).
- **Обоснование:** node-llama-cpp (prebuilt-бинари llama.cpp) — JS-нативный мост, стандарт для Electron; альтернативы (llama-server HTTP-сайдкар — порты/брандмауэр; WebLLM — нет CPU-пути) отклонены в архитектуре. Контекст: 4096 токенов (промпт+ответ), threads = физические ядра−1 (конфиг, не авто-тюнинг).

## 5. Объём

- **Включено:** движок-модуль воркера: `loadModel(path) → context/session` (двойной вызов load → перезагрузка модели), `complete(messages, params, onToken, abortSignal)`, `unload()`; маппинг протокола 076 (ready/token/done/error); idle-таймер: 5 мин без генераций → unload + лог (константа IDLE_UNLOAD_MS); замер: первый токен и токенов/с на dev-GGUF (1B Q4 — тест-фикстура ~700 МБ НЕ в репо: скрипт скачивает через EgressGateway? НЕТ — ручная загрузка разработчиком, путь через env HL_TEST_MODEL — решение; в CI модели нет — тесты движка помечены `[model]` и пропускаются); тесты без модели: контракт движка на моке, idle-таймер, отмена.
- **Не включено:** выбор/загрузка моделей из сети (079/080), тюнинг квантования/GPU offload (не в MVP — CPU).
- **Будущая работа:** GPU-слои опционально (настройка, пост-MVP), speculative decoding — никогда в MVP.

## 6. Файлы

- **Создать:** `main/llm-worker/{engine.ts,llama-engine.ts}` (+ конфиг-дефолты); тесты; dev-документация модели (`docs/dev/local-llm.md`: где взять GGUF, как включить).
- **Изменить:** `llm-worker/main.ts` (подключение движка за протоколом), package.json (зависимость node-llama-cpp).

## 7. Модель предметной области

Параметры генерации (дефолты, конфиг): `temperature 0.3` (факты, не креатив), `maxTokens 1024`, `stop` — из протокола; детерминированность НЕ требуется (LLM), но seed фиксируется для повторяемости eval (TASK-091) — параметр seed в протоколе опционален.

## 12. Управление состоянием

## 13. Бизнес-логика

Кейсы: load несуществующего файла → error `AI/MODEL_FILE_MISSING`; load битого GGUF → `AI/MODEL_INVALID` (краш-защита: обёртка try + валидация magic GGUF-заголовка до передачи движку); generate при no-model → `AI/NO_MODEL`; отмена → stop генерации, частичный текст отбрасывается (решение — протокол done(cancelled)).

## 14. Безопасность

Путь модели только из каталога models (TASK-080) или test-env; без сети в воркере (depcruise-зона); GGUF извне — sha256-проверка на 080 до загрузки.

## 15. Производительность

Замеры (dev-машина, 1B Q4): первый токен ≤3 с, ≥8 ток/с — базовая линия в ADR-комментарии; целевая модель 3–4B — ожидание ≤10 с/≥3 ток/с (честные ожидания NFR-5; полный гейт — TASK-111).

## 19. Стратегия тестирования
