# 02. Модель предметной области (DDD)

**Статус:** черновик v0.1 · 2026-09-24

---

## 1. Ограниченные контексты

Выделены по бизнес-возможностям SRS (не по слоям и не по таблицам). Каждый контекст = модуль кода (03) со своим доменом, своими use case'ами и своими адаптерами.

| Контекст | Отвечает за | Ключевые требования SRS |
|---|---|---|
| **Measurement (Журнал)** | ввод, валидация, хранение, правка измерений АД | FR-1, FR-2 |
| **Analytics (Аналитика)** | периоды, агрегаты, классификация по шкалам, тренды | FR-3, FR-4 |
| **AI Insight (ИИ-разбор)** | резюме, чат, guardrails, контекст для LLM | FR-5, FR-7.4 (панель — правила, не ИИ) |
| **Reporting (Отчёты)** | PDF/CSV/JSON-экспорт | FR-6.1–6.3, FR-6.7 |
| **Data Care (Забота о данных)** | копии, восстановление, импорт (пост-MVP), полное удаление | FR-6.4–6.6 |
| **Settings & Profile** | настройки, локаль, тема, профили (пост-MVP) | FR-8, FR-11 |
| **Security** | ключи, локальный вход, шифрование | FR-7.5, NFR-2 |
| **Platform Services** | обновления, сетевая политика, планировщик, уведомления, флаги | FR-7.1–7.3, FR-10, NFR-11 |

**Почему контексты именно так.** Границы проведены по языку и скорости изменения: «измерение» меняется медленно и стабильно; «аналитика» — чистая математика с жёсткими тестами (NFR-10); «ИИ» — самая летучая часть (модели, промпты, guardrails); «отчёты» и «данные» меняются под требования врачей/миграций. Смешение ИИ с журналом или аналитикой сделало бы каждую замену модели правкой ядра.

**Альтернатива:** один «модуль здоровья» + «модуль утилит». Отклонена: теряется возможность развивать/тестировать ИИ и математику независимо; нарушается высокое сцепление.

## 2. Карта контекстов

```
                    ┌────────────────┐
                    │  Measurement   │◀── пишет UI
                    └───┬───────┬────┘
             read models│       │ read models (проекции периода)
                        ▼       ▼
              ┌────────────┐  ┌──────────────┐
              │  Analytics │  │  Reporting   │
              └─────┬──────┘  └──────────────┘
                    │ проекция данных периода
                    ▼
              ┌────────────┐     ┌──────────────────┐
              │ AI Insight │────▶│ Settings&Profile │ (локаль, настройки контекста)
              └────────────┘     └──────────────────┘
   Data Care ◀── порты файловой системы ──▶ Platform Services (обновления, сеть, jobs)
        ▲
        └── Security: ключи/шифрование используются адаптерами Measurement, Data Care

Shared Kernel (минимальный): типы времени, идентификаторы, Result, коды ошибок — пакет kernel.
```

Правила интеграции: контексты общаются **только** через (а) публичные интерфейсы-порты чужого модуля, (б) read-model запросы, (в) события. Прямой импорт чужого домена запрещён (проверяется в CI, 03 §5).

**Почему read models, а не общие сущности:** Analytics и Reporting потребляют форму данных (агрегаты, списки), а не жизненный цикл измерения. Отдача сущностей наружу создала бы связанность с инвариантами журнала.

## 3. Доменная модель по контекстам

### 3.1 Measurement

**Агрегат `BpMeasurement`** (корень):

- Поля: `id`, `profileId`, `takenAt` (Instant = utc + tzOffset), `sys`, `dia`, `pulse?`, `irregularPulse`, `arm`, `note?`, `source` (manual|import).
- Инварианты (нарушение = доменная ошибка, не исключение): `sys ∈ [50,300]`, `dia ∈ [20,200]`, `pulse ∈ [20,300]` или пусто, `sys > dia`, `takenAt ≤ now(clock)`.
- **Value Objects:** `BloodPressure(sys, dia)` с инвариантом `sys > dia`; `Pulse`; `Arm(left|right)`; `Instant(utcMs, tzOffsetMin)` — «настенное время» вычисляется детерминированно.
- **Доменные сервисы (чистые функции):**
  - `TypoHeuristic.newValueVsMedian(history14d, value) → flag` (FR-1.6, порог 40 мм рт. ст.);
  - `DuplicateDetector.suspect(history, candidate) → flag` (EC-04).
- **Порт (application):** `BpMeasurementRepository` (add/update/delete/getById/listByPeriod), мутации повышают `data_version` (04 §4).

### 3.2 Analytics

- **VO:** `Period(from, to, tz)`; `Category {code, label, isHypertensionGrade?}`; `ReferenceScale` (версионируемые данные: таблица 4.1 SRS + примечание о домашних порогах).
- **Сущность `ScaleVersion`** (из хранилища справочников, FR-4.5): `code, version, source, table, active`.
- **Доменный сервис `Classifier.classify(avgSys, avgDia, scale) → Category`** — правило «по более высокой категории из двух» + приложение примечания о домашних порогах (FR-4.2).
- **Read model `PeriodStatistics`**: counts, avg/min/max/SD по СДА/ДДА/ЧСС, утро/вечер и разница, распределение категорий, пометка критических значений (FR-4.3), регулярность (FR-4.4). Всё — чистые функции над сырыми точками; утро/вечер определяется по настенному времени `Instant` (EC-06/07).
- Порог «мало данных» (`<7 измерений / <3 дней`, FR-5.4) — константа домена, общая с AI Insight через kernel-константу, чтобы правило существовало в одном месте.

**Почему аналитика — чистые функции, а не сервис с состоянием:** детерминизм и тестируемость (NFR-10, реперные примеры), тривиальный параллелизм, ноль моков в тестах.

### 3.3 AI Insight

- **Сущность `Insight` (резюме):** `id, period, kind(summary|chat), contentMd, contextHash, modelId, modelVersion, createdAt, dataVersionAtGeneration`.
  - Инвариант/политика **стейлса:** `stale = dataVersionAtGeneration < текущий dataVersion` (FR-5.7, бейдж «данные изменились»).
- **VO `AiContext`:** детерминированная проекция периода (агрегаты + серии + метаданные разрывов + заметки по настройке FR-5.5) + `contextHash = H(period, фильтры, контент, modelId, версия шаблона промпта)`.
- **Политика `GuardrailPolicy` (домен):** классы запретов (диагноз, лечение/дозы, «поставь диагноз»), требования к ответу (дисклеймер, период), реакция на критические значения (FR-5.3, FR-7.4). Политика — домен; **исполнение** (пост-фильтр текста, маршрутизация в LLM) — application/adapters (07 §4).
- **Сущности `ChatSession`, `ChatMessage`** — локальная история, очищаемая (UC-04).
- **Порты:** `LlmEngine` (load/unload/complete(stream)), `ModelStore` (list/download(resumable)/verify), `InsightRepository`, `ChatRepository`.

### 3.4 Reporting

- **VO:** `ReportSpec(period, includeAiSection=false, format)`; `ReportDocument` (результат рендера: bytes + metadata).
- **Доменная политика:** состав отчёта врача обязателен (таблица, средние, регулярность, версия приложения), ИИ-раздел — только по явному выбору и с маркировкой (FR-6.3). Отчёт собирается **только** из read models Analytics/Measurement — ИИ-тексты не могут «протечь» в клиническую часть.
- **Порты:** `PdfRenderer`, `FileSaver` (save dialog — всегда выбор пользователя).

### 3.5 Data Care

- **Сущности:** `Backup` (path, manifest{schemaVersion, appVersion, sha256, createdAt}), `RestorePlan` (проверки + предупреждение о замене, EC-25), `WipeConfirmation`.
- **Инвариант восстановления:** восстановление невозможно без проверки целостности; замена данных — только после явного подтверждения отдельным действием (UC-08/10).
- **Порты:** `DatabaseFileAccess`, `KeyVault`, `BackupCrypto`.

### 3.6 Settings & Profile

- **Сущность `Profile`** (MVP — один, seeded; FR-11 — много): `id, name, createdAt`. Существование profileId с первого дня — дешёвая страховка схемы (04 §3).
- **Сущность `Preferences`**: theme, textScale, locale, dateFormat, netConsents (updates: bool), aiSettings (modelId, includeNotes), simpleMode.
- **Инвариант:** все запросы журнала/статистики/ИИ всегда скоупятся по `profileId` на уровне репозиториев (08 §3) — «авторизация» без аккаунтов.

### 3.7 Security

- **Агрегат `VaultState`:** `keyUnwrapped`, `protection: none|passphrase`, `lastUnlockedAt`. Домен определяет политику автоблокировки и rate-limit попыток входа; механика — адаптеры (08 §2).

### 3.8 Platform Services

- **Сущности:** `UpdateCheck` (consent, lastChecked, result), `NetworkOperation` (kind, endpoint, статус — источник журнала FR-7.1), `Job` (пост-MVP расписание напоминаний, `quiet hours`).
- **Доменная политика `EgressPolicy`:** закрытый список операций; всё вне списка — отказ до уровня транспорта (08 §5).

## 4. Единый язык (выдержка)

Измерение (Measurement) · Период (Period) · Резюме (Insight) · Разбор/Чат · Шкала (Scale) · Категория (Category) · Отчёт (Report) · Копия (Backup) · Профиль (Profile) · Критическое значение (Critical Value). В коде — английские термины из этой таблицы; в UI — русские формулировки из SRS. Запрещённая клиническая лексика SRS (док 01 §8) отражена в GuardrailPolicy и в текстах UI-каталога локализации.

## 5. Соответствие Clean Architecture

```
        ┌──────────────────────────────────────────────┐
UI/IPC  │  renderer + ipc-хендлеры (адаптеры входа)    │  ← снаружи
        └───────────────┬──────────────────────────────┘
                        ▼
        ┌──────────────────────────────────────────────┐
        │ application: use cases, порты, оркестрация   │
        └───────────────┬──────────────────────────────┘
                        ▼
        ┌──────────────────────────────────────────────┐
        │ domain: сущности, VO, инварианты, политики,  │
        │ чистые сервисы                               │
        └──────────────────────────────────────────────┘
        adapters (SQLite, LLM, PDF, файлы, ОС) реализуют порты application.
```

**Правило зависимостей:** зависимости направлены внутрь; domain не импортирует ничего внешнего (даже из npm), application — только domain; adapters реализуют порты application; сборка — в composition root (03 §5). **Почему:** домен и use case'ы тестируются без Electron/SQLite/LLM (миллисекундные юнит-тесты), замена рантайма (D1a) или LLM-бэкенда не затрагивает логику. **Альтернатива** «прагматичная» (домен знает о Drizzle-типах) отклонена: экономия часов против потери главного свойства — переносимости и чистой тестируемости.
