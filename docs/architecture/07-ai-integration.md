# 07. Интеграция ИИ

**Статус:** черновик v0.1 · 2026-09-24 · реализует SRS FR-5, FR-7.4 (панель — правила, не ИИ)

---

## 1. D5: рантайм инференса

**llama.cpp через node-llama-cpp, в отдельном Electron UtilityProcess (`llm-worker`).** Целевой класс моделей: инструктивные LLM 3–4 млрд параметров, Q4, ~2–3 ГБ на диске (референс SRS 05 NFR-5). Общение main ↔ worker — MessagePort; токены стримятся сообщениями; есть `unload`.

**Почему UtilityProcess, а не worker_threads в main:** нативный крах llama.cpp убивает воркер, но не приложение (NFR-3 защищает данные, NFR-5 — отзывчивость UI); память процесса возвращается ОС при выходе/выгрузке.
**Почему не HTTP-сайдкар (llama-server):** localhost-порт → возможен prompt брандмауэра Windows, управление процессом/портами, «невидимая сеть» в журнале приватности — против духа FR-7.1.
**Почему не WebLLM/WebGPU:** целевое железо — старые ноутбуки с iGPU, где WebGPU недоступен/медлен; CPU-путь llama.cpp — единственный предсказуемый.
**Почему не облачный API:** запрещено SRS (FR-5.2) — это ядро продукта.

**Компромиссы.** CPU-скорость ограничивает размер модели (R-3): честные ожидания через NFR-5 и сообщение о слабом железе. Управление памятью: загрузка по требованию, авто-выгрузка после 5 минут простоя; во время генерации ≤4 ГБ RAM.

## 2. Компоненты модуля ai-insight

```
UI ──IPC──▶ GenerateSummary (use case)
              │ 1. AiContextBuilder (детерминированная проекция периода)
              │ 2. GuardrailPipeline: system-prompt + политика
              │ 3. LlmEngine (порт) ──▶ llm-worker ──▶ стрим токенов
              │ 4. ResponseGuard (пост-фильтр) ──▶ финальный текст
              ▼
            InsightRepository (кэш + data_version) ──▶ события ai:token/ai:status
```

## 3. AiContextBuilder — детерминированная сборка контекста

LLM получает **проекцию данных, а не «прямой доступ»**: агрегаты периода (из Analytics), серии по дням (утро/вечер), разрывы, пометки аритмии/критических значений, заметки (если `includeNotes`, FR-5.5), справочную шкалу. Формат — компактный markdown/CSV-подобный текст. `contextHash = SHA-256(period, фильтры, контент-параметры, modelId, PROMPT_TEMPLATE_VERSION)`.

**Почему без RAG/векторной базы:** объём данных периода мал (сотни строк) и помещается в контекст; встраивания добавили бы недетерминизм поиска при нулевой пользе. **Почему контекст строит код, а не LLM:** воспроизводимость и тестируемость — один и тот же период даёт байт-в-байт одинаковый контекст (проверяется тестом).

## 4. Guardrails — три эшелона (FR-5.3, FR-5.4, AC-5.1)

1. **System prompt (политика из домена):** роли, запреты (диагнозы/дозы/лечение), требование дисклеймера и указания периода, правило честного отказа при малых данных (порог из kernel), правило называть разрывы.
2. **Детерминированный префильтр:** малые данные/критические значения в периоде/вопрос о лечении — часть ответов формируется **без LLM** (отказ-шаблоны, панель срочной помощи FR-7.4). LLM не используется там, где нужен гарантированный текст.
3. **ResponseGuard (пост-фильтр):** эвристики на запрещённые паттерны (названия препаратов+дозировка, «диагноз:», инструкции «прекратите приём») → замена на отказ-шаблон + лог-событие. Промпт-инъекция из заметок: заметки включаются в контекст как «данные пользователя», политика явно отводит им роль данных; инструментов (tools/агентов) у LLM **нет вообще** — модель может только генерировать текст, ничего не исполняя и никуда не обращаясь.

**Почему post-фильтр, хотя LLM «обычно слушается»:** промпт — мягкий контроль; релизный гейт (AC-5.1 «красный набор») требует гарантий на каждой модели. **Компромисс:** эвристики дают ложные срабатывания — они заменяют ответ на безопасный отказ (fail-safe), а не молчат.

## 5. Потоки и стейлс

```
GenerateSummary(period):
  ctx = AiContextBuilder.build(period)         # детерминированно
  if (insight = repo.findByContextHash(ctx.hash)) exists
     → вернуть кэш (+ stale = insight.dataVersion < текущий data_version)
  else:
     worker.load(model) → stream tokens → ai:token → ResponseGuard → save(data_version)
```

- **Кэш-идентичность** = `context_hash` (повторный запрос того же периода без изменений данных — мгновенный).
- **Стейлс** = сравнение `data_version` (04 §4): изменение любых данных → бейдж «данные изменились, обновите резюме» (FR-5.7), без пересчёта до запроса.
- **Отмена:** `ai/cancel` → прерывание генерации в воркере + освобождение памяти (EC-16); частичный ответ не сохраняется как резюме.
- **Чат:** каждая реплика = короткая генерация с контекстом периода; история хранится локально, чистится пользователем (UC-04).

## 6. Жизненный цикл моделей (FR-5.8)

- **Реестр-манифест** (JSON в пакете приложения + обновляемый с той же гейт-моделью, что обновления): `{id, version, file, sha256, sizeBytes, languages, minRamGb, license}`.
- Загрузка: явное действие UI → прогресс-события → докачка после обрыва (EC-15) → проверка sha256 → атомарное переименование в кэш моделей (`app.getPath('userData')/models/`).
- Выбор модели: UI показывает размер/языки/мин. RAM; предупреждение при несовпадении языка модели с локалью (FR-5.9) и при железе ниже минимума (NFR-5).
- Проверка целостности при старте использования; битая модель → предложение перезагрузить (EC-15).
- Версия модели фиксируется в каждом резюме и видна в «О приложении» (NFR-10).

**Почему модель вне установщика:** лимит установки ≤200 МБ (NFR-5), согласие на 2–3 ГБ загрузки — отдельное действие (доверие), независимое обновление моделей. **Альтернатива** (комплектовать всё) отклонена: установщик 250+ МБ и «тихие» мегабайты — предательство принципа прозрачности.

## 7. Оценка качества (гейт релиза)

- **«Красный набор»** (tools/eval, AC-5.1): скриптованные вопросы + фиксированные контексты → детерминированные проверки формы ответа (отказ/шаблон срочности/дисклеймер) без семантических суждений. Ночь в CI на компактной 1B-модели (дёшево), полная модель — перед релизом вручную.
- **Золотой набор резюме:** ручная экспертная проверка на эталонных периодах при смене модели/шаблона промпта (PROMPT_TEMPLATE_VERSION бампится).
- Логи оценок — локальные артефакты CI, не продукт.

## 8. Ограничения и отказы

| Ситуация | Поведение |
|---|---|
| Модель не установлена | Экран ИИ показывает установку с объёмом; остальное приложение полноценно (FR-5.8) |
| Слабое железо | Замер при первой генерации → честное сообщение и предложение меньшей модели (NFR-5) |
| Крах воркера | main перезапускает UtilityProcess; UI — сообщение «генерация прервана, повторите»; данные не затронуты |
| Диск переполнен при загрузке | Проверка свободного места до загрузки + понятная ошибка (EC-15) |
