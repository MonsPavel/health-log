# ADR-0003: чарт-библиотека — Recharts (декларативный SVG-чарт)

**Задача:** TASK-055 · **Дата:** 2026-09-28 · **Статус:** принято
**Связанные решения:** D7 (арх. 06 §3 — состояние рендерера), арх. 06 §8 (требования к графику динамики), US-10, FR-3.2/3.5/3.6, NFR-6 (доступность), T-3.3.1 (дорожная карта)

---

## 1. Контекст

График динамики давления — главный экран понимания тренда (US-10); замена библиотеки после
написания экранов аналитики = переписывание UI-слоя. Требования арх. 06 §8: опорные линии
с подписью источника шкалы; две серии (СДА/ДДА) + отдельная ось/график ЧСС; различение
утро/вечер формой+цветом (читаемость при дальтонизме — не только цвет); агрегация
день=среднее+диапазон при >500 точках; тултипы с точными значениями и переходом к записи;
пустые состояния. Ограничения: производительность 5k точек < 1 с (§13.6); bundle ≤ 150 КБ
gzip (§13.7); SVG-путь для скринридеров и будущего PDF-экспорта (§13.8, §16); i18n-совместимость
подписей (§17); телеметрии у кандидата быть не должно (§14).

Перед решением проведён спайк (TASK-055, T-3.3.1): одинаковый прототип тренда СДА/ДДА на
трёх кандидатах из фиксированного списка дорожной карты — **visx**, **Recharts**, **ECharts** —
с замерами bundle-size (gzip), времени рендера 500/5000 точек и LOC. Прототипы реализовали
полный объём §5: 2 серии + ЧСС на правой оси, опорная линия «Порог АГ — 140 (ВОЗ)», точки
утро=круг/вечер=ромб, тултип с датой/частью суток/значениями, клик по точке → обратный вызов
`onOpenRecord(id)`, переключение агрегации день=avg+коридор min–max (500→30 точек).
Кандидаты (версии на 2026-09-28): `@visx/*` 3.12.0 (8 модульных пакетов), `recharts` 3.10.1,
`echarts` 6.1.0 (tree-shaken core + SVGRenderer). Прототипы удалены из репозитория (§20);
исходники — в истории git (коммит `41c778a`, ветка task/TASK-055).

## 2. Решение (выбранный путь)

**Recharts 3.x** — декларативный SVG-чарт из React-компонентов.

Взвешенная оценка чек-листа §13 (веса ×2, шкала 0–5, приложение А): **Recharts 79**,
visx 77, ECharts 64. Пороговые критерии: Recharts выполняет оба жёстких ограничения
(5k точек: 100,7 мс < 1 с; bundle Δ111,6 КБ gzip ≤ 150 КБ), ECharts проваливает бюджет
размера (Δ184,0 КБ > 150 КБ). Разрыв Recharts/visx (2 балла) устойчив к способу подсчёта
(грейд vs порог: 83 против 77 — приложение А.2); правило §22 (при равенстве — приоритет
критериев 6/7) не применялось — равенства нет.

Аргументы:

- **Все требования арх. 06 §8 решаются «из коробки» декларативно:** `ReferenceLine` с
  подписью источника; `YAxis yAxisId` для ЧСС; `Tooltip` с кастомным содержимым и
  `activeDot.onClick` → `onOpenRecord(id)`; range-`Area` (`dataKey => [min, max]`) для
  коридора день=min–max без ручной отрисовки.
- **React-идиоматичность (критерий 10, ×2):** график — функция от props/state; состояние
  диаграммы не покидает React. Против: ECharts — императивный `setOption` в `useEffect`
  (состояние вне React, ручные `on/off/dispose`), visx — ручная сборка шкал/осей/тултипов.
- **Минимальный LOC прототипа (критерий 9):** 258 строк против 296 (visx) и 291 (ECharts,
  где 120+ строк — stack-трюк коридора и императивная опция).
- **Чистый SVG** (критерий 8): скринридер-дружественность, стандартная сериализация для
  PDF-экспорта (TASK-067).
- **Отсутствие телеметрии подтверждено:** grep по production-бандлу на `fetch(` /
  `XMLHttpRequest` / `sendBeacon` — 0 вхождений у всех трёх кандидатов (§14).

Правила применения (фиксируются с ADR): анимации отключать (`isAnimationActive={false}`)
при >100 точках; агрегация день=avg+range — на read model (main-процесс, арх. 06 §8),
не в рендерере; графику — `role="img"` + `aria-label`, декоративные узлы — `aria-hidden`;
обязательная табличная альтернатива рядом (TASK-059, арх. 06 §7) — график ≠ контент.

## 3. Замеры спайка

Методика: esbuild 0.28.2, production-минификация, IIFE; gzip = zlib level 9. Рендер —
Chromium (Playwright), Windows 10.0.26200 x64, localhost-HTTP; `performance.now()` вокруг
монтирования компонента до отрисовки кадра (двойной `requestAnimationFrame` — пол 33,3 мс
при 60 Гц); 5 прогонов после прогрева, медиана. DOM-узлы — в контейнере бенчмарка после
рендера. Одинаковый детерминированный датасет (LCG, seed 42) во всех прототипах.

**LOC прототипа (критерий 9):** visx 296 (278 непустых) · Recharts 258 (245) · ECharts 291 (279).
Общие модули (генератор данных, харнесс, HTML, сборка) excluded — байт-в-байт одинаковы.

А.2. Чувствительность: при пороговом подсчёте критериев 6–7 (прошёл порог = 5):
Recharts 83, visx 77, ECharts 66 — ранжирование не меняется. Единственный критерий,
где visx впереди Recharts по существу, — абсолютная скорость (37,9 против 100,7 мс);
оба ≥10× ниже порога, а на рабочих объёмах (>500 точек → агрегация, 30 точек) разница
неразличима (33,3–33,4 мс у всех).

## 5. Альтернативы

1. **visx (@visx/* 3.12.0)** — низкоуровневые примитивы «собери сам»: полный контроль над
   каждым SVG-элементом, минимальный бандл (Δ34 КБ), лучший рендер на 5k. Отвергнуто при
   равном качестве результата: каждая ось/тултип/опорная линия/легенда — ручной код
   (296 LOC против 258), который надо поддерживать и тестировать; нет готового tooltip-
   позиционирования (TooltipWithBounds + бисекция своими руками). Дорожная карта допускала
   класс «visx/Recharts»; по взвешенной таблице Recharts покрывает все требования §8 без
   ручной работы. Возвращение к visx имеет смысл при появлении требований, выходящих за
   декларативную модель (нестандартные композиции, экстремальные объёмы точек без агрегации).
2. **ECharts 6.1.0** — самый функциональный движок; отвергнут по измеренным причинам:
   бюджет размера §13.7 провален даже в tree-shaken core+SVGRenderer конфигурации
   (Δ184 КБ > 150 КБ); полная сборка ~330 КБ gzip; React-интеграция — императивная обёртка
   (критерий 10: 2/5); коридор min–max — stack-трюк (критерий 4: 3/5). Сильные стороны
   зафиксированы в последствиях: progressive rendering на очень больших данных, `getDataURL`
   для PNG-экспорта, canvas-производительность — не критичны при нашем пороге агрегации 500
   точек (арх. 06 §8, FR-3.5).
3. **Ничего не выбирать (нативный SVG руками)** — не рассматривался всерьёз: воспроизводит
   путь visx с ещё большим объёмом ручного кода (оси, шкалы, тултипы, легенды), вне списка
   кандидатов дорожной карты T-3.3.1.

## 6. Компромиссы

- **+111,6 КБ gzip к рендереру (Δ к react-базелину):** в пороге §13.7, но в 3,3 раза тяжелее
  visx-конфигурации. Контроль — при каждой мажорной обнове Recharts пересобирать бандл и
  сверять дельту (воспроизводится скриптом спайка; бюджет — этот ADR).
- **Производительность per-point маркеров:** кастомный `dot` — React-элемент на точку;
  при 5000 точек рендер 100,7 мс против 37,9 у visx. Приемлемо: порог агрегации 500 точек
  (FR-3.5) делает рабочие объёмы ≤500 маркеров (33,4 мс). Регресс ловится бенчмарком спайка
  при обновлениях (см. §8).
- **Тултипы/анимации Recharts не виртуализированы:** зависание на десятках тысяч точек без
  агрегации; правило — агрегация обязательна >500 точек (уже требование арх. 06 §8), сырой
  режим длиннее года не показываем.
- **График — не контент:** Recharts-SVG не читается скринридером как данные; текстовое
  резюме тренда + табличная альтернатива (TASK-059, арх. 06 §7) обязательны — это требование
  NFR-6, а не опция.
- **Блокировка на Recharts-мажорах:** кастомные `dot`/`Tooltip`-контент опираются на
  публичный API колбэков (payload); обновления мажорной версии — с прогоном прототипа-эталона
  (§8), не «по факту выпуска».

## 7. Последствия

- **TASK-057 (экран графика)** строится на `ComposedChart`/`Line`/`Area`/`ReferenceLine`/`Tooltip`
  как в прототипе; read model отдаёт и сырые точки, и day-агрегаты (T-3.3.2), рендерер только
  переключает режим.
- **PDF-экспорт (TASK-067):** Recharts рендерит SVG ⇒ стандартная цепочка
  `XMLSerializer(svg) → canvas → PNG` без участия библиотеки; задачу это устраивает, отдельного
  серверного рендера не требуется. (У ECharts было бы `getDataURL` из коробки — преимущество
  не перевесило бюджет размера; у visx та же SVG-сериализация, что у Recharts.)
- **Пульс-график (TASK-058):** отдельный график ЧСС теми же компонентами (вторая ось
  проверена в спайке — критерий 2, 5/5).
- **A11y (NFR-6, §16):** `role="img"`+`aria-label` на чарте, `aria-hidden` на декоративных
  узлах; скрытие точек от скринридера — группировка маркеров в `aria-hidden`-слой (проверяемо
  в TASK-057); таблица-альтернатива и текстовое резюме — TASK-059.
- **i18n (§17):** подтверждено прототипами у всех трёх кандидатов — подписи осей, легенды и
  содержимое тултипов передаются параметрами/колбэками (props, `tickFormatter`, formatter-
  функции); русские строки в прототипах подавались без модификации библиотек. Каталоги
  i18n наполняются в TASK-057.
- **Дальтонизм (§8):** различение утро/вечер формой (круг/ромб) + цветом серии; легенда с
  глифами — как в прототипе.
- **§23 (коридор min–max):** не требуется — range-`Area` нативен у победителя; если когда-либо
  переезжаем на движок без range-area, stack-трюк из ECharts-прототипа — готовый рецепт (история git).
