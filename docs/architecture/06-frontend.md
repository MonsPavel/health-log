# 06. Архитектура фронтенда (Renderer)

**Статус:** черновик v0.1 · 2026-09-24

---

## 1. Состав

React 18 + TypeScript, Vite-сборка. Библиотеки UI: **Radix UI** (доступные примитивы) + **Tailwind** (токены темы). Графики: **visx/Recharts-класс** (декларативный SVG-чарт; окончательный выбор — за ADR при реализации, требования в §8). Формы — контролируемые с zod-валидацией на клиенте (зеркало контрактных схем).

**Почему Radix, а не MUI/Ant:** товарный вид самописный, а доступность (NFR-6: клавиатура, контраст, фокус) достаётся «в подарок» с безстилевыми примитивами; MUI/Ant тянули бы дизайн-систему чужого продукта. **Компромисс:** свои стили для всех примитивов — больше работы на старте.

## 2. Структура рендерера

```
src-renderer/
├─ app/                    # провайдеры, роутер, ErrorBoundary, layout
├─ features/
│  ├─ measurement/         # ввод, история
│  │  ├─ ui/               #   компоненты экранов
│  │  ├─ model/            #   zustand-сторы локального UI-состояния
│  │  └─ api/              #   хуки над IPC-клиентом (contracts)
│  ├─ dashboard/           # графики, статистика
│  ├─ ai/                  # резюме, чат, выбор модели
│  ├─ reports/             # экспорт/копии
│  ├─ settings/            # настройки, приватность
│  └─ onboarding/          # FR-9
├─ components/ui/          # дизайн-примитивы (Button, Field, Dialog…)
├─ i18n/                   # ru/en каталоги, ICU
└─ lib/                    # ipc-клиент (preload), утилиты
```

Feature-based группировка вместо слоёв: экран меняется целиком, фича не импортирует внутренности другой фичи (общее — только `components/ui` и `lib`).

## 3. Управление состоянием (D7)

Три категории, без пересечений:

| Категория | Где живёт | Инструмент |
|---|---|---|
| **Истина (данные)** | SQLite в главном процессе | — (рендерер не хранит истину) |
| **Кэш серверных данных** (списки, статистика) | рендерер | **TanStack Query** (ключи = read-model запросы; инвалидация по событиям `measurement:changed`, `data:versionBumped`) |
| **UI-состояние** (открытые диалоги, черновик формы, активный период) | рендерер | **Zustand** (по фичам); черновик ввода сохраняется в zustand persist → восстановление после краша (NFR-3) |

**Почему так.** Классическая проблема локальных приложений — дублирование истины в сторе. Здесь единственный источник — БД; Query — только кэш с явной инвалидацией; Zustand — лишь эфемерное UI. **Альтернативы:** Redux Toolkit (лишний церемониал для приложения такого размера), «всё в Zustand» (ручная инвалидация = рассинхрон с БД), URL-состояние периода (частично используется — период в query-параметре роутера).

**Поток мутации:** форма → IPC-команда → подтверждение main → ответ/событие → `queryClient.invalidateQueries`. Оптимистичные обновления для ввода не нужны (запись ~миллисекунды); для удаления — оптимистично с откатом при ошибке.

## 4. Роутинг и каркас экранов

HashRouter (совместим с file://-подобной загрузкой). Каркас: Sidebar (Журнал · Динамика · ИИ · Отчёты · Настройки) + контент. Маршруты несут минимум состояния (`/dashboard?period=30d`). Модальности — Radix Dialog с ловушкой фокуса. Экран блокировки (Security) — вне роутера, оверлеем при событии `lock:engaged`.

## 5. Форма ввода (сердце продукта, US-1)

- Автофокус, цифровые кнопки-клавиатура (FR-1.4), Enter = сохранить, рука/флаги запоминают последнее значение.
- Валидация: мгновенная клиентская (zod) + обязательная серверная (домен) — клиентская только для UX, истиной считается ответ main.
- Диалоги «Проверьте значения» и «вероятная опечатка» — по флагам из ответа `measurements/add` (EC-03, FR-1.6): логика в main, UI только представляет решение пользователю.

## 6. Интернационализация (FR-8.3, FR-5.9)

- **react-i18next + ICU**: каталоги `i18n/ru/*.json`, `en/*.json`; русские тексты — источник, переводы — пост-MVP.
- Ошибки IPC приходят ключами (`messageKey` + params) — рендерер локализует единообразно с UI.
- Формат дат/чисел — Intl API по выбранной локали (FR-8.4).
- Язык = язык ИИ-ответов: выбор модели проверяет языковую совместимость (метаданные модели, 07 §6) и предупреждает.
- CI-проверка: отсутствие ключа в любом каталоге = ошибка сборки.

## 7. Доступность (NFR-6)

- Rem-масштабирование: три размера текста (FR-8.2) — токены Tailwind в rem, вёрстка без фикс. высот; «очень крупный» режим проверяется E2E-снапшотами (AC-7.2).
- Темы light/dark/system (FR-8.1) через CSS-переменные + `prefers-color-scheme`; контраст AA зафиксирован в токенах и проверяется axe-правилами.
- Клавиатура: полная навигация, видимый фокус, Radix-примитивы; горячие клавиши ввода (Ctrl+N → новая запись).
- Графики: обязательная альтернатива «таблица» рядом (переключатель) — служит и a11y (скринридер), и персоне П5 (врач). Каждому чарту — текстовое резюме тренда.
- Тесты: axe-core в E2E на всех маршрутах; ручной NVDA-чеклист перед релизом (автоматизация скринридеров недостоверна).

## 8. Требования к графику динамики

Опорные линии с подписью источника шкалы (FR-3.2), различение утро/вечер (форма/цвет + легенда, читаемая при дальтонизме — не только цвет), агрегация день=среднее+диапазон при >500 точках (FR-3.5, расчёт series на main), тултипы с точными значениями и ссылкой на запись, пустые состояния с подсказкой (FR-3.6).

## 9. Обработка ошибок в UI

- `ErrorBoundary` на каркас и на каждую фичу: падение чата ИИ не роняет журнал.
- Все IPC-ошибки → тост/панель с локализованным текстом + действие («Повторить», «Открыть настройки ИИ»); никаких «Error: undefined» (NFR-12).
- Критические сценарии (БД повреждена, миграция не прошла) — полноэкранные состояния восстановления, единственные показывающие техническую информацию (по явному раскрытию для диагпакета).
