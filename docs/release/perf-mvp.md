## 7. Размер установщика — BLOCKED (среда, не провал цели)

**Причина**: Smart App Control машины-сборщика в режиме enforcement
(`VerifiedAndReputablePolicyState=1`) блокирует запуск свежесобранного
неподписанного установщика. Конвейер electron-builder 26 на win32 после сборки
NSIS-стаба запускает его (`WineVm.execWine` → прямой exec Setup.exe — извлечение
uninstaller'а для подписи, app-builder-lib NsisTarget.computeScriptAndSignUninstaller);
Windows Code Integrity убивает процесс:

```
Event 3077/3033 (Microsoft-Windows-CodeIntegrity/Operational, 2026-10-03 23:11:54):
Code Integrity determined that a process (node.exe) attempted to load
\...\apps\desktop\dist-perf\Health Log Setup 0.0.0.exe that did not meet the
Enterprise signing level requirements or violated code integrity policy
```

→ NSIS-цель аварийна (`spawn UNKNOWN`), на диске остаётся обрезанный стаб
«Health Log Setup 0.0.0.exe» 168 118 байт (0.2 МБ) — НЕ замер цели (size-audit
его формально «принял», вердикт 0.2 МБ недействителен).

**Фактура доступного (финальный гейт — в CI `release.yml`/на машине без SAC-блока):**

| Артефакт | Размер |
|---|---|
| `@hldesktop-0.0.0-x64.nsis.7z` (сжатый пакет app-builder) | **164.5 МБ** (172 494 368 байт) |
| win-unpacked (справочно; NSIS-несжат) | 552.3 МБ |
| Компоненты win-unpacked | electron-runtime 319.0 (57.8%) / resources 164.5 (29.8%) / locales 48.3 (8.7%) / native *.node 20.5 (3.7%) |

Ожидание по прецеденту TASK-034 (установщик 120 МБ при win-unpacked 443 МБ):
~150–170 МБ < 200 МБ — оценка по коэффициенту сжатия, НЕ замер; не заполнять
вердикт PASS до реального замера установщика.

Обход рассмотрен и отвергнут как вне §5: кастомный NSIS-скрипт
(`resources/installer.nsi`) пропускает запуск Setup.exe, но меняет релизную
конфигурацию сборки/подписи (uninstaller не извлекается/не подписывается
стандартным путём) — риск для TASK-104/107 без задачи-владельца.

## 8. Отклонения методики и среды (честно, сводка)

1. **perf-mark §4 не добавлялся** (§6 «Изменить: нет»): первый осмысленный кадр —
   DOM-селектор `dashboard-welcome` через e2e-хелпер; t0 включает проводку
   Playwright (в запас метрики). Минимальное сопутствующее изменение всё же
   потребовалось в самом хелпере: опция `executablePath` (packaged-запуск через
   e2e-хелпер, §4/§5) — tests/e2e/helpers/launch.ts, покрыто юнит-тестом.
2. **Каталог сборки `dist-perf`** вместо `dist`: штатный `dist/win-unpacked.tmp`
   (остаток прошлой сборки) залочен внешним процессом (вотчер рабочего стола
   ZCode.exe, Restart Manager; file от 27.09) — electron-builder падал EBUSY на
   его очистке. Выход перенаправлен CLI-оверрайдом
   `-c.directories.output=dist-perf`; electron-builder.yml НЕ менялся;
   check-size запущен с `--dist dist-perf`. Замеры запускались с
   `--exe apps/desktop/dist-perf/win-unpacked/Health Log.exe` (дефолт скрипта
   указывает на dist/win-unpacked).
3. **Прогрев старта**: первый запуск exe после сборки — 7917.9 мс (антивирусный
   скан свежих файлов); в медиану ×5 не входит (прогрев §13 062).
4. **ИИ — движко-уровень, не UI-уровень**: протокол метки §20.4 измеряет
   генерацию движка (load → complete → стрим), как и база-лайн 077 —
   сопоставимость чисел; накладные расходы UI/каналов (сотни мс) в замер не
   входят и запасу к целям (×340/×400) несущественны.
5. **Пять замеров выполнены полностью; шестой (размер установщика) — BLOCKED
   средой SAC** (§7): продолжение честно невозможно на этой машине; гейт
   подлежит снятию в CI.
