# 10. Объём MVP, пост-MVP и будущие функции

**Статус:** черновик v0.1 · 2026-09-24 · ветка `docs/planning`

---

## 1. Объём MVP

Одна фраза: **«Измерил → ввёл → увидел динамику → понял простым языком → принёс врачу PDF» — полностью локально, на Windows, по-русски.**

### Входит

| Область | Состав | Требования |
|---|---|---|
| Ввод измерений | СДА/ДДА (обяз.), ЧСС, рука, флаг «неровный пульс», заметка; валидация (жёсткая + мягкая); детектор опечаток; ввод задним числом; ввод ≤15 с | FR-1.1–1.7 |
| История | Список по дням, фильтры по периоду/руке/заметкам, поиск, правка и удаление с подтверждением | FR-2.1–2.4 |
| Графики | Тренд СДА/ДДА/ЧСС, периоды 7д/30д/90д/всё, опорные линии с источником, различение утро/вечер, агрегация при больших объёмах, пустые состояния | FR-3.1–3.6 |
| Статистика | Средние/мин/макс/СКО, утро/вечер, распределение по категориям, пометка критических значений, регулярность; шкала ESC/ESH с примечанием о домашних порогах | FR-4.1–4.5 |
| Локальный ИИ | Резюме периода + чат; guardrails (без диагнозов/доз); честный отказ при малых данных; прозрачность контекста; дисклеймер; «Стоп»/повтор; выбор и загрузка модели с докачкой; работа без модели | FR-5.1–5.10 |
| Данные | CSV-экспорт, JSON-слепок, PDF-отчёт для врача, ручная зашифрованная копия и восстановление, полное удаление | FR-6.1–6.5, FR-6.7 |
| Приватность/безопасность | Экран «Приватность» с журналом; белый список сети; запрет телеметрии; панель критических значений; шифрование в покое; опц. пароль на запуск | FR-7.1–7.5, NFR-1, NFR-2 |
| Настройки/доступность | Темы, размеры текста, формат даты, клавиатурная доступность, контраст AA | FR-8.1–8.6, NFR-6 |
| Онбординг | 3 шага ≤2 минут; обучающие пустые состояния; «простой режим» по умолчанию | FR-9.1–9.3 |
| Платформа | Windows 10/11 x64; русский язык; реф. железо A — полный функционал без ИИ, Железо B — с ИИ в целях NFR-4/5 | NFR-4, NFR-5, NFR-7, NFR-8 |

### Не входит в MVP (сознательно, с причиной)

| Исключено | Причина | Куда |
|---|---|---|
| Напоминания-уведомления | MVP и так велик; привычку сначала держит UX ввода | Пост-MVP, кандидат №1 (OQ-7) |
| Профили | Ядро ценности — «свой дневник» | Пост-MVP |
| Импорт CSV | Нет базы пользователей со старыми данными | Пост-MVP |
| Приём лекарств (факты) | Заметка покрывает базу; структурирование — отдельная модель данных | Пост-MVP (OQ-11) |
| Bluetooth-тонометры, импорт из Apple Health/Google Fit, фото тонометра | Дорогие интеграции, не влияют на ядро ценности | Future |
| Английский и другие языки | Качество RU важнее покрытия | Пост-MVP |
| macOS/Linux как обязательные платформы | Концентрация усилий | Пост-MVP (сборки «желательные») |
| Прямая печать на принтер | PDF + системный просмотрщик покрывает сценарий | Не планируется до спроса |
| Телеметрия и аналитика любого рода | Противоречит BG-2 | Никогда (без ревизии видения) |

### Критерии готовности MVP (Definition of Done)

1. Все AC доков 08 проходят на релизной сборке, включая сетевой аудит (AC-4.1) и «красный набор» ИИ (AC-5.1) на каждой заявленной модели.
2. Производительность: цели NFR-4 на Железе A, NFR-5 на Железе B — подтверждены замерами.
3. Надёжность: тест отключения питания в момент записи — ноль потерянных сохранённых записей (NFR-3).
4. Юридические формулировки: дисклеймеры и тексты панелей проверены на соответствие доку 01 §8; юридическая консультация по позиционированию — перед публичным распространением (R-1).
5. Документация пользователя: установка, копии/восстановление, настройка ИИ, экран «Приватность».

## 2. Объём после MVP (приоритизированный)

1. **Напоминания** (FR-10) — крупнейший резерв привычки для П1/П3.
2. **Профили** (FR-11) — открывает П4; изоляция данных, экспорт по профилю.
3. **Импорт CSV** — миграция с других приложений и таблиц.
4. **Структурированные теги самочувствия и факты приёма лекарств** — усиливает статистику и ИИ-корреляции («давление на фоне пропуска препарата»).
5. **Недельные ИИ-отчёты** и проактивные наблюдения аномалий (выбросы, разрывы, разница рук) — из «спрашиваемого» в «предлагаемое».
6. **Английская локализация;** сборки macOS/Linux до статуса «поддерживаемых».
7. **Стандарт классификации в настройках** (ESC/ESH ↔ AHA) — ответ на OQ-6.

## 3. Будущие функции (горизонт)

- **Внешние источники данных (FR-12):** импорт из Apple Health / Google Fit / Samsung Health (файлы), BLE-тонометры, распознавание фото тонометра на устройстве.
- **Расширение health-log:** пульс в покое, вес, сон, глюкоза — отдельные типы показателей в одном журнале с кросс-корреляциями («давление vs вес») и единым ИИ-объяснением.
- **Голосовой ввод и озвучивание** — доступность (П3) и ввод с занятыми руками.
- **ABPM-импорт** — загрузка суточного мониторирования из клиники и сравнение с домашними измерениями.
- **Семейный обмен** — контролируемая передача отчёта родственнику/врачу без облака (например, шифрованный файл).
- **Предиктивные тренды** — только после юридической проработки (риск R-1 резко растёт).
- **Открытый формат данных и плагины** — экосистема вокруг мастер-формата FR-6.2.

## 4. Правило изменения объёма

Любое изменение MVP (добавить/убрать) — через ревизию этого SRS с записью в историю изменений README. Это рабочая защита от R-5 (расползание объёма).
