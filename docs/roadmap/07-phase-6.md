# Фаза P6 — Безопасность, приватность, надёжность

**Веха фазы:** опциональный пароль/блокировка, обновления только по согласию, экран «Приватность» с журналом, устойчивость к сбоям подтверждена тестами. После этой фазы продукт готов к упаковке в публичный релиз (P7).

---

## Epic 6.1 — Локальный вход и блокировка

**T-6.1.1 (L) Двойная обёртка ключа: passphrase + Argon2id (FR-7.5)**
- **Цель:** при включении пароля: `KEK = Argon2id(passphrase, salt)` поверх safeStorage-обёртки; set/change/remove passphrase; соли и параметры — в файле vault.
- **Почему:** NFR-2: забыли пароль — данные невосстановимы; механика арх. 08 §2.
- **Объём:** адаптер vault-расширение + тесты: верный/неверный пароль, смена пароля, потеря salt.
- **Зависимости:** T-1.2.2.
- **Файлы:** `src/main/modules/security/adapters/key-vault*`.
- **Проверка:** интеграционные тесты roundtrip; замер времени Argon2id (~0,5 с — UX-приемлемо).
- **AC:** смена пароля не требует перешифрования БД; неверный пароль → `VAULT/WRONG_PASSPHRASE`, БД не открывается.
- **Риски:** параметры Argon2id на слабых машинах — калибровка по времени, не константой.
- **Сложность:** L (2,5–4 ч)

**T-6.1.2 (M) Use cases vault + rate limit + события**
- **Цель:** unlock/lock/set-passphrase; экспоненциальная задержка после неудач; события `lock:engaged/required`; автоблок по простою (настройка).
- **Зависимости:** T-6.1.1.
- **Файлы:** `src/main/modules/security/application/*`.
- **Проверка:** юнит-тесты rate limit (фейковые часы); интеграция блокировки с состоянием БД.
- **AC:** 5 неудач → нарастающая задержка; lock закрывает доступ до unlock; unlock происходит до первого обращения к БД после запуска.
- **Риски:** deadlock «заблокированы собственные фоновые job'ы» — планировщик уважает locked-состояние.
- **Сложность:** M (1,5–2,5 ч)

**T-6.1.3 (M) UI: экран блокировки + настройка защиты**
- **Цель:** оверлей блокировки (пароль → unlock), настройка «включить пароль» с предупреждением о невосстановимости (NFR-2), таймер автоблока.
- **Зависимости:** T-6.1.2.
- **Файлы:** `src-renderer/features/security/*`.
- **Проверка:** e2e: включить пароль → перезапуск → экран блокировки → unlock.
- **AC:** предупреждение о необратимости показывается до включения; автоблок настраивается (5/15/60 мин/выкл).
- **Риски:** нет.
- **Сложность:** M (1–2 ч)

## Epic 6.2 — Обновления (по согласию)

**T-6.2.1 (M) electron-updater за согласием (D15, NFR-11)**
- **Цель:** проверка обновлений — только при выданном согласии (первый запуск + экран «Приватность»), через EgressGateway; журнал каждой проверки; событие `update:available`.
- **Почему:** «даже проверка обновлений — сетевой след» (арх. NFR-11); BG-2.
- **Объём:** интеграция updater → gateway-модель on-demand (не фоновый авточек), согласие в онбординге-настройках.
- **Зависимости:** T-5.1.1.
- **Файлы:** `src/main/modules/platform-services/updates*`.
- **Заметки:** updater настроен на GitHub Releases generic provider; подпись появится в P7 — dev проверяет на unpublished feed (заглушка).
- **Проверка:** тест-мок: без согласия ни одного сетевого вызова; с согласием — журнал записи.
- **AC:** AC-4.1-поведение подтверждено тестом; согласие отзываемо.
- **Риски:** electron-updater сам инициирует сеть — использовать ручной режим download/update без автопроверок.
- **Сложность:** M (1,5–2,5 ч)

**T-6.2.2 (S) UI обновлений**
- **Цель:** индикатор «доступна версия X → скачать/установить с подтверждением»; бета-канал в настройках.
- **Зависимости:** T-6.2.1.
- **Файлы:** `src-renderer/features/settings/ui/updates*`.
- **AC:** установка только по явному действию; отмена на любом шаге безопасна.
- **Риски:** нет.
- **Сложность:** S (0,5–1 ч)

## Epic 6.3 — Экран «Приватность»

**T-6.3.1 (S) Хендлеры privacy/journal + consents**
- **Цель:** каналы: журнал network_event (последние N, фильтр), текущие согласия, переключение.
- **Зависимости:** T-5.1.1, T-6.2.1.
- **Файлы:** `src/main/modules/platform-services/application/privacy*`, `packages/contracts/src/privacy*`.
- **Проверка:** интеграционные тесты.
- **AC:** журнал совпадает с фактическими операциями гейтвея (общий источник — network_event).
- **Риски:** нет.
- **Сложность:** S (0,5–1 ч)

**T-6.3.2 (M) Экран «Приватность»**
- **Цель:** список всех возможных сетевых операций с состояниями, переключатели согласий, лента последних активностей в реальном времени (`net:activity`) (FR-7.1).
- **Почему:** US-33; проверяемая честность — витрина BG-2.
- **Зависимости:** T-6.3.1.
- **Файлы:** `src-renderer/features/settings/ui/privacy*`.
- **Проверка:** ручной прогон: скачать модель/проверить обновления → записи появляются в ленте.
- **AC:** список операций == белому списку EgressPolicy (сверка в e2e); отключение согласия мгновенно запрещает операцию.
- **Риски:** нет.
- **Сложность:** M (1–2 ч)

## Epic 6.4 — Устойчивость и диагностика

**T-6.4.1 (M) Startup self-check + «О приложении»**
- **Цель:** при старте: integrity-check БД, версия схемы, наличие ключа, состояние воркера, версии приложения/шкал/модели → экран «О приложении»/диагностика (NFR-3, NFR-10).
- **Зависимости:** P1.2, P5.2.
- **Файлы:** `src/main/app/selfcheck*`, `src-renderer/features/settings/ui/about*`.
- **Проверка:** тесты: повреждённая БД обнаруживается; все версии отображаются.
- **AC:** любой сбой self-check виден пользователю текстом, не молча.
- **Риски:** integrity-check время на больших БД — PRAGMA quick_check.
- **Сложность:** M (1–2 ч)

**T-6.4.2 (M) Восстановление при повреждении (EC-14)**
- **Цель:** повреждение/провал миграции → полноэкранное состояние: объяснение, выбор копии → restore (P4), повтор; техническая информация — по явному раскрытию.
- **Зависимости:** T-6.4.1, T-4.3.2.
- **Файлы:** `src-renderer/app/recovery*`, `src/main/app/bootstrap*`.
- **Проверка:** e2e с преднамеренно испорченным файлом БД (тестовый сценарий).
- **AC:** из «мёртвого» состояния пользователь восстанавливается из копии без консоли; AC EC-14 выполнен.
- **Риски:** нет.
- **Сложность:** M (1,5–2 ч)

**T-6.4.3 (M) Крэш-тест потери питания (NFR-3)**
- **Цель:** скрипт: цикл вставок → kill процесса/эмуляция отключения → перезапуск → инвариант: все зафиксированные записи целы, схема не повреждена; счётчик data_version согласован.
- **Почему:** главный страх пользователя R-4; подтверждение для DoD (SRS 10 §4).
- **Зависимости:** P1.2.
- **Файлы:** `tools/scripts/crash-test*`.
- **Проверка:** локальный прогон ≥10 итераций; включение в тег-пайплайн (P7).
- **AC:** ноль потерянных зафиксированных записей во всех прогонах; WAL-файлы после сбоя переигрываются корректно.
- **Риски:** Windows-специфика kill — использовать taskkill /F и Kill-on-close паттерны.
- **Сложность:** M (1,5–2,5 ч)

**T-6.4.4 (S) Диагностический пакет (NFR-12)**
- **Цель:** по явному действию: zip логов (без PHI — редакция уже в логгере), версий, self-check-статусов; предпросмотр содержимого перед сохранением.
- **Зависимости:** T-0.2.4, T-6.4.1.
- **Файлы:** `src/main/modules/platform-services/diag*`, settings UI.
- **Проверка:** тест содержимого пакета (grep на поля измерений — пусто).
- **AC:** пакет можно безопасно приложить к issue; пользователь видит содержимое до сохранения.
- **Риски:** нет.
- **Сложность:** S (0,5–1 ч)

**Веха P6:** безопасность и приватность — не декларации, а работающие экраны и пройденные тесты; продукт переживает крахи и восстанавливается.
