# Фаза P0 — Фундамент и конвейер

**Веха фазы:** пустое приложение собирается, запускается, CI зелёный; каркас (контракты, ошибки, события, логи, i18n) готов принять фичи.

---

## Epic 0.1 — Монорепо и качество кода

**T-0.1.1 (M) Инициализация pnpm-монорепо**
- **Цель:** рабочий скелет: `apps/desktop`, `packages/{kernel,contracts,scales-data}`, корневые конфиги.
- **Почему:** структура из арх. 03 §3; границы пакетов дешевле задать до первого кода фич.
- **Объём:** pnpm-workspace, корневой package.json, пустые пакеты со скриптами build/test, .gitignore, engines/node version pin.
- **Зависимости:** нет.
- **Файлы:** `pnpm-workspace.yaml`, `package.json`, `packages/*/package.json`.
- **Заметки:** имена пакетов `@hl/*`; никакой бизнес-логики в этой задаче.
- **Проверка:** `pnpm install` и сборка всех (пустых) пакетов.
- **AC:** workspace устанавливается из чистого клона по инструкции README за ≤10 мин.
- **Риски:** конфликт версий Node/pnpm — фиксируется engines.
- **Сложность:** M (1–2 ч)

**T-0.1.2 (M) Единый TypeScript-конфиг**
- **Цель:** strict TS для всех пакетов без дублирования настроек.
- **Почему:** типовая строгость — дешёвая защита контрактов (D6).
- **Объём:** base tsconfig + extends в пакетах; strict, noUncheckedIndexedAccess, moduleResolution bundler; сборка пакетов через tsup/tsc.
- **Зависимости:** T-0.1.1.
- **Файлы:** `tsconfig.base.json`, `packages/*/tsconfig.json`.
- **Заметки:** решения о project references — минимальные; главное — один источник истины настроек.
- **Проверка:** сборка всех пакетов при strict.
- **AC:** intentionally-небезопасный код (`any`, implicit index access) не компилируется.
- **Риски:** трения strict с Electron-типами — изолировать в отдельные d.ts.
- **Сложность:** M (1–2 ч)

**T-0.1.3 (M) ESLint + правила границ + Prettier**
- **Цель:** линтер, механически запрещающий нарушения архитектуры (арх. 03 §4).
- **Почему:** границы монолита без автоматической проверки не существуют (01 §4).
- **Объём:** eslint flat config; eslint-plugin-boundaries; правило «renderer без node builtins», «domain без внешних импортов»; prettier; husky/lint-staged (опционально).
- **Зависимости:** T-0.1.2.
- **Файлы:** `eslint.config.*`, `.prettierrc`.
- **Заметки:** правила должны падать на заведомое нарушение — проверяем тестом правила.
- **Проверка:** временный файл-нарушитель → красный lint; удалён → зелёный.
- **AC:** нарушение границы = ошибка сборки, не предупреждение.
- **Риски:** ложные срабатывания правил границ — тюнинг зон в конфиге.
- **Сложность:** M (1–2,5 ч)

**T-0.1.4 (M) Vitest монорепо**
- **Цель:** единый быстрый тестовый рантайм с merged coverage.
- **Почему:** основа пирамиды тестирования (арх. 10 §1) — юнит-тесты домена без Electron.
- **Объём:** vitest в корне + пер-пакетные конфиги, coverage provider v8, порог отчёта (не гейт до P1).
- **Зависимости:** T-0.1.2.
- **Файлы:** `vitest.workspace.ts`, `packages/kernel/src/**/*.test.ts`.
- **Заметки:** node-окружение по умолчанию; jsdom — только рендереру позже.
- **Проверка:** демо-тест в kernel зелёный, coverage-отчёт собирается.
- **AC:** `pnpm test` запускает все пакеты одним вызовом.
- **Риски:** нет значимых.
- **Сложность:** M (1–1,5 ч)

**T-0.1.5 (S) dependency-cruiser**
- **Цель:** проверка матрицы зависимостей арх. 03 §4 как отдельный гейт.
- **Почему:** eslint-boundaries — про зоны файлов, cruiser — про пакеты/направления; дублирование намеренное (две сети безопасности).
- **Объём:** `.dependency-cruiser.cjs` с правилами из матрицы; npm-script `depcruise`.
- **Зависимости:** T-0.1.1.
- **Файлы:** `.dependency-cruiser.cjs`, `package.json` (script).
- **Проверка:** фиктивная связь `renderer→node:fs` валит проверку.
- **AC:** `depcruise` зелёный на корректном графе, красный на тестовом нарушении.
- **Риски:** нет.
- **Сложность:** S (0,5–1 ч)

**T-0.1.6 (M) Пакет kernel: Result, AppError, Instant, Clock**
- **Цель:** базовые примитивы домена: `Result<T,E>`, `AppError{code,i18nKey,params}`, `Instant(utcMs,tzOffsetMin)`, порт `Clock`.
- **Почему:** на этом стоят ошибки (05 §2), время (04 §2) и тестируемость (02 §5).
- **Объём:** типы + минимальные утилиты (wallTime, formatDate для Intl), без зависимостей.
- **Зависимости:** T-0.1.2.
- **Файлы:** `packages/kernel/src/*`.
- **Заметки:** Instant — VO с методами wall-clock; никаких `Date.now()` вне Clock.
- **Проверка:** юнит-тесты Instant: DST, переходы через полночь, отрицательные смещения (EC-06/07).
- **AC:**(property) любая пара utc+offset даёт стабильное настенное время; сериализация/парсинг симметричны.
- **Риски:** переусложнение примитивов — держать минимальными.
- **Сложность:** M (1,5–2 ч)

## Epic 0.2 — Каркас Electron-приложения

**T-0.2.1 (M) Запуск Electron + React (безопасно)**
- **Цель:** окно с React из Vite (dev-сервер) и из собранных файлов (prod); contextIsolation+sandbox включены.
- **Почему:** фундамент рендерера с моделью безопасности 08 §4 с первого дня.
- **Объём:** main bootstrap, BrowserWindow, vite-сборка рендерера, preload-заглушка.
- **Зависимости:** T-0.1.1.
- **Файлы:** `apps/desktop/src/main/app/*`, `src-renderer/*`.
- **Проверка:** ручной запуск dev и prod-сборки рендерера.
- **AC:** окно открывается; в рендерере недоступны Node-API (проверка в консоли).
- **Риски:** Vite+Electron интеграция — взять проверенный шаблон, не изобретать.
- **Сложность:** M (1,5–2 ч)

**T-0.2.2 (M) Preload-мост и конверты IPC**
- **Цель:** типизированный вызов `api.channel(dto) → ApiResult<T>` через contextBridge; конверты из contracts (арх. 05 §2).
- **Почему:** единственный канал UI↔логики; форма ошибок и валидация zod закладываются сейчас.
- **Объём:** пакет contracts: тип конверта, ping-канал, zod-схема; preload-обёртка; обработчик в main.
- **Зависимости:** T-0.1.2, T-0.2.1.
- **Файлы:** `packages/contracts/src/*`, `src/main/ipc/*`, `src-renderer/lib/ipc*`.
- **Заметки:** маппинг исключений в `APP/INTERNAL` уже на этом каркасе.
- **Проверка:** unit-тест маппера; ручной ping из UI.
- **AC:** ошибка хендлера приходит в UI как структурированный AppErrorDto, не как исключение.
- **Риски:** сериализация больших payload — зафиксировать лимиты в контракте.
- **Сложность:** M (1,5–2 ч)

**T-0.2.3 (M) Шина событий + broadcast в рендерер**
- **Цель:** типизированный EventBus в main (арх. 01 §5) и пересылка подписчикам UI.
- **Почему:** инвалидация кэшей, стейлс, lock, net-журнал — всё на этом механизме.
- **Объём:** `shared/eventbus` (on/off/emit, типы), мост `main→webContents.send`, hook подписки в рендерере.
- **Зависимости:** T-0.2.2.
- **Файлы:** `src/main/events/*`, `src-renderer/lib/events*`.
- **Проверка:** тест: emit в main → callback в renderer (интеграционный мини-тест).
- **AC:** событие `data:versionBumped` доходит до UI; отписка не течёт.
- **Риски:** утечки подписчиков при закрытии окна — снять подписки в did-close.
- **Сложность:** M (1–2 ч)

**T-0.2.4 (S) Логгер с редакцией PHI**
- **Цель:** pino в ротируемые файлы; сериализатор вырезает измерения/заметки/чат (NFR-12).
- **Почему:** логи без PHI — разрешение на диагпакет и issues.
- **Объём:** обёртка logger с категориями, ротация, redact-схема.
- **Зависимости:** T-0.2.1.
- **Файлы:** `src/main/shared/logger*`.
- **Проверка:** тест: логирование объекта с `sys/dia/note` — в файле полей нет.
- **AC:** правило «PHI не попадает в лог» закреплено тестом-контрактом логгера.
- **Риски:** нет.
- **Сложность:** S (0,5–1 ч)

**T-0.2.5 (M) Глобальная обработка ошибок**
- **Цель:** uncaughtException/unhandledRejection в main, ErrorBoundary в renderer, единый UX ошибок.
- **Почему:** NFR-12 с первого дня; никакой «сырой» ошибки до пользователя.
- **Объём:** хендлеры + безопасный диалог; ErrorBoundary каркаса; тост-компонент.
- **Зависимости:** T-0.2.2, T-0.2.4.
- **Файлы:** `src/main/app/*`, `src-renderer/app/*`.
- **Проверка:** искусственный крах main-хендлера и рендер-компонента.
- **AC:** приложение переживает обе ошибки; в логе — причина; в UI — локализованный текст с кодом.
- **Риски:** зацикление диалогов — guard на повторные краши.
- **Сложность:** M (1–2 ч)

**T-0.2.6 (S) Single-instance lock**
- **Цель:** второй запуск активирует существующее окно (EC-24).
- **Почему:** два процесса на одном SQLCipher-файле — недопустимы.
- **Объём:** requestSingleInstanceLock + фокус существующего окна.
- **Зависимости:** T-0.2.1.
- **Проверка:** ручной запуск дважды.
- **AC:** второе приложение не появляется, окно на переднем плане.
- **Риски:** нет.
- **Сложность:** S (0,5 ч)

**T-0.2.7 (M) Каркас UI: роутер, layout, темы, i18n-инфраструктура**
- **Цель:** Sidebar-каркас с заглушками экранов, тема light/dark/system, react-i18next с каталогом `ru`, Intl-утилиты дат.
- **Почему:** i18n и темы с первого экрана = нет ретрофита (TD-4); карточки персон ждут крупный режим позже, токены — сейчас.
- **Объём:** HashRouter, layout, ThemeProvider (CSS-переменные), i18n-init, формат дат через Intl (FR-8.4).
- **Зависимости:** T-0.2.1.
- **Файлы:** `src-renderer/app/*`, `src-renderer/i18n/*`, `components/ui/*` (минимум).
- **Проверка:** переключение темы, замена текста через каталог.
- **AC:** ни одной строки-литерала в JSX — только ключи; CI-скрипт проверки ключей добавлен.
- **Риски:** нет.
- **Сложность:** M (1,5–2,5 ч)

## Epic 0.3 — CI-конвейер

**T-0.3.1 (M) PR-пайплайн GitHub Actions**
- **Цель:** на каждый PR: install (кэш pnpm) → lint → typecheck → depcruise → test → build рендерера.
- **Почему:** зелёный main = всегда собираемый продукт (арх. 10 §3).
- **Объём:** workflow, кэш, артефакты отчётов; ubuntu-runner (Electron-тесты окна пока не нужны).
- **Зависимости:** T-0.1.3, T-0.1.4, T-0.1.5.
- **Файлы:** `.github/workflows/pr.yml`.
- **Проверка:** PR с нарушением каждого шага — красный.
- **AC:** время прогона ≤5 мин на пустом проекте.
- **Риски:** медленный кэш Electron — использовать cache-экшены.
- **Сложность:** M (1–2 ч)

**T-0.3.2 (S) Конвенции разработки (CONTRIBUTING)**
- **Цель:** короткий документ: как собрать, как тестировать, как оформлять PR, Definition of Done задачи.
- **Почему:** соло ≠ безпроцессно; правила карты (roadmap README §Правила) должны жить в репо.
- **Объём:** `CONTRIBUTING.md` + ссылки из README.
- **Зависимости:** T-0.3.1.
- **Файлы:** `CONTRIBUTING.md`.
- **AC:** новый разработчик (или ты через полгода) собирает проект по документу без вопросов.
- **Риски:** нет.
- **Сложность:** S (0,5 ч)

**Веха P0:** PR-пайплайн зелёный; приложение запускается с каркасом безопасности/ошибок/логов; kernel с тестами готов принять домен.
