# Фаза P5 — Локальный ИИ

**Веха фазы:** резюме периода и чат работают на локальной модели; guardrails проходят «красный набор»; приложение полноценно без модели. Самая рискованная фаза (R-3) — порядок внутри строго: сеть → воркер → модели → guardrails → фичи → eval.

---

## Epic 5.1 — EgressGateway (до первой сетевой операции)

**T-5.1.1 (M) Сетевая политика и журнал (D11, FR-7.1/7.3)**
- **Цель:** EgressPolicy (белый список: updates.check, models.download), EgressGateway (согласие → журнал network_event → выполнение), lint-запрет прямого net/fetch вне гейтвея, событие `net:activity`.
- **Почему:** единственная точка сети = проверяемая честность (AC-4.1); строится ДО первого сетевого кода.
- **Объём:** policy + gateway + таблица network_event (миграция v6) + eslint-правило + тесты.
- **Зависимости:** P1.2 (БД), T-0.1.3 (lint).
- **Файлы:** `src/main/modules/platform-services/egress*`, `migrations/v6*`.
- **Проверка:** тесты: операция вне списка → `NET/BLOCKED_BY_POLICY`; без согласия → отказ; журнал пишется в обоих случаях.
- **AC:** ни один сетевой вызов невозможен мимо гейтвея (тест + правило линтера).
- **Риски:** забытый «законный» вызов библиотеки — аудит зависимостей на скрытую сеть в P7 (T-7.1.3).
- **Сложность:** M (1,5–2 ч)

## Epic 5.2 — LLM-воркер

**T-5.2.1 (L) UtilityProcess: протокол и жизненный цикл**
- **Цель:** llm-worker процесс: MessagePort-протокол (load/unload/complete/stream/cancel), requestId, перезапуск после краша, события `ai:status`.
- **Почему:** изоляция сбоев нативного кода и памяти (арх. 07 §1, NFR-5).
- **Объём:** каркас воркера + main-side клиент-протокол + тесты протокола (fake-воркер).
- **Зависимости:** P0.2.
- **Файлы:** `src/main/llm-worker/*`, `src/main/modules/ai-insight/adapters/llm-client*`.
- **Заметки:** протокол без знания о llama.cpp — воркер Swappable (в тестах — fake-engine).
- **Проверка:** тесты: параллельные requestId, отмена, kill воркера → перезапуск.
- **AC:** краш воркера не роняет приложение; UI получает `ai:status:crashed→restarted`.
- **Риски:** MessagePort-детали Electron — проверить на раннем smoke.
- **Сложность:** L (2,5–4 ч)

**T-5.2.2 (L) Интеграция node-llama-cpp в воркере**
- **Цель:** реальная генерация: загрузка GGUF, контекст, стрим токенов, отмена, unload; idle-выгрузка через 5 мин.
- **Почему:** D5; CPU-инференс без GPU (целевое железо).
- **Объём:** движок в воркере + ручной smoke на любой мини-GGUF (1B).
- **Зависимости:** T-5.2.1.
- **Файлы:** `src/main/llm-worker/engine*`.
- **Заметки:** параметры инференса (context size, threads) — конфиг с дефолтами; не тюнить сейчас.
- **Проверка:** ручной smoke: генерация стримится, cancel останавливает, RAM освобождается после unload (диспетчер задач).
- **AC:** первый токен и полный ответ — в пределах честных ожиданий на dev-машине (замер зафиксирован).
- **Риски:** сборка/ABI node-llama-cpp — по возможности prebuilt-бинари.
- **Сложность:** L (2,5–4 ч)

**T-5.2.3 (M) Порт LlmEngine + fake для тестов**
- **Цель:** application-порт (load/complete-stream/cancel/status) + in-process fake (детерминированный «паравозик» токенов) для юнит-тестов use case'ов.
- **Почему:** guardrails и оркестрация тестируются без модели (арх. 10 §1).
- **Зависимости:** T-5.2.1.
- **Файлы:** `src/main/modules/ai-insight/application/ports*`, `adapters/llm-engine.fake*`.
- **AC:** fake используется всеми последующими тестами P5; real-адаптер за тем же портом.
- **Риски:** нет.
- **Сложность:** M (1–1,5 ч)

## Epic 5.3 — Модели: реестр и загрузка

**T-5.3.1 (S) Манифест моделей**
- **Цель:** JSON-реестр: `{id, version, file, sha256, sizeBytes, languages, minRamGb, license}` + zod-схема (арх. 07 §6).
- **Зависимости:** T-5.1.1.
- **Файлы:** `packages/contracts/src/models*`, `apps/desktop/resources/models-manifest.json`.
- **Проверка:** schema-тест манифеста.
- **AC:** метаданные языков/RAM читаемы; файл манифеста версионируется.
- **Риски:** нет.
- **Сложность:** S (0,5–1 ч)

**T-5.3.2 (L) ModelStore: докачиваемая загрузка + верификация**
- **Цель:** загрузка через EgressGateway: проверка места (EC-15), Range-докачка после обрыва, sha256, атомарное переименование в `userData/models/`.
- **Почему:** FR-5.8; 2–3 ГБ без докачки и без проверки = предательство доверия.
- **Объём:** адаптер + прогресс-события `ai:progress` + тесты (обрыв, битый файл, нехватка места).
- **Зависимости:** T-5.1.1, T-5.3.1.
- **Файлы:** `src/main/modules/ai-insight/adapters/model-store*`.
- **Проверка:** интеграционные тесты на локальном http-сервере фикстур.
- **AC:** обрыв → повтор → докачка с середины; несовпадение sha256 → файл отброшен, место не занято.
- **Риски:** прокси/антивирусы рвут соединения — retry-политика с бэкоффом.
- **Сложность:** L (2,5–4 ч)

**T-5.3.3 (M) UI моделей: выбор, загрузка, «позже»**
- **Цель:** экран ИИ: список моделей (размер/языки/мин. RAM), загрузка с прогрессом и докачкой, «настроить позже»; предупреждение о несовпадении языка (FR-5.9) и слабом железе (NFR-5).
- **Зависимости:** T-5.3.2.
- **Файлы:** `src-renderer/features/ai/ui/models*`.
- **Проверка:** ручной прогон загрузки/обрыва/повтора.
- **AC:** AC-5.4 выполнен: без модели приложение полноценно; «позже» не навязывается повторно.
- **Риски:** нет.
- **Сложность:** M (1,5–2 ч)

## Epic 5.4 — Контекст и guardrails

**T-5.4.1 (M) GuardrailPolicy (домен)**
- **Цель:** классы запретов (диагноз, лечение/дозы, «поставь диагноз»), требования к ответу (дисклеймер, период), порог малых данных из kernel — как данные политики (арх. 02 §3.3).
- **Почему:** политика — домен, исполнение — адаптеры; меняется без затрагивания LLM-кода.
- **Объём:** типы политики + дефолтная политика + юнит-тесты классификации вопросов.
- **Зависимости:** T-0.1.6.
- **Файлы:** `src/modules/ai-insight/domain/guardrail*`.
- **AC:** каждая категория «красного набора» (AC-5.1) маппится в элемент политики.
- **Риски:** нет.
- **Сложность:** M (1–2 ч)

**T-5.4.2 (L) AiContextBuilder + context_hash**
- **Цель:** детерминированная проекция периода (агрегаты, серии по дням, разрывы ≥7 дней, пометки аритмии/критических, заметки по includeNotes) + `SHA-256(period, параметры, modelId, PROMPT_TEMPLATE_VERSION)`.
- **Почему:** кэш резюме и воспроизводимость (арх. 07 §3); одинаковый вход = одинаковый контекст.
- **Зависимости:** P3.2 (read models), T-5.3.1.
- **Файлы:** `src/main/modules/ai-insight/application/context-builder*`.
- **Проверка:** тест детерминизма (байт-в-байт), тест разрывов (EC-08), тест excludeNotes.
- **AC:** контекст без заметок не содержит ни одного их байта; hash стабилен при перестановке записей (сортировка).
- **Риски:** размер контекста при 90-дневном периоде — лимитировать серию (сжатие до дневных агрегатов).
- **Сложность:** L (2,5–4 ч)

**T-5.4.3 (M) System prompt (версионируемый шаблон, RU)**
- **Цель:** шаблон системного промпта из политики: роль, запреты, дисклеймер, указание периода, правило разрывов; `PROMPT_TEMPLATE_VERSION`.
- **Зависимости:** T-5.4.1.
- **Файлы:** `src/main/modules/ai-insight/application/prompts/*`.
- **Проверка:** снапшот-тест собранного промпта; правка шаблона требует бампа версии (тест).
- **AC:** промпт содержит все элементы политики; версия попадает в context_hash.
- **Риски:** качество промпта — итерируется в eval (5.7), здесь фиксируется каркас.
- **Сложность:** M (1–2 ч)

**T-5.4.4 (L) ResponseGuard (пост-фильтр)**
- **Цель:** эвристики запрещённых паттернов (названия препаратов+дозировка, «диагноз:», «прекратите приём») → замена отказ-шаблоном + лог-событие; fail-safe.
- **Почему:** промпт — мягкий контроль; релизный гейт AC-5.1 требует гарантий на каждой модели.
- **Объём:** фильтр + фикс-тесты на всех пунктах красного набора (тексты-фикстуры ответов моделей).
- **Зависимости:** T-5.4.1.
- **Файлы:** `src/main/modules/ai-insight/application/response-guard*`.
- **Проверка:** таблица фикстур «опасный ответ → заменён; безопасный → пропущен».
- **AC:** ни одна опасная фикстура не проходит фильтр; ложное срабатывание = отказ, не мусор.
- **Риски:** ложные срабатывания на медицинских терминах в вопросах пользователя — фильтр смотрит только утверждения ответа.
- **Сложность:** L (2–3 ч)

**T-5.4.5 (M) Отказ-шаблоны без LLM**
- **Цель:** детерминированные ответы: малые данные (<7/<3), вопрос о лечении, критические значения → срочный текст FR-7.4 (локальные номера); LLM не вызывается.
- **Почему:** гарантированные тексты там, где нужен не «обычно», а «всегда» (арх. 07 §4).
- **Зависимости:** T-5.4.1, T-5.4.2.
- **Файлы:** `src/main/modules/ai-insight/application/precheck*`.
- **Проверка:** юнит-тесты: период из 3 записей → отказ без обращения к порту LlmEngine (spy).
- **AC:** префильтры срабатывают до LLM; тексты соответствуют AC-5.1/AC-6.2.
- **Риски:** нет.
- **Сложность:** M (1–2 ч)

## Epic 5.5 — Резюме периода

**T-5.5.1 (L) GenerateSummary use case**
- **Цель:** полный поток UC-03: кэш по context_hash, стейлс по data_version, стрим токенов в UI, отмена, сохранение с метаданными (арх. 07 §5); миграция v4 (ai_summary).
- **Зависимости:** T-5.2.3, T-5.4.2–5.4.5.
- **Файлы:** `src/main/modules/ai-insight/application/generate-summary*`, `migrations/v4*`.
- **Проверка:** интеграционные тесты с fake-engine: повторный запрос из кэша, стейлс, отмена (частичный не сохраняется).
- **AC:** AC-5.6 (бейдж стейлса) и ветки UC-03 A1–A4 зелёные.
- **Риски:** race «отмена во время сохранения» — транзакция + статус.
- **Сложность:** L (2,5–4 ч)

**T-5.5.2 (M) UI резюме: контекст-превью, стрим, «Стоп»**
- **Цель:** экран: выбор периода, предпросмотр передаваемых данных (FR-5.5), стрим-текст, «Стоп»/«Повторить», бейдж «данные изменились», несъёмный дисклеймер (FR-5.6).
- **Зависимости:** T-5.5.1.
- **Файлы:** `src-renderer/features/ai/ui/summary*`.
- **Проверка:** e2e с fake-режимом (dev-флаг fake LLM) + ручной прогон с реальной моделью.
- **AC:** AC-5.2/5.3/5.5/5.6 визуально подтверждены; дисклеймер нельзя скрыть скроллом.
- **Риски:** dev-флаг fake-LLM обязателен для стабильных e2e — заложить сразу.
- **Сложность:** M (1,5–2,5 ч)

## Epic 5.7 — Оценка качества (eval)

**T-5.7.1 (L) Runner «красного набора» (tools/eval)**
- **Цель:** скриптованный прогон фиксированных вопросов/контекстов через реальную модель → детерминированные проверки формы ответа (отказ/дисклеймер/срочность) → отчёт.
- **Почему:** гейт релиза AC-5.1 на каждой модели (R-12).
- **Объём:** runner + набор кейсов (из фикстур 5.4.4) + отчёт markdown; локальный запуск на 1B-модели.
- **Зависимости:** T-5.5.1 (реальный путь генерации).
- **Файлы:** `tools/eval/*`.
- **Проверка:** локальный прогон: отчёт со статусами по каждому кейсу.
- **AC:** кейсы проваливаются на модели без guardrails (контрольная проверка механизма) и проходят с ними.
- **Риски:** nondeterminism модели — проверяются структурные признаки, не дословный текст.
- **Сложность:** L (2,5–4 ч)

**T-5.7.2 (S) Ночной CI-прогон eval (опциональный job)**
- **Цель:** workflow nightly: eval на 1B-модели (кэшируемой), артефакт-отчёт; гейт — вручную в релизе (TD-7).
- **Зависимости:** T-5.7.1.
- **Файлы:** `.github/workflows/eval-nightly.yml`.
- **AC:** ночной отчёт появляется; флейки моделей не блокируют PR (отдельный job).
- **Риски:** стоимость/кэш модели в CI — модель ~1 ГБ кэшируется.
- **Сложность:** S (0,5–1 ч)

**Веха P5:** «объясни мне мои данные» работает локально; приложение без модели полноценно; красный набор автоматизирован.
