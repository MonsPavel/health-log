# Фаза P1 — Вертикальный срез журнала (Walking Skeleton)

**Веха фазы:** можно ввести измерение (с валидацией и подтверждениями), оно сохраняется в **зашифрованную** БД, видно в истории; упакованный билд запускается. Это ядро ценности без аналитики.

---

## Epic 1.1 — Домен измерений

**T-1.1.1 (M) VO BloodPressure, Pulse, Arm**
- **Цель:** value objects с инвариантами SRS (FR-1.2, табл. 4.1): диапазоны, `sys > dia`.
- **Почему:** мусор в данных недопустим — на нём стоят статистика и ИИ.
- **Объём:** VO + factory-валидация, ошибки `MEASUREMENT/INVALID_RANGE`, `MEASUREMENT/SYS_LE_DIA`; property-тесты.
- **Зависимости:** T-0.1.6.
- **Файлы:** `src/modules/measurement/domain/*`.
- **Заметки:** границы 50–300/20–200/20–300 — константы домена с комментарием-источником SRS.
- **Проверка:** юнит + property-тесты (fast-check).
- **AC:** любые (sys≤dia) и вне диапазонов отклоняются с корректным кодом; граничные значения проходят.
- **Риски:** споры о границах — вынесены в константы, меняются одной правкой.
- **Сложность:** M (1–2 ч)

**T-1.1.2 (M) Агрегат BpMeasurement**
- **Цель:** сущность с инвариантами: обязательные поля, `takenAt ≤ now(Clock)`, заметка ≤500 симв. (FR-1.1).
- **Почему:** центральный агрегат контекста (арх. 02 §3.1).
- **Объём:** entity, create/update-factories, Clock-инъекция, коды `MEASUREMENT/FUTURE_TIME` и др.
- **Зависимости:** T-1.1.1.
- **Файлы:** `src/modules/measurement/domain/*`.
- **Проверка:** юнит-тесты с фейковыми часами.
- **AC:** create/update с будущим временем и длинной заметкой отклоняются; валидные — собираются.
- **Риски:** нет.
- **Сложность:** M (1–2 ч)

**T-1.1.3 (M) TypoHeuristic (FR-1.6)**
- **Цель:** чистая функция: медиана СДА/ДДА за 14 дней vs новое значение, порог 40 мм рт. ст. → флаг.
- **Почему:** защита истории от опечаток (персона П3, тремор).
- **Объём:** сервис + порог-константа + тесты (golden + property).
- **Зависимости:** T-1.1.1.
- **Файлы:** `src/modules/measurement/domain/typo-heuristic*`.
- **Заметки:** функция над массивом историй — репозиторий не нужен (чистота).
- **Проверка:** кейсы: пустая история, ровно 40, 41, аритмичные истории.
- **AC:** детерминирована, документирована, покрыта ≥90%.
- **Риски:** ложные срабатывания у волатильных пользователей — флаг только предупреждает, не блокирует.
- **Сложность:** M (1–2 ч)

**T-1.1.4 (S) DuplicateDetector (EC-04)**
- **Цель:** флаг вероятного дубля: те же значения в пределах 2 минут.
- **Объём:** чистая функция + тесты.
- **Зависимости:** T-1.1.1.
- **Файлы:** `src/modules/measurement/domain/duplicate*`.
- **Проверка:** юнит-тесты границ окна.
- **AC:** 119 с — флаг, 121 с — нет.
- **Риски:** нет.
- **Сложность:** S (0,5 ч)

**T-1.1.5 (S) CriticalValuePolicy (FR-7.4)**
- **Цель:** доменные правила критических значений: `sys≥180 ∨ dia≥120` → high; `sys≤90 ∨ dia≤60` → low.
- **Почему:** панель срочной помощи и пометки в статистике — из правил, не из ИИ.
- **Объём:** чистая политика + тип флага.
- **Зависимости:** T-1.1.1.
- **Файлы:** `src/modules/measurement/domain/critical*`.
- **Проверка:** юнит-тесты на границах (180/179, 120/119…).
- **AC:** граничные значения классифицируются ровно по SRS.
- **Риски:** нет.
- **Сложность:** S (0,5 ч)

**T-1.1.6 (S) Порт репозитория + in-memory fake**
- **Цель:** `BpMeasurementRepository` (add/update/delete/listByPeriod/getById) + фейк для тестов.
- **Почему:** application-слой тестируется без SQLite (арх. 02 §5).
- **Зависимости:** T-1.1.2.
- **Файлы:** `src/modules/measurement/application/ports*`, `adapters/measurement-repo.fake*`.
- **AC:** фейк проходит тем же контрактом, что и будущий SQLite-адаптер (общие тесты).
- **Риски:** нет.
- **Сложность:** S (0,5–1 ч)

## Epic 1.2 — Хранилище: SQLCipher сразу (долг-минимизация)

**T-1.2.1 (L) SQLCipher-стек better-sqlite3**
- **Цель:** пересобранный под Electron better-sqlite3 с SQLCipher; открытие БД ключом; проверка, что файл нечитаем.
- **Почему:** перевод незашифрованной БД на шифрование позже = миграция данных и риск (решение README фазы, TD-стойка); NFR-2 «включено по умолчанию».
- **Объём:** скрипт сборки/пресет, electron-rebuild, smoke-тест шифрования.
- **Зависимости:** T-0.2.1.
- **Файлы:** `apps/desktop/scripts/*`, `src/main/modules/measurement/adapters/db*`.
- **Заметки:** спайк-характер: если пресет SQLCipher нежизнеспособен — fallback «шифрование файла целиком» (арх. 04 §1) с записью ADR.
- **Проверка:** интеграционный тест: создать, переоткрыть с ключом; текстовый дамп файла — мусор.
- **AC:** AC-4.2 частично выполнен (файл нечитаем); пересборка автоматизирована скриптом.
- **Риски:** самый рискованный таск фазы (R-6); заложить буфер, не переносить.
- **Сложность:** L (2,5–4 ч)

**T-1.2.2 (M) KeyVault: ключ БД через safeStorage**
- **Цель:** генерация 32-байтного ключа, обёртка через Electron safeStorage (DPAPI), файл ключа в userData, unwrap при старте.
- **Почему:** NFR-2: ключ не лежит открытым текстом рядом с БД (арх. 08 §2).
- **Объём:** адаптер + тесты roundtrip; обработка «файл ключа удалён».
- **Зависимости:** T-1.2.1.
- **Файлы:** `src/main/modules/security/adapters/key-vault*`.
- **Проверка:** интеграционный тест: создать → переоткрыть; вручную удалить ключ → понятная ошибка `VAULT/KEY_MISSING` с предложением восстановить из копии.
- **AC:** в файле ключа нет открытого ключа (dump-проверка).
- **Риски:** safeStorage недоступен на Linux без keyring — задокументировать ограничение платформы.
- **Сложность:** M (1–2 ч)

**T-1.2.3 (M) Migration runner + автокопия перед миграцией**
- **Цель:** forward-only миграции по `schema_version`; хук «снапшот перед миграцией» (сейчас — заглушка-интерфейс, реализация в T-4.3.1).
- **Почему:** R-4; стратегия отката арх. 04 §5.
- **Объём:** runner (список версий, транзакционные DDL), хук, тесты двух миграций.
- **Зависимости:** T-1.2.1.
- **Файлы:** `src/main/shared/db/migrations*`.
- **Проверка:** интеграционный тест: v0→v1→v2 на temp-БД; сбой посреди миграции → откат транзакции.
- **AC:** сбой миграции не оставляет полусозданной схемы; хук вызывается до DDL.
- **Риски:** нет.
- **Сложность:** M (1,5–2 ч)

**T-1.2.4 (M) Миграция v1: profile + bp_measurement**
- **Цель:** схема из арх. 04 §3: profile (seeded), bp_measurement, индексы, meta (schema_version, data_version=1).
- **Зависимости:** T-1.2.3.
- **Файлы:** `src/main/shared/db/migrations/v1*`.
- **Проверка:** тест применяет к свежей БД, сверяет схему.
- **AC:** seeded-профиль существует; CHECK-ограничения работают (вставка sys<dia падает).
- **Риски:** нет.
- **Сложность:** M (1–1,5 ч)

**T-1.2.5 (M) SQLite-адаптер репозитория измерений**
- **Цель:** реализация порта T-1.1.6: CRUD + listByPeriod; мутации поднимают `data_version` в той же транзакции.
- **Почему:** атомарность «запись+версия» — основа стейлса ИИ (04 §4).
- **Объём:** адаптер + общие тесты контракта + тест транзакции (сбой посреди → ничего не изменилось, версия не поднялась).
- **Зависимости:** T-1.2.4, T-1.1.6.
- **Файлы:** `src/main/modules/measurement/adapters/*`.
- **Проверка:** интеграционные тесты на temp-БД.
- **AC:** контрактные тесты фейка и адаптера зелёные на одном наборе; data_version инвариантен к сбоям.
- **Риски:** SQL-типы/булевы — аккуратно с INTEGER/boolean.
- **Сложность:** M (1,5–2,5 ч)

**T-1.2.6 (S) Сборка контейнера (composition root)**
- **Цель:** container.ts: Clock → vault → db → миграции → репозитории; регистрация готовых хендлеров.
- **Почему:** единая точка сборки графа (арх. 03 §5).
- **Зависимости:** T-1.2.2, T-1.2.5.
- **Файлы:** `src/main/container.ts`.
- **Проверка:** запуск приложения — БД создаётся в userData, журнал «db.ready».
- **AC:** повторный запуск переоткрывает существующую БД без ошибок.
- **Риски:** нет.
- **Сложность:** S (0,5–1 ч)

## Epic 1.3 — Ввод и список (первый UI-вертикаль)

**T-1.3.1 (M) Contracts: каналы измерений**
- **Цель:** DTO + zod-схемы + коды ошибок для add/update/delete/list (арх. 05 §3).
- **Зависимости:** T-0.2.2.
- **Файлы:** `packages/contracts/src/measurement*`.
- **Проверка:** schema-тесты (валидные/невалидные payload).
- **AC:** невалидный payload отклоняется zod-ом до use case.
- **Риски:** нет.
- **Сложность:** M (1–1,5 ч)

**T-1.3.2 (M) Use case AddMeasurement**
- **Цель:** оркестрация: валидация домена → эвристики (typo/duplicate) → репозиторий; ответ с флагами и `criticalValue`.
- **Почему:** поведение UC-01 с альтернативами A1–A3.
- **Объём:** use case + unit-тесты с фейком репозитория и Clock.
- **Зависимости:** T-1.1.2–1.1.6, T-1.3.1.
- **Файлы:** `src/modules/measurement/application/add-measurement*`.
- **Проверка:** юнит-тесты всех веток (сохранить/исправить при флагах).
- **AC:** ветки флагов возвращают корректные маркеры; запись+data_version атомарны.
- **Риски:** нет.
- **Сложность:** M (1,5–2 ч)

**T-1.3.3 (S) Use case ListMeasurements + хендлеры**
- **Цель:** чтение списка (период, пагинация по дням — простая), регистрация add/list в IPC.
- **Зависимости:** T-1.3.2.
- **Файлы:** `src/modules/measurement/application/list*`, `src/main/ipc/*`.
- **Проверка:** интеграционный тест хендлеров через контейнер.
- **AC:** добавленная запись появляется в списке (e2e-мини).
- **Риски:** нет.
- **Сложность:** S (0,5–1 ч)

**T-1.3.4 (L) Форма ввода (сердце UX, US-1)**
- **Цель:** экран ввода: автофокус, цифровая клавиатура-кнопки, автоподстановка руки/флагов, дата-время «сейчас» с правкой (включая заднее число, EC-19), Enter=сохранить, мгновенная клиентская валидация.
- **Почему:** цель ≤15 с (NFR-6) — главный UX-риск продукта.
- **Объём:** компонент формы + zustand-черновик + интеграция с IPC.
- **Зависимости:** T-1.3.1, T-0.2.7.
- **Файлы:** `src-renderer/features/measurement/ui/*`, `model/*`.
- **Заметки:** клавиатура физическая И экранные кнопки; поле времени — простой датапикер (TD-11).
- **Проверка:** ручной хронометраж ввода; юнит-тесты зеркала валидации.
- **AC:** ввод 3 значений ≤15 с; клиентская валидация = зеркальное отражение zod-схемы.
- **Риски:** переусложнение формы — резать всё необязательное для ввода.
- **Сложность:** L (2,5–4 ч)

**T-1.3.5 (M) Диалоги подтверждений (EC-03, FR-1.6)**
- **Цель:** потоки «Проверьте значения» (мягкая валидация), «вероятная опечатка», «возможный дубль» — по флагам из ответа add.
- **Почему:** баланс «не блокировать правду / не пускать мусор» (SRS 07 EC-01/03).
- **Объём:** модальные потоки: Сохранить/Исправить; после сохранения при criticalValue — панель FR-7.4.
- **Зависимости:** T-1.3.2, T-1.3.4.
- **Файлы:** `src-renderer/features/measurement/ui/dialogs*`.
- **Проверка:** ручной прогон веток + e2e-сценарий.
- **AC:** 185/115 → панель срочности; 258 при медиане 128 → подсказка; оба сохраняются при подтверждении.
- **Риски:** баннерная усталость — панели не блокируют ввод.
- **Сложность:** M (1,5–2 ч)

**T-1.3.6 (M) История: список по дням + пустые состояния**
- **Цель:** журнал: группировка по дням, обратная хронология, бейджи флагов (typo/irregular/critical), обучающее пустое состояние (FR-3.6).
- **Зависимости:** T-1.3.3.
- **Файлы:** `src-renderer/features/measurement/ui/history*`.
- **Проверка:** ручной прогон + скриншот-тест пустого состояния.
- **AC:** записи сгруппированы по датам; флаги видны; пустой экран подсказывает следующий шаг (AC-3.6 частично).
- **Риски:** нет.
- **Сложность:** M (1,5–2 ч)

## Epic 1.4 — Упаковка (рано, чтобы не копить «dev-only» долг)

**T-1.4.1 (M) electron-builder: сборка Windows**
- **Цель:** установщик/распакованная сборка; asar; нативный модуль внутри; ресурсы.
- **Почему:** билд-проблемы (нативные модули, пути) вскрываются сейчас, а не в P7.
- **Объём:** конфиг builder, скрипт `dist`, локальный запуск собранного.
- **Зависимости:** T-1.2.1.
- **Файлы:** `apps/desktop/electron-builder*`, `package.json`.
- **Проверка:** установка собранного, ввод измерения в packaged-режиме.
- **AC:** packaged-приложение полноценно работает с БД в userData.
- **Риски:** antivirus-ложняки на неподписанном — фиксируется, подпись в P7.
- **Сложность:** M (1,5–2,5 ч)

**T-1.4.2 (M) Playwright Electron smoke**
- **Цель:** e2e: запуск → ввод измерения → виден в списке (каркас UC-01).
- **Почему:** критический путь под автотестом с первой недели фич.
- **Объём:** playwright-config для _electron, первый сценарий, скрипт запуска (локально; в CI — P7, TD-6).
- **Зависимости:** T-1.3.6, T-1.4.1.
- **Файлы:** `apps/desktop/tests/e2e/*`.
- **AC:** сценарий зелёный локально; isolated temp-userData на каждый прогон.
- **Риски:** нестабильность e2e — держать сценарии атомарными.
- **Сложность:** M (1,5–2 ч)

**T-1.4.3 (S) Скрипт аудита размера**
- **Цель:** замер установщика/установленной папки, сравнение с лимитом 200 МБ (NFR-5, D1a).
- **Объём:** скрипт отчёта (гейт подключается в P7).
- **Зависимости:** T-1.4.1.
- **Файлы:** `tools/scripts/size-audit*`.
- **AC:** отчёт показывает текущий размер и лимит.
- **Риски:** если уже >200 МБ — ранний сигнал для решения D1a (Tauri-миграция) не в конце проекта.
- **Сложность:** S (0,5 ч)

**Веха P1:** «Ввёл → сохранилось (шифровано) → вижу» — в dev и в packaged-сборке; smoke-e2e зелёный.
