# Фаза P4 — Данные и отчёты

**Веха фазы:** пользователь владеет данными: CSV/JSON-экспорт, PDF врачу, зашифрованная копия/восстановление, полное удаление. Фаза идёт **до** ИИ: ядро ценности не должно зависеть от самого рискованного компонента (R-3).

---

## Epic 4.1 — Экспорт CSV/JSON

**T-4.1.1 (M) CSV-экспорт (FR-6.1)**
- **Цель:** все поля всех записей; UTF-8 с BOM, разделитель `;` (параметр); потоки через FileSaver-порт.
- **Почему:** US-27, владение данными; Excel-совместимость для П5.
- **Объём:** use case + чистый конвертер + fixtures-тест (открытие в Excel-режиме: BOM, кавычки, переносы в заметках).
- **Зависимости:** P1.2 (репозиторий).
- **Файлы:** `src/modules/reporting/{application,adapters}/*`.
- **Заметки:** генерация в памяти до ~50k строк допустима (NFR-4: <60 с); escape-правила RFC 4180.
- **Проверка:** fixture-тесты на кавычках/переносах/юникоде; ручная проверка в Excel.
- **AC:** файл корректно открывается в Excel с русской локалью; данные полны и без искажений (AC-2.3).
- **Риски:** нет.
- **Сложность:** M (1–2 ч)

**T-4.1.2 (M) JSON-слепок (мастер-формат, FR-6.2)**
- **Цель:** версионированный полный экспорт (профили, записи, настройки, шкалы-версии) + `schemaVersion`.
- **Почему:** страховка миграций и основа будущих интеграций.
- **Объём:** сериализатор + zod-схема формата; roundtrip-тест (экспорт → валидация схемой).
- **Зависимости:** T-4.1.1.
- **Файлы:** `src/modules/reporting/application/json*`, `packages/contracts/src/export*`.
- **Проверка:** roundtrip + fixture со всеми граничными полями (null-пульс, флаги).
- **AC:** экспорт проходит валидацию собственной схемой; версия формата в файле.
- **Риски:** нет.
- **Сложность:** M (1–1,5 ч)

**T-4.1.3 (M) Save dialog + UI экспорта + ошибки**
- **Цель:** диалог сохранения (выбор места пользователем всегда, арх. 02 §3.4), кнопки в настройках/отчётах; ошибки диска — понятные (`EXPORT/WRITE_FAILED`).
- **Зависимости:** T-4.1.1, T-4.1.2.
- **Файлы:** `src/main/platform/files*`, `src-renderer/features/reports/*`.
- **Проверка:** ручной прогон; e2e-смоук экспорта CSV.
- **AC:** экспорт недоступен в момент копирования БД (блокировка одновременных файловых операций) — простая очередь задач.
- **Риски:** нет.
- **Сложность:** M (1–1,5 ч)

## Epic 4.2 — PDF-отчёт врачу

**T-4.2.1 (M) Worker pool (2 потока) для CPU-задач**
- **Цель:** общий пул: PDF, CSV 50k, тяжёлые series; API «job → прогресс → результат»; main не блокируется (NFR-4).
- **Почему:** рендер PDF секунды — нельзя в main (арх. 03 §6).
- **Объём:** пул + очередь + таймауты + тесты (параллельные задачи, отказ воркера).
- **Зависимости:** P1.
- **Файлы:** `src/main/shared/workerpool*`.
- **Проверка:** интеграционные тесты пула (конкурентные задачи, ошибка воркера не валит main).
- **AC:** во время генерации PDF UI отвечает (замер IPC-латентности).
- **Риски:** передача больших данных воркеру — structured clone, следить за размером.
- **Сложность:** M (1,5–2,5 ч)

**T-4.2.2 (L) Шаблон PDF-отчёта (FR-6.3)**
- **Цель:** @react-pdf/renderer шаблон: титул (период, дата, версия приложения), таблица измерений, средние утро/вечер/период, график, регулярность; опциональный ИИ-раздел с маркировкой «не является медицинским заключением», по умолчанию выключен.
- **Почему:** US-26, П5 — получатель; данные без «умных» выводов.
- **Объём:** компоненты шаблона + генерация из read models P3 (никаких новых вычислений).
- **Зависимости:** T-4.2.1, P3.2.
- **Файлы:** `src/modules/reporting/adapters/pdf/*`.
- **Заметки:** график — рендер сериализованного SVG в PNG на стороне воркера либо векторные примитивы; решение — в ADR-комментарии задачи.
- **Проверка:** golden-снапшот PDF на fixture-данных; ручная печать.
- **AC:** AC-2.6 выполнен; раздел ИИ отсутствует по умолчанию; при включении промаркирован.
- **Риски:** @react-pdf/renderer ограничения (шрифты кириллицы — подключить TTF; объём бандла) — проверить в первой половине задачи.
- **Сложность:** L (2,5–4 ч)

**T-4.2.3 (M) BuildPdfReport use case + предпросмотр UI**
- **Цель:** выбор периода, чекбокс «включить ИИ-раздел» (заблокирован, если резюме нет), предпросмотр в UI, сохранение.
- **Зависимости:** T-4.2.2, T-4.1.3.
- **Файлы:** `src/modules/reporting/application/pdf*`, `src-renderer/features/reports/*`.
- **Проверка:** юнит-тесты use case (пустой период → отказ, EC A2); e2e-сценарий UC-05.
- **AC:** UC-05 основной и альтернативные потоки работают; файл открывается в системном просмотрщике.
- **Риски:** нет.
- **Сложность:** M (1,5–2 ч)

**T-4.2.4 (S) Bench PDF (NFR-4)**
- **Цель:** замер: отчёт на 5k записей <30 с на референсном железе A; скрипт в tools.
- **Зависимости:** T-4.2.3.
- **Файлы:** `tools/scripts/perf-pdf*`.
- **AC:** замер зафиксирован; при превышении — профилировка шаблона.
- **Риски:** нет.
- **Сложность:** S (0,5 ч)

## Epic 4.3 — Копии, восстановление, полное удаление

**T-4.3.1 (L) CreateBackup: VACUUM INTO + шифрованный контейнер (FR-6.4)**
- **Цель:** безопасный снапшот → AES-GCM контейнер (ключ из KeyVault) + манифест `{schemaVersion, appVersion, sha256, createdAt}`.
- **Почему:** сценарий «умер ноутбук» (UC-08) — главный страх многолетнего дневника (R-4).
- **Объём:** use case + адаптер криптоконтейнера + прогресс + тесты roundtrip.
- **Зависимости:** T-1.2.2, T-1.2.3 (хук автокопии подключается сюда — T-1.2.3).
- **Файлы:** `src/modules/data-care/*`.
- **Заметки:** VACUUM INTO даёт консистентный снапшот без остановки записи.
- **Проверка:** интеграционный тест: создать копию базы с данными → sha256 манифеста сходится.
- **AC:** копия создаётся во время работы приложения; манифест валиден; AC-2.4-подготовка.
- **Риски:** размер копии на 50k записях — приемлем (сотни КБ–МБ).
- **Сложность:** L (2,5–4 ч)

**T-4.3.2 (M) RestoreBackup: проверки + замена**
- **Цель:** валидация манифеста/sha256/версии схемы → предупреждение «текущие данные будут заменены» (включая «копия старее», EC-25) → восстановление → переоткрытие.
- **Зависимости:** T-4.3.1.
- **Файлы:** `src/modules/data-care/application/restore*`.
- **Проверка:** интеграционные тесты: битая копия (AC-2.5), копия старее, копия будущей схемы.
- **AC:** ни один отказ не трогает текущие данные; успешное восстановление = полный перезапуск состояния (включая FTS).
- **Риски:** восстановление поверх изменённой схемы — правило «копия старее по schema → отказ с понятным текстом, обновите приложение».
- **Сложность:** M (1,5–2,5 ч)

**T-4.3.3 (M) WipeAllData (FR-6.5, UC-10)**
- **Цель:** двухшаговое подтверждение + предложение экспорта; удаление db/-wal/-shm, ключа, логов, событий; состояние «как после установки».
- **Зависимости:** T-1.2.2.
- **Файлы:** `src/modules/data-care/application/wipe*`.
- **Проверка:** интеграционный тест: после wipe запуск создаёт новую БД; старые файлы отсутствуют.
- **AC:** AC-4.4 выполнен; отказ на подтверждении ничего не удаляет.
- **Риски:** открытые хендлы файлов на Windows — закрывать БД перед удалением.
- **Сложность:** M (1–2 ч)

**T-4.3.4 (M) UI: экран копий и удаления**
- **Цель:** экран «Данные»: создать копию, восстановить (файл-пикер + предупреждения), удалить всё (двухшагово); подсказка о регулярных копиях.
- **Зависимости:** T-4.3.2, T-4.3.3.
- **Файлы:** `src-renderer/features/reports/*` (или отдельная data-care фича).
- **Проверка:** e2e: копия → wipe → восстановление (сквозной UC-08/UC-10).
- **AC:** все тексты предупреждений соответствуют SRS (необратимость, замена данных).
- **Риски:** нет.
- **Сложность:** M (1,5–2 ч)

**T-4.3.5 (S) Еженедельная подсказка о копии (JobScheduler)**
- **Цель:** минимальный JobScheduler (09 §1) + job «копии нет >14 дней → мягкая подсказка» (R-4).
- **Почему:** первая фоновая задача — каркас планировщика появляется здесь, а не в пост-MVP напоминаниях.
- **Зависимости:** T-4.3.4.
- **Файлы:** `src/main/shared/scheduler*`, `src/main/modules/platform-services/*`.
- **Проверка:** тест с фейковыми часами (интервал срабатывания, тихий показ).
- **AC:** подсказка показывается не чаще раза в неделю; отключаема.
- **Риски:** нет.
- **Сложность:** S (0,5–1 ч)

**Веха P4:** данные пользователя полностью под его контролем: экспорт/копия/восстановление/удаление; PDF врача принят по шаблону SRS; e2e UC-08/UC-10 зелёные.
