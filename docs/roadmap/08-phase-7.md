# Фаза P7 — Релиз MVP

**Веха фазы:** подписанный установщик, канал обновлений, полный прогон DoD SRS; release candidate. Публичное распространение — отдельное бизнес-решение (регуляторная проверка SRS 01 §8 / R-1).

---

## Epic 7.1 — Релиз-инженерия

**T-7.1.1 (L) Подпись Windows + update feed**
- **Цель:** Authenticode-подпись установщика (сертификат приобретается вне этой задачи — бюджетная строка), electron-builder подпись, публикация latest.yml на Releases.
- **Почему:** неподписанный установщик = паника антивирусов и браузеров (R-6); обновления проверяют подпись (NFR-11).
- **Объём:** конфиг подписи, секреты CI, пробная подписанная сборка.
- **Зависимости:** T-1.4.1, T-6.2.1.
- **Файлы:** `electron-builder*`, `.github/workflows/*`.
- **Заметки:** OV-сертификат достаточно для MVP; EV (мгновенный SmartScreen-рейтинг) — дороже, решение зафиксировать в ADR-заметке релиза.
- **Проверка:** подписанная сборка: свойства файла показывают подпись; SmartScreen не ругается резко (мягкий тест).
- **AC:** релизные артефакты подписаны; updater принимает только подписанные обновления.
- **Риски:** procurement сертификата — длительный внешний процесс; начать заранее (задача-«закупка» отмечена в порядке разработки).
- **Сложность:** L (2,5–4 ч)

**T-7.1.2 (M) Тег-пайплайн релиза**
- **Цель:** на `v*`: полный E2E на Windows-runner → подпись → сборка → полный AI-eval (компактная модель) + крэш-тест (T-6.4.3) + perf-бенчи → draft release → публикация вручную.
- **Почему:** человек публикует релиз — последняя ручная точка контроля (арх. 10 §3).
- **Зависимости:** T-7.1.1, T-5.7.1, T-6.4.3.
- **Файлы:** `.github/workflows/release.yml`.
- **Проверка:** пробный релиз `v0.9.0-rc` на себя.
- **AC:** от тега до draft release — без ручных шагов; публикация — одной кнопкой.
- **Риски:** Windows-runner E2E нестабилен — ретраи только на смоук, не на ассерты.
- **Сложность:** M (2–3 ч)

**T-7.1.3 (M) Сетевой аудит релизной сборки (AC-4.1)**
- **Цель:** чеклист-скрипт/процедура: запуск релизной сборки с мониторингом соединений; фиксация: трафик нулевой без согласий; с согласиями — только заявленные endpoints; сверка с журналом приватности.
- **Почему:** центральное доказательство BG-2 перед каждым публичным релизом.
- **Объём:** процедура (документ) + скрипт-помощник (например, монитор через системные средства) + отчёт-шаблон.
- **Зависимости:** T-7.1.2.
- **Файлы:** `tools/scripts/net-audit*`, `docs/architecture/audits/*`.
- **AC:** отчёт аудита приложен к релизу; расхождение журнал↔факт = блокер.
- **Риски:** скрытая сеть в зависимостях — аудит ловит только наблюдаемое; дополнительно `pnpm audit` + ревью новых зависимостей.
- **Сложность:** M (1,5–2,5 ч)

**T-7.1.4 (S) Beta-канал**
- **Цель:** второй feed (beta), переключение канала в настройках, порядок публикации latest ← beta.
- **Зависимости:** T-7.1.2.
- **Файлы:** updates-конфиг, settings UI.
- **AC:** beta-сборка получает beta-обновления; стабильная не видит beta.
- **Риски:** нет.
- **Сложность:** S (0,5–1 ч)

## Epic 7.2 — Доступность и полировка текстов

**T-7.2.1 (M) axe-аудит всех маршрутов + клавиатурные маршруты**
- **Цель:** axe-core в E2E на каждом экране (светлая/тёмная, обычный/крупный); прохождение всех флоу только с клавиатуры; исправления.
- **Зависимости:** все UI-фазы.
- **Файлы:** e2e-конфиг, компоненты по результатам.
- **AC:** AC-7.3 зелёный; axe-нарушений уровня critical/serious нет.
- **Риски:** поток исправлений непредсказуем — заложить буфер фазы.
- **Сложность:** M (2–3 ч)

**T-7.2.2 (M) NVDA-чеклист + контраст (NFR-6)**
- **Цель:** ручной прогон основных сценариев со скринридером; аудит контраста токенов темы (WCAG AA); исправления.
- **Зависимости:** T-7.2.1.
- **Файлы:** компоненты, tokens, документ чеклиста.
- **Проверка:** чеклист-документ с результатами прогона.
- **AC:** ключевые сценарии (ввод, история, ИИ, экспорт) озвучиваются осмысленно.
- **Риски:** скринридер-тесты не автоматизируемы достоверно — ручной процесс фиксируется документом.
- **Сложность:** M (1,5–2,5 ч)

**T-7.2.3 (S) Ревизия текстов RU (тон, дисклеймеры, запрет лексики)**
- **Цель:** сквозное ревью каталога i18n: отсутствие запрещённой лексики SRS (док 01 §8), единый спокойный тон, обязательные дисклеймеры на месте.
- **Зависимости:** T-2.2.1, P5.
- **Файлы:** `src-renderer/i18n/ru/*`.
- **AC:** чеклист формулировок SRS пройден; все дисклеймеры на месте.
- **Риски:** нет.
- **Сложность:** S (0,5–1 ч)

## Epic 7.3 — Производительность и DoD

**T-7.3.1 (M) Полный perf-прогон (NFR-4/5)**
- **Цель:** замеры на референсном железе: старт ≤3 с, график <1 с, PDF <30 с, экспорт 50k <60 с, ИИ-латентности; отчёт vs целевые; точечные оптимизации.
- **Зависимости:** T-1.4.3, T-3.4.2, T-4.2.4.
- **Файлы:** `tools/scripts/perf-*`, отчёт в docs.
- **AC:** все цели NFR-4 подтверждены (или задокументированные отклонения с решением).
- **Риски:** оптимизации могут съесть буфер — резать по профайлеру, не по ощущениям.
- **Сложность:** M (2–3 ч)

**T-7.3.2 (S) Финальный прогон DoD (SRS 10 §4)**
- **Цель:** чеклист всех AC SRS (док 08) построчно: статусы, артефакты проверок.
- **Зависимости:** всё выше.
- **Файлы:** `docs/release/mvp-dod.md`.
- **AC:** ни одной строки чеклиста без статуса; блокеры → в баг-трекер, не в «потом».
- **Риски:** нет.
- **Сложность:** S (0,5–1 ч)

## Итоговая оценка

≈ 90 задач: P0 ≈ 15 · P1 ≈ 19 · P2 ≈ 12 · P3 ≈ 12 · P4 ≈ 12 · P5 ≈ 17 · P6 ≈ 10 · P7 ≈ 11.
Суммарно ~180–200 часов чистой работы; при 8–10 ч/неделю — ориентировочно 4–5 месяцев до RC. Критический путь: T-1.2.1 (SQLCipher) → T-1.2.5 → P1.3; и в P5: T-5.2.1 → T-5.2.2 → P5.4/5.5. Внешние процессы (сертификат подписи T-7.1.1, выбор и проверка моделей для манифеста) начинать параллельно с P4–P5.
