# Фаза P3 — Аналитика и визуализация

**Веха фазы:** дашборд отвечает на главный вопрос пользователя «что происходит»: средние, категория по шкале, утро/вечер, тренд-график с опорными линиями и таблицей-альтернативой.

---

## Epic 3.1 — Справочные шкалы

**T-3.1.1 (M) Пакет scales-data (ESC/ESH)**
- **Цель:** версионируемые данные таблицы 4.1 SRS: категории, пороги, правило «по высшей из двух», примечание о домашних порогах ≥135/85, source_label.
- **Почему:** шкалы — данные с версией, не код (FR-4.5, R-10).
- **Объём:** JSON-данные + zod-схема + экспорт констант; коммент-источник (ESC/ESH 2018, сверить по первоисточнику — OQ-6).
- **Зависимости:** T-0.1.1.
- **Файлы:** `packages/scales-data/src/*`.
- **Проверка:** schema-тесты данных; сверка таблицы с SRS 04 табл. 4.1.
- **AC:** данные проходят валидацию; версия/источник читаемы программно.
- **Риски:** неточность порогов — только правка данных, миграция не нужна.
- **Сложность:** M (1–1,5 ч)

**T-3.1.2 (M) Хранилище шкал + ScaleService**
- **Цель:** миграция v3 (reference_scale), загрузка активной шкалы из пакета при первом старте, кэш в памяти, канал `scales/active`.
- **Зависимости:** T-3.1.1, T-1.2.3.
- **Файлы:** `migrations/v3*`, `src/main/modules/analytics/adapters/scale-repo*`, `application/scale-service*`.
- **Проверка:** интеграционные тесты: активация, идемпотентность повторного старта.
- **AC:** активная шкала ровно одна на код; версия видна через канал (NFR-10).
- **Риски:** нет.
- **Сложность:** M (1–2 ч)

## Epic 3.2 — Статистика периода

**T-3.2.1 (L) Read model PeriodStatistics**
- **Цель:** все метрики FR-4.1: count, avg/min/max/SD (СДА/ДДА/ЧСС), утро/вечер и разница (по настенному времени Instant), распределение категорий, пометка критических (FR-4.3), регулярность/streak (FR-4.4), флаг «мало данных» (<7/<3 — константа kernel, FR-5.4).
- **Почему:** это контракт и для UI, и для PDF (P4), и для ИИ-контекста (P5) — строится один раз.
- **Объём:** SQL-агрегаты + чистые функции домена; golden-fixture тесты (сгенерированные периоды с ручными эталонами).
- **Зависимости:** T-1.2.5, T-3.1.2.
- **Файлы:** `src/modules/analytics/{application,domain}/*`.
- **Заметки:** SD — Population vs Sample: зафиксировать выбор (Sample) в комментарии и fixtures; пустые/частичные периоды не должны падать.
- **Проверка:** golden-тесты ≥5 реперных периодов; property: перестановка записей не меняет агрегаты.
- **AC:** AC-3.1 зелёный; NaN/деление на ноль невозможны (пустой период → корректный «мало данных»).
- **Риски:** тонкости утро/вечер при ночных измерениях (EC-05) — правило: 06:00–11:59 утро, 18:00–23:59 вечер, иначе «другое» (константа, отображается отдельно).
- **Сложность:** L (2,5–4 ч)

**T-3.2.2 (M) Classifier + примечание о домашних порогах**
- **Цель:** категория среднего по активной шкале + обязательные примечания (FR-4.2): домашний порог, дисклеймер, неприменимость особым группам (EC-11).
- **Зависимости:** T-3.1.2, T-3.2.1.
- **Файлы:** `src/modules/analytics/domain/classifier*`.
- **Проверка:** реперные тесты: 138/86 → «высокое нормальное» + примечание 135/85; 136/84 → тоже с примечанием.
- **AC:** AC-3.3 зелёный; примечания неотделимы от результата (структура данных, не UI-забота).
- **Риски:** нет.
- **Сложность:** M (1–1,5 ч)

**T-3.2.3 (M) Канал stats/period + UI-представление «мало данных»**
- **Цель:** хендлер статистики; на UI — корректное представление периодов с <7 измерений (EC-09): значения с пометкой, без категорий-приговоров.
- **Зависимости:** T-3.2.1, T-3.2.2.
- **Файлы:** `src/main/ipc/*`, `src-renderer/features/dashboard/*`.
- **Проверка:** интеграционный тест хендлера; ручной прогон на малых данных.
- **AC:** малый период не показывает категорию как «вердикт»; пометка «мало данных» обязательна.
- **Риски:** нет.
- **Сложность:** M (1–2 ч)

## Epic 3.3 — График динамики

**T-3.3.1 (M) ADR: выбор чарт-библиотеки (spike)**
- **Цель:** сравнить 2–3 кандидата (visx / Recharts / ECharts) против требований арх. 06 §8 (опорные линии, две серии + ЧСС, дальтонизм-безопасность, агрегация, SSR/печать не нужна, вес).
- **Почему:** решение с длинным хвостом UI; зафиксировать до написания экрана.
- **Объём:** мини-прототип тренда на каждом кандидате, ADR-документ в docs/architecture.
- **Зависимости:** T-3.2.3.
- **Файлы:** `docs/architecture/adr/0001-chart-lib.md`, временные прототипы.
- **AC:** ADR принят (решение + альтернативы + компромиссы); прототипы удаляются.
- **Риски:** паралич выбора — лимит времени, решение по требованиям, не по вкусу.
- **Сложность:** M (2–3 ч)

**T-3.3.2 (M) Read model trend/series**
- **Цель:** серии точек (время, sys, dia, pulse, флаги) за период; агрегация >500 точек → день = среднее + диапазон (FR-3.5); различение утро/вечер.
- **Зависимости:** T-3.2.1.
- **Файлы:** `src/modules/analytics/application/trend*`.
- **Проверка:** тесты порога агрегации (499/501 точек); тест 10k точек по времени (<1 с, NFR-4).
- **AC:** payload графика детерминирован; агрегация включается ровно по порогу.
- **Риски:** нет.
- **Сложность:** M (1,5–2 ч)

**T-3.3.3 (L) Экран «Динамика»**
- **Цель:** линейный график СДА/ДДА с опорными линиями (подпись источника шкалы, FR-3.2), точки утро/вечер различимы формой+цветом (не только цветом), периоды 7/30/90/всё, тултип → переход к записи.
- **Зависимости:** T-3.3.1, T-3.3.2.
- **Файлы:** `src-renderer/features/dashboard/ui/chart*`.
- **Проверка:** ручной прогон + e2e-смоук; скриншот-тесты.
- **AC:** все элементы FR-3.1–3.3 на экране; тултип показывает точные значения и дату.
- **Риски:** производительность SVG на 500+ точках — агрегация уже решает; кэшировать вычисленные path.
- **Сложность:** L (2,5–4 ч)

**T-3.3.4 (M) ЧСС-представление**
- **Цель:** пульс отдельным графиком/вкладкой (вторая шкала не смешивает единицы).
- **Зависимости:** T-3.3.3.
- **Файлы:** dashboard chart components.
- **AC:** ЧСС читаем независимо; флаг irregular подсвечен (EC-10).
- **Риски:** нет.
- **Сложность:** M (1–1,5 ч)

**T-3.3.5 (M) Таблица-альтернатива + a11y-резюме (FR-3.2, NFR-6)**
- **Цель:** переключатель «график ↔ таблица» (и для П5, и для скринридеров); текстовое резюме тренда под графиком («среднее за 30 дней 138/86, категория …»).
- **Зависимости:** T-3.3.3.
- **Файлы:** dashboard ui, i18n каталог.
- **Проверка:** axe-прогон экрана; ручная проверка NVDA (первичная).
- **AC:** таблица содержит те же данные, что график; резюме генерируется из тех же read models (нет расхождений).
- **Риски:** нет.
- **Сложность:** M (1–2 ч)

**T-3.3.6 (S) Пустые состояния графиков**
- **Цель:** нет данных/мало данных → подсказка + следующий шаг (FR-3.6, AC-3.6).
- **Зависимости:** T-3.3.3.
- **Файлы:** dashboard ui.
- **AC:** пустой и малый период показывают подсказку, не «мёртвый холст».
- **Риски:** нет.
- **Сложность:** S (0,5 ч)

## Epic 3.4 — Дашборд

**T-3.4.1 (M) Домашний экран-сводка**
- **Цель:** последнее измерение, среднее 7 дней, категория, streak дней, быстрый CTA «Добавить измерение»; пустое состояние = приглашение.
- **Почему:** US-16; «домашний экран» снижает цену входа в привычку.
- **Зависимости:** T-3.2.3, T-3.3.6.
- **Файлы:** `src-renderer/features/dashboard/ui/summary*`.
- **Проверка:** ручной прогон на пустых/малых/полных данных.
- **AC:** сводка собирается из тех же read models (нет параллельных вычислений); streak без «штрафов» (FR-4.4).
- **Риски:** нет.
- **Сложность:** M (1,5–2 ч)

**T-3.4.2 (S) Bench графика на 10k точек**
- **Цель:** автоматический замер:series+рендер на 10k записей <1 с (NFR-4); скрипт в tools.
- **Зависимости:** T-3.3.3.
- **Файлы:** `tools/scripts/perf-chart*`.
- **AC:** замер воспроизводим; при превышении — известный узкий узел (агрегация/кэш path).
- **Риски:** нет.
- **Сложность:** S (0,5–1 ч)

**Веха P3:** пользователь видит и понимает свою динамику; все вычисления — через протестированные read models; золотые статистические fixtures в CI.
