# 01. Видение продукта и цели

**Статус:** черновик v0.1 · 2026-09-24 · ветка `docs/planning`

---

## 1. Одно предложение

Десктопное приложение, в котором человек ведёт дневник артериального давления, видит свою динамику в понятных графиках и получает объяснения «человеческим языком» от ИИ, который работает **полностью локально** — данные никогда не покидают устройство.

## 2. Проблема

- Повышенное АД — одно из самых массовых состояний в мире: по оценкам ВОЗ, повышенное давление имеют порядка 1,1–1,3 млрд взрослых (оценку сверить с актуальным источником перед внешними публикациями).
- Врачам для принятия решений нужна **динамика АД вне клиники** («домашний мониторинг»), но бумажные дневники ведутся нерегулярно, теряются и плохо читаются.
- Существующие приложения: облачные (медицинские данные уходят на чужие серверы), перегружены подписками и рекламой, показывают цифры, но **не объясняют** их.
- Пациент остаётся наедине с числами: «147/95» ничего не говорит — это кормит тревожность у одних и апатию с пропусками измерений у других.

## 3. Решение

Локальное десктоп-приложение: быстрый ввод измерений → наглядная история, графики и статистика → объяснения ИИ в чате и в отчётах → готовый PDF-отчёт для визита к врачу. Всё работает офлайн; единственные сетевые операции — обновление самого приложения и (по явному согласию) загрузка ИИ-модели.

## 4. Видение (горизонт 3–5 лет)

Health Log — **приватный личный журнал здоровья**: давление — первый модуль, дальше — пульс в покое, вес, сон, глюкоза, с кросс-корреляциями между показателями и локальным ИИ-объяснением. Пользователь владеет данными так же, как своими документами: файлы у него, экспорт в открытых форматах, полная работа без облака.

> Название репозитория `health-log` выбрано не случайно: давление — первый модуль расширяемого журнала, а не отдельный «калькулятор давления». Это намерение зафиксировано как продуктовое; архитектурные следствия — вне рамок этого SRS.

## 5. Ценностное предложение по персонам

- **Елене, 54** («врач сказал вести дневник»): не думать о бумажке — цифры сами превращаются в аккуратную распечатку; ИИ простыми словами объясняет, что происходит, без паники.
- **Дмитрию, 34** (quantified self): полный доступ к сырым данным, CSV/JSON-экспорт, локальная LLM, ноль облака.
- **Виктору Петровичу, 68** («цифровой минималист»): крупный шрифт, минимум шагов, одна кнопка «Объяснить».
- **Врачу** (косвенный потребитель): отчёт, которому можно доверять, собранный за секунды, с данными, а не «умными» выводами.

## 6. Бизнес-цели и метрики успеха

| ID | Цель | Метрика успеха |
|---|---|---|
| BG-1 | Польза: пользователь реально ведёт дневник и понимает его | ≥5 дней с измерениями из 7 у активного пользователя (локальный индикатор; продуктово — опросы/интервью) |
| BG-2 | Доверие через приватность: ноль обязательного сетевого трафика | Аудит релизной сборки: сетевая активность только из заявленного списка (FR-7.3) |
| BG-3 | Врач получает нужные данные с первого визита | Качественная метрика: отчёты принимаются врачами без просьб «принесите по-другому» (интервью) |
| BG-4 | Устойчивость проекта для автора: поддерживаемый продукт | Регулярные релизы без критических регрессий; время на выпуск релиза |
| BG-5 | Фундамент для расширения до health-log | Продуктовое намерение зафиксировано в этом SRS; проверка — успешная добавляемость второго типа показателей после MVP |

**⚠️ Напряжение «приватность vs метрики».** Классические продуктовые метрики (retention, воронки) требуют телеметрии, которая прямо противоречит BG-2. Принятое решение по умолчанию: **без телеметрии вообще**; успех измеряем опциональными опросами, статистикой скачиваний релизов и локальными индикаторами. Это допущение A-11, оспорить его можно в OQ-10.

## 7. Не-цели (Non-goals)

- **Не диагностика.** Не ставим диагнозы, не подбираем и не корректируем лечение, не «оцениваем состояние пациента».
- **Не медицинское изделие.** Позиционирование — инструмент записи и описательной статистики для самоконтроля (см. §8). Не заменяем врача и инструкцию к тонометру.
- **Не облачный сервис.** Нет аккаунтов, серверов и синхронизации в MVP.
- **Не соцсеть.** Никаких «сообществ» и публичных профилей.
- **Не измеряем давление сами.** Работаем с данными бытовых тонометров; подключение тонометров — будущие функции.

## 8. Позиционирование и регуляторные рамки

Продукт — «инструмент записи и описательной статистики для самоконтроля» (wellness / self-tracking), **а не медицинское изделие**. Из этого следуют обязательные требования к формулировкам:

- Запрещённая лексика в UI и ответах ИИ: «диагноз», «у вас гипертония», «лечение», «показание», «назначение». Допустимо: «данные», «средние», «категория по справочной шкале», «показатели за период».
- Каждый экран с анализом и каждый ответ ИИ содержит несъёмный дисклеймер «не является медицинской консультацией» (FR-5.6).
- Справочные шкалы показываются с указанием источника и версии, с пометками, что пороги для домашних измерений и особых групп (беременность, дети, аритмия) отличаются (FR-4.2, FR-4.5).

⚠️ **Критический риск:** при публичном распространении (особенно в ЕС) ПО, «предназначенное для мониторинга состояния», может быть квалифицировано как медицинское изделие — см. R-1, R-2 в доке 09. Перед публичным релизом обязательна юридическая проверка формулировок. Для личного использования риск минимален.

## 9. Продуктовые принципы

1. **Privacy by design.** Локально по умолчанию; шифрование; честный экран «Приватность» со списком всех сетевых операций.
2. **Объясняй, а не диагностируй.** ИИ описывает данные и тренды, а не «состояние человека».
3. **Данные принадлежат пользователю.** Открытый экспорт (CSV/JSON), настоящее удаление, никаких ловушек.
4. **Offline-first.** Полный функционал без сети; сеть — только по явному согласию.
5. **Доступность.** Пожилой пользователь — полноправная персона, а не «edge case»: крупный текст, контраст, клавиатура.
6. **Честный ИИ.** Отказывается обобщать без данных, признаёт разрывы и ограничения, не выдумывает.
