# TASK-102: отчёт демонстрации чувствительности крэш-теста (§20-3 / §24)

Дата: 02.10.2026 · ветка `task/TASK-102` · Windows 10.0.26200, node v24.13.0 · seed 20261002.

## Цель

Обязательный критерий приёмки §20-3 (и «ключевой» проверка §24): доказать, что
крэш-тест NFR-3 способен ПОЙМАТЬ реальную потерю данных — при отключённой
транзакции батча (авто-коммит каждой вставки) килл внутри батча оставляет
частичный батч (`ack < found < ack + batchSize`), и вердикт итерации обязан
дать FAIL с кодом `PARTIAL_BATCH`.

## Процедура (документирована в шапке apps/desktop/src/main/ipc/handlers/test-hooks.ts)

1. Базовая линия: транзакции на месте → прогон → ожидание PASS.
2. Временная dev-правка: тело цикла вставки вынесено из-под `db.transaction`
   (каждые INSERT + bump data_version — авто-коммит) → rebuild main
   (`tsc -b tsconfig.main.json`) → тот же прогон → ожидание FAIL(PARTIAL_BATCH).
3. Откат правки (`git checkout -- apps/desktop/src/main/ipc/handlers/test-hooks.ts`)
   → rebuild → прогон → ожидание PASS (восстановление подтверждено).

Команда всех трёх прогонов (одна и та же):

```
pnpm test:crash --smoke --kill-mode in-flight --batch 5000
```

Полные логи прогонов: `step1-baseline-pass.log`, `step2-autocommit-fail.log`,
`step3-restored-pass.log` (рядом с этим отчётом).

## Результаты

| Шаг | Состояние транзакции | Вердикт | Факт итерации | exit |
|---|---|---|---|---|
| 1 (baseline) | одна db.transaction на батч | **PASS** | ack=40000 found=40000 dv=40001 schema=7 | 0 |
| 2 (авто-коммит) | обёртка отключена | **FAIL(PARTIAL_BATCH)** | ack=15000 found=15465 dv=15466 schema=7 | 1 |
| 3 (откат) | одна db.transaction на батч | **PASS** | ack=35000 found=35000 dv=35001 schema=7 | 0 |

Ключевой вывод шага 2: при авто-коммите килл застал батч исполнения — из 5000
строк недобатча 465 успели закоммититься по одной (`found = ack + 465`), что
НАРУШАЕТ атомарность и поймано инвариантом `PARTIAL_BATCH` (частичный батч
невозможен при транзакции — §8). Базовые линии показывают парный факт: при
транзакции килл внутри того же батча оставляет `found == ack` — недо-батч
откатился ЦЕЛИКОМ, подтверждённые записи целы.

## Примечания

- Прогон 20:30 (попытка до процедуры) дал средовой сбой запуска
  (`electron.launch: Target page, context or browser has been closed`):
  причиной были 4 зомби-процесса Electron от прерванного прогона RED-фазы
  ревью-фикса; после `taskkill` базовая линия воспроизвелась чисто. К результатам
  демонстрации отношения не имеет, зафиксировано ради воспроизводимости.
- Сопутствующий фикс ревью (коммит a2d074e): `--kill-mode` валидируется по
  словарю `CRASH_KILL_MODES` — опечатка даёт отказ (usage/exit 2), а не
  молчаливую деградацию к idle; без него демо §20-3 могло пройти впустую.
- Отчёты прогонов (`tools/crash-results/*.json`) — в .gitignore (§6), логи
  трёх шагов выше committed как свидетельство.
