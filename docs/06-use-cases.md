# 06. Варианты использования (Use Cases)

**Статус:** черновик v0.1 · 2026-09-24 · ветка `docs/planning`

---

## UC-01. Добавить измерение

- **Персона:** П1 (типично), любые.
- **Предусловия:** приложение установлено, хотя бы один запуск выполнен.
- **Триггер:** пользователь измерил давление тонометром.
- **Основной поток:**
  1. Пользователь открывает приложение (или оно уже открыто) и нажимает «Добавить измерение».
  2. Вводит СДА, ДДА (обязательные), ЧСС (опционально), при необходимости меняет руку.
  3. Время подставлено автоматически; пользователь может его изменить.
  4. Нажимает «Сохранить» (или Enter). Значения проходят валидацию FR-1.2/1.3.
  5. Система подтверждает сохранение, поля очищены для возможного следующего ввода.
- **Альтернативные потоки:**
  - A1 (FR-1.3): значения вне типичного диапазона → диалог «Проверьте значения» → «Сохранить» или «Исправить».
  - A2 (FR-1.6): отклонение от личной медианы >40 мм рт. ст. → подсказка о вероятной опечатке → сохранение по выбору.
  - A3 (FR-7.4): значения ≥180/120 → после сохранения показана информационная панель о критических значениях.
- **Постусловия:** запись сохранена с локальным временем; серия/статистика обновлены.
- **Связи:** US-1, US-4, US-5; FR-1.1–1.7; критерии AC-1.

## UC-02. Посмотреть динамику за период

- **Персона:** П1, П2.
- **Триггер:** «Как мои дела на этой неделе?»
- **Основной поток:** открывает экран «Динамика» → выбирает период (7д) → видит график СДА/ДДА с опорными линиями, точки различают утро/вечер → на панели видит средние утро/вечер и общее среднее.
- **Альтернативы:** A1 (FR-3.6): данных мало → обучающее пустое состояние; A2 (FR-3.5): точек слишком много → агрегированный вид.
- **Постусловия:** без изменений данных.
- **Связи:** US-10, US-11; FR-3.1–3.6; AC-3.

## UC-03. Получить ИИ-резюме периода

- **Персона:** П1 (типично), П3.
- **Предусловия:** ≥7 измерений за ≥3 дней (иначе FR-5.4 — честный отказ); модель установлена или установка запускается сейчас.
- **Основной поток:**
  1. Нажимает «Объяснить мой период» → выбирает период (по умолчанию 30 дней).
  2. Видит, какие данные будут переданы (FR-5.5), подтверждает.
  3. Индикатор генерации; текст появляется по мере генерации (FR-5.7).
  4. Читает резюме: средние и динамика, утро/вечер, заметные события, разрывы, «что обсудить с врачом». Дисклеймер на месте (FR-5.6).
- **Альтернативы:**
  - A1 (FR-5.4): данных <7/<3 дней → отказ от обобщений с объяснением.
  - A2 (FR-5.8): модель не установлена → предложение скачать с показом объёма либо «позже».
  - A3 (FR-5.7): генерация остановлена кнопкой «Стоп» → частичный текст не сохраняется как резюме.
  - A4 (FR-5.7): данные изменились после генерации → бейдж «обновите резюме».
- **Постусловия:** резюме кэшировано с периодом и датой.
- **Связи:** US-18, US-21; FR-5.1–5.9; AC-5.

## UC-04. Задать вопрос ИИ по своим данным

- **Персона:** П2 (типично), П1.
- **Триггер:** вопрос («почему вечером выше, чем утром?», «были ли дни с очень высоким давлением?»).
- **Основной поток:** открывает чат → вводит вопрос → видит контекст (период) → получает ответ с опорой на конкретные записи; при необходимости меняет период анализа.
- **Альтернативы:**
  - A1 (FR-5.3): вопрос про лекарства/дозы → вежливый отказ, направление к врачу.
  - A2 (FR-7.4): в данных/вопросе фигурируют критические значения → информация о срочной помощи.
  - A3 (FR-5.4): данных недостаточно для ответа → честный отказ.
- **Постусловия:** история чата локальна; может быть очищена пользователем.
- **Связи:** US-19, US-23; FR-5.1–5.9; AC-5.

## UC-05. Подготовить отчёт к врачу

- **Персона:** П1.
- **Предусловия:** ≥1 неделя наблюдения.
- **Основной поток:** выбирает «Отчёт для врача» → период (по умолчанию 30 дней) → предпросмотр (таблица, средние, график, регулярность, версия приложения) → сохраняет PDF → печатает (FR-6.7).
- **Альтернативы:**
  - A1 (FR-6.3): включает или не включает раздел ИИ-резюме (по умолчанию выключен, с маркировкой).
  - A2: данных нет → пустой отчёт не формируется, подсказка.
- **Постусловия:** PDF-файл у пользователя; данные не изменены.
- **Связи:** US-26; FR-6.3, FR-6.7; AC-4.

## UC-06. Реакция на критическое значение

- **Персона:** П1; особая ответственность продукта.
- **Триггер:** ввод или наличие в данных значений ≥180/120 (или ≤90/60).
- **Основной поток:**
  1. Значение сохраняется (пользователь не блокируется — данные важны).
  2. Показывается бережная панель FR-7.4: что такое ≥180/120, при каких симптомах — немедленная помощь, номера служб по локали.
  3. Значение помечается в статистике и отчётах (FR-4.3).
- **Альтернативы:** A1: значение распознано как вероятная опечатка (FR-1.6) → подсказка до сохранения.
- **Постусловия:** запись сохранена; пометка установлена.
- **Связи:** US-20; FR-7.4; AC-6.

## UC-07. Первый запуск и настройка ИИ

- **Персона:** П1 (самостоятельно), П3 (с сыном).
- **Основной поток:** установка → онбординг FR-9.1 (приватность → первое измерение → ИИ «позже») → пользователь начинает вести дневник. Настройку ИИ может выполнить сразу или позже с экрана ИИ.
- **Альтернативы:**
  - A1 (FR-5.8): слабое железо → сообщение о несовместимости с ИИ, приложение работает без него.
  - A2: обрыв при загрузке модели → докачка (FR-5.8).
  - A3: отказ от ИИ → приложение полноценно, предложения ИИ ненавязчивы.
- **Постусловия:** дневник готов; модель опционально установлена.
- **Связи:** US-39; FR-9.1–9.3; AC-7.

## UC-08. Резервная копия и восстановление

- **Персона:** П1 (сценарий: умер ноутбук).
- **Основной поток:** на старом ПК: «Создать копию» → файл-копия (зашифрован) → пользователь переносит файл сам. На новом ПК: установка → «Восстановить из копии» → выбор файла → проверка целостности → предупреждение «текущие данные будут заменены» → восстановление.
- **Альтернативы:** A1: файл повреждён/не той версии → явная ошибка, текущие данные не тронуты; A2: копия старее текущих данных → предупреждение о замене более новых данных.
- **Постусловия:** данные восстановлены полностью.
- **Связи:** US-29; FR-6.4; AC-4.

## UC-09. Возврат после разрыва в наблюдениях

- **Персона:** П1, П3 (отпуск, болезнь, «забросила»).
- **Триггер:** возвращается к дневнику через 2+ недели.
- **Основной поток:** открывает приложение → видит историю с явным разрывом → запрашивает ИИ-резюме → резюме честно называет разрыв и его длительность, анализирует данные вокруг него (FR-5.4) → пользователь продолжает вести дневник без чувства вины (FR-4.4 — регулярность без штрафов).
- **Альтернативы:** A1: разрыв пришёлся на период терапии → данные до/после не смешиваются в одно «среднее» без оговорки (требование к тексту резюме, AC-5).
- **Постусловия:** без изменений данных.
- **Связи:** US-18, US-21; FR-5.4, FR-4.4; EC-08.

## UC-10. Полное удаление данных

- **Персона:** любой.
- **Триггер:** «удалить всё» (передача ПК, решение уйти).
- **Основной поток:** настройки → «Удалить все данные» → предупреждение о необратимости → предложение сначала экспортировать → подтверждение отдельным действием → удаление → приложение в состоянии «как после установки».
- **Альтернативы:** A1: отказ на подтверждении → ничего не удалено.
- **Постусловия:** данные фактически удалены (NFR-1).
- **Связи:** US-31; FR-6.5; AC-4.
