# @hl/scales-data

Версионируемые справочные шкалы health-log — **данные, а не код** (FR-4.5):
обновление шкалы = правка файла данных, не логики. Пакет ни от чего не зависит
(арх. 03 §4, depcruise `packages-layering`): публикует только данные и типы
(`src/schema.ts`), без zod — рантайм-валидация данных живёт в тестах пакета
(`test/schema.test.ts`) и в потребителе (TASK-051 валидирует `data_json` из БД).

## Состав (v1.0.0)

`src/bp-office-esc2018.json` — офисная шкала **ESC/ESH 2018** (таблица 4.1 SRS
`docs/04-functional-requirements.md`): 6 категорий от `optimal` до
`hypertension3`, примечание о домашних порогах (`homeBPNote`: среднее домашнее
≥135/85 ↔ офисные ≥140/90) и дисклеймер об особых группах (`specialGroupsNote`).

## Форма данных

```jsonc
{
  "code": "bp_office_esc2018",
  "version": "1.0.0", // семвер данных; смена порогов = новая версия
  "sourceLabel": "ESC/ESH 2018", // показывается пользователю
  "language": "ru", // §17: данные v1.0.0 не локализуемы
  "categories": [{ "code", "label", "sysRange": {min, max}, "diaRange": {min, max} }],
  "homeBPNote": "…",
  "specialGroupsNote": "…"
}
```

Границы включительны; `null` — открытая сторона (у `optimal` нет нижней, у
`hypertension3` — верхней). Соседние категории стыкуются: `max(k) + 1 =
min(k+1)` — дыр и пересечений нет (property-тест в `test/schema.test.ts`).

## Семантика «и/или» = «худшая из двух» (SRS табл. 4.1)

В рекомендациях категории заданы парами «СДА **и/или** ДДА» (например,
«130–139 и/или 85–89» — высокое нормальное). Хранить такие строки нельзя:
значение 138/92 попадает и в «130–139», и в «90–99». Поэтому данные держат
**пороги границ каждой категории по каждому измерению отдельно** (СДА и ДДА
рассматриваются независимо), а правило отнесения одно:

> категория измерения — по его диапазону; итоговая категория — **худшая из двух**
> (максимальная из категорий СДА и ДДА).

Это та же формулировка, что и «и/или» SRS: «и» для оптимальной (обе величины в
диапазоне), «и/или» дальше — сокращение правила «худшая из двух». Классификатор
— TASK-053; данные пакета классификацию не выполняют.

## Верификация (OQ-6)

Пороги сверены построчно с таблицей 4.1 SRS (автотест), но перед публичным
релизом подлежат сверке с первоисточником (ESC/ESH 2018) — см. `$comment` в
файле данных. AHA 2017 — пост-MVP настройка стандарта (OQ-6), тот же формат.
